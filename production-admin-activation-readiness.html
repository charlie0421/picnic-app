3. TestFlight 구매와 운영 지갑

Apple TestFlight의 앱 내 구매는 Sandbox를 사용한다. Apple 공식 테스트 환경 설명.

Apple 결제 환경이 Sandbox라는 사실과 앱의 운영 지갑이 격리돼 있다는 것은 다르다. 현재 배포된 서버 경로에서는 검증에 성공한 Sandbox 구매도 같은 운영 DB의 해당 사용자 지갑에 캔디를 적립한다.

  • 운영 wallet-provider-event ACTIVE/version 29: 앱이 PRODUCTION으로 요청해도 Apple JWS가 Sandbox이면 인테이크에서 SANDBOX로 정규화하는 코드가 배포돼 있음을 확인.
  • 운영 wallet-operation-worker ACTIVE/version 30: 같은 프로젝트 클라이언트로 검증된 환경을 grant_verified_purchase에 전달. 두 Edge 함수의 updated_at은 2026-09-03.
  • 운영 구매 RPC 정의에서 상품 기본 캔디·기본 보너스를 credit_star_bonus_with_debt(p_user_id,...)로 지급하는 경로 확인. 환경은 구매 식별·검증·중복 방지에 쓰이고 별도 지갑을 선택하지 않는다.
  • 기본 상품 적립과 V2 추가 프로모션은 별개다. V2 OFF가 Sandbox 기본 적립까지 막아 주지 않는다. 미회수 debt가 있으면 가산분 일부가 상계될 수 있다.
  • 같은 거래의 재전달은 중복 방지 대상이지만 새 Sandbox 거래는 새 적립이다. 앱 재설치나 Apple Sandbox 구매 내역 초기화로 운영 원장이 복구된다고 가정하면 안 된다.
  • 기존 사용자 잔액을 보존해야 한다면 전용 관리자 테스트 계정을 지정한다. 이 점검에서는 계정을 생성하거나 역할을 변경하지 않았다. 기존 계정으로 시험한다면 가산분이 남는 테스트임을 전제로 해야 한다.
  • ADMIN_ONLY의 적격 여부는 구매 스냅샷 시점에 고정된다. 기능과 역할이 설정된 뒤 새 거래로 테스트해야 하며 과거 구매에 관리자 권한을 붙여 소급 적용하는 방식은 불가하다.

4. 다음 작업과 승인 경계

승인을 요청하는 구현 범위는 새 후속 마이그레이션의 워커별 안전 검사·상태 기록과 회귀 테스트다. clean_scans≥2는 reconciliation에만 적용하고, 두 필수 워커의 행 존재·최근 성공·건너뜀 검사는 유지하거나 명시적으로 검증한다. expiry에서 실제 잠금 건너뜀이 발생하면 health에 반영되도록 보완한다. 기존 잔액 계산, 관리자 이관 완료값, 운영 플래그 및 이미 적용된 마이그레이션·고정 번들은 변경하지 않는다.

회귀 검증에는 정상 상태, 오래된 성공 기록, 잠금 건너뜀, 필수 워커 행 누락, 관리자 경로 미이관만 남은 경우의 차단, 긴급 OFF 유지가 포함된다. 관리자 이관은 읽기 전용 검증과 운영 절차 정리까지이며, 실제 UI/API 통합·역할 변경·증거 등록·이관 완료 처리는 별도 범위다. 아직 테스트를 실행하지 않았다.

  1. 기존 관리자 지갑 경로의 실제 이관 상태 및 만료 워커 지표 계약을 보완하는 변경 범위를 확정하고 승인받는다. 단순 완료 표시·카운터 보정·안전 검사 우회는 하지 않는다.
  2. 승인된 수정은 격리 환경의 재현 테스트와 금융·권한 변경에 맞는 독립 교차 리뷰를 거친다. 다른 서버 세션의 변경과 충돌 여부도 다시 확인한다.
  3. 테스트 계정, 배율(스키마 허용 1.1~3.0배), KST 시작·종료·요일, 표시 위치, 변경 주체·사유·티켓을 확정한다. 일정은 불변 버전 기록이므로 임의 생성 후 삭제하는 방식을 쓰지 않는다.
  4. 지갑 안전 게이트를 다시 통과한 뒤 정확한 활성화·비상 OFF 계획을 확인하고 별도 승인으로 ADMIN_ONLY를 켠다. 표시만 먼저 켜는 부분 활성화도 이번에 실행하지 않았다.
  5. 관리자·슈퍼관리자·일반 사용자 및 계정 전환 테스트를 수행하고, 실제 구매는 운영 지갑 가산 영향을 확인한 후 진행한다. 전체 공개 ALL은 범위 밖이다.

이번 작업은 Supabase 읽기 전용 점검과 Superpowers systematic-debugging의 원인 우선 절차를 사용했다. 보조 에이전트는 로컬 결제 경로를 독립 조사했고, 본 세션이 운영 Edge·DB 정의를 추가 확인했다. 실제 구매·배포를 승인하는 교차 리뷰로 간주하지 않는다.

이전 설치 결과는 프로덕션 OFF 설치 결과에 보존했다. 이번 준비에서 앱 코드·태그·빌드, 서버 코드·마이그레이션·Edge·운영 플래그·캠페인·원장은 변경하지 않았다.
