방향 전환

사용자가 스테이징 대신 프로덕션에서 바로 구현하는 방향으로 전환을 요청했다. 현재 결제이벤트 워크스페이스의 Candy Boost V2를 기준으로 검토했으며, 스테이징 복제·익명화·초기화 도구 완성을 이번 기능의 선행 조건에서 제외한다. 아래 접힌 스테이징 작업 기록은 과거 이력이며, Task 1 수정 라운드 3이나 Task 2~11을 자동 재개하는 지시로 사용하지 않는다.

프로덕션 적용 준비의 권장 순서는 운영 현황 읽기 전용 확인 → 로컬 검증 및 교차 리뷰 → V2 비활성 상태 배포 → 운영 확인 후 활성화다. 구체적인 마이그레이션·배포·활성화 대상은 아직 확정되지 않았으며, 이번 방향 전환을 해당 작업의 실행 승인으로 해석하지 않는다.

현재 상태

Task 1은 아직 승인되지 않았다.

Sol 최종 재검토에서 High 1건이 남았다. public.wallet_runtime_flags의 16개 초기화 행은 현재 flag_key와 value_json만 제공한다. 그러나 실제 스키마에서 version과 reason은 기본값이 없는 NOT NULL 컬럼이고, reason은 비어 있으면 안 된다. 따라서 비워진 테이블을 현 계약만으로 다시 seed할 수 없다.

다음 작업: Task 1 수정 라운드 3

  1. config/staging-refresh.yaml의 runtime flag reset 계약에 완전한 insert 메타데이터를 추가한다.

  3. scripts/staging-refresh/lib/policy.mjs에서 위 값의 존재와 정확 일치를 강제한다.
  4. 누락된 version/reason, 변경된 값, 빈 reason을 거부하는 RED 테스트를 먼저 작성한다.
