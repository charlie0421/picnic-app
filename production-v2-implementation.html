스테이징 생략의 의미와 운영 적용 경계

공유 스테이징 서버를 구성하지 않는 방향으로 구현했다. 대신 네트워크가 없는 일회용 PG15 리허설과 앱 회귀 테스트를 수행했다. 이것은 실제 운영 부하·외부 결제·worker 상태까지 검증했다는 뜻이 아니며, 프로덕션 안전성을 무조건 보장하지 않는다.

  1. 운영 적용은 별도 명시 승인 후에만 진행한다. 실제 접속층에서 PICNIC-PROD / xtijtefcycoeqludlngc를 확인하고 복구 가능한 백업 및 writer freeze를 확보해야 한다.
  2. 적용 직전 최신 운영 catalog·flags·migration 이력을 다시 읽고 고정 preflight와 대조한다. drift가 있으면 중단한다.
  3. 승인된 정확한 6개 원본의 한정 번들만 한 트랜잭션으로 적용한다. V2는 OFF이고 기존 flags는 그대로 유지한다. 광범위한 db push나 과거 migration 재실행을 하지 않는다.
  4. 성공 후 이력·소유권·권한 회수·OFF 상태를 검증한다. 실패 주입/rollback 결과는 COMMIT 이전의 원자적 복구 증거일 뿐, COMMIT 이후 운영 역마이그레이션 절차는 아니다.
  5. 플래그 활성화 및 앱 배포는 별도 단계다. 실제 worker health·결제 공급자·기능 readiness를 재확인하고 해당 승인 절차를 따른다.
