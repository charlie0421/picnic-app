패치 구현과 배포 준비 검증을 구분한다. 이번 차례에는 운영 조회와 격리 재검증만 수행했다. 새 소스 구현, commit/push/merge, 운영 migration 적용, 플래그·역할·이관값 변경은 하지 않았다. 기능은 여전히 OFF다.

현재 판단

  • 이미 검토된 4개 파일 패치만 최신 main에 적용하는 충돌 검사는 통과했다. 실제 통합·전체 테스트·배포 완료를 뜻하지 않는다.
  • 핵심 SQL 회귀 4개는 다시 통과했다. 기존 릴리즈 테스트 1개 실패는 재현됐으며, 누락된 플래그 이름 외에 최초 설치 상태와 운영형 테스트 fixture의 차이도 확인했다.
  • 관리자 한정 Candy Boost 공개와 관리자 재무 명령 활성화는 별개다. 재무 명령을 켜기 위한 UI 증거·관리자 인원 조건을 Candy Boost의 직접 필수조건으로 혼동하지 않는다.
  • 다만 공통 쓰기 게이트에는 미이관 경로 2개와 promotion-ops 적립 경로 coverage 75%가 남아 있다. worker 패치만 배포해도 자동으로 해소되지 않는다.

  • authenticated: avatar_url, updated_at, birth_date, gender, open_ages, open_gender, birth_time, language.

따라서 “모든 컬럼 쓰기 권한이 없다”는 표현은 부정확하다. 이 카탈로그 검사는 실제 쓰기 거절 실행 시험이나 배포된 UI 전환 증거를 대신하지 않으며, 전체 보안 감사 완료 선언도 아니다.

독립 지적 중 채택하지 않은 주장

현재 운영이 1a-only여서 wallet-core 10/12라는 주장은 가정이다. 이번 실제 조회는 12/12였고 직접 테이블 쓰기도 차단돼 있었다. 기존 고정 V2 manifest에 새 migration이 없다는 사실은 과거 배포물의 결함이 아니므로 이를 고쳐 재사용하자는 제안은 채택하지 않는다. 공유 54322 reset이나 staging 복귀 제안도 이번 사용자 범위에 포함하지 않는다.

“쓰기 플래그를 켜면 모든 사용자 백로그가 일제히 지급된다”는 지적 역시 그대로 채택하지 않았다. worker는 최종적으로 resolve_purchase_promotion을 호출하고, 최신 20260908031648 wrapper는 동결된 구매 대상 및 현재 OFF를 검사한다. 기존 grant/award 재처리 분기는 별도로 존재하므로 활성화 전 대기 건 확인은 필요하다. 12:48:29 KST 운영 읽기 전용 집계에서 PROMOTION_AWARD 인박스는 모든 상태 합계 0건이었다. 운영 resolver hash는 baca2e76d7e9b2e6dc9882e80e1f0b5b이며 audience/OFF 검사와 기존 grant 분기 존재도 확인했다. 이는 이후 생길 대기 건까지 0이라는 보장이 아니므로 실제 활성화 직전에 다시 조회한다.

정리 및 검증 한계

다른 client backend 0개를 확인한 뒤, 이번 재검증에서 재시작했던 전용 컨테이너 828ff561755bc259f6863bb5ba569d6eb40a344afc1892fad7f661b8a2172769를 12:44:36 KST에 다시 중지했다. 합성 fixture DB와 증거 파일은 삭제하지 않았다. 다른 컨테이너와 공유 DB는 변경하지 않았다.

기존 worker 소스 4개 SHA256은 앞선 리뷰 결과와 동일하고 git diff --check 통과. admin 저장소의 사용자 소유 package.json/.nvmrc/보고서는 수정하지 않았다. 실제 배포된 관리자 웹 SHA·UI E2E는 이번에 검증하지 않았다. 이 문서는 구조·로컬 링크를 검사하며 브라우저 시각 검수는 하지 않는다.

감사 worker 완료 보고를 수락한 뒤 worker-release 및 메시지 ACK를 처리했다. Orca는 기존 외부 터미널을 retained/external_terminal로 보존했고 프로세스를 종료하지 않았다. 긴 보고 메시지의 권한 오류 때문에 생긴 전달 문제는 소스/DB 접근 권한을 확대하지 않고 종료했다. worker의 가정과 권고를 운영 사실이나 승인으로 취급하지 않았다.
