Task 1: worker-specific release safety (TDD)

소유 파일: 새 supabase/migrations/*_wallet_worker_specific_release_health.sql, 새 supabase/tests/wallet_worker_specific_release_health.test.sql, 필요 시 이 테스트를 기존 실행기에 등록하는 최소 수정. 다른 파일 변경은 조정자에게 먼저 알린다.

Consumes: wallet_private.assert_promotion_release_implications(jsonb) returns void, public.expire_cotton_candy_batch(integer) returns public.wallet_batch_result. Produces: 동일 API와 기존 ACL, 보완된 검사/health 기록.

  1. 기존 테스트 fixture와 원본 함수·관련 명세를 읽고, 새 테스트를 작성한다. 모든 정상 전제조건을 격리 fixture로 만족시킨 뒤 expiry clean_scans=0, reconciliation clean_scans=2로 write 요청을 전달하면 성공해야 한다. 현재 baseline에서는 WALLET_RELEASE_GATE_BLOCKED로 실패해야 한다. 구현 전 실제 RED 출력을 보존한다.
  2. 음성 사례: 각 필수 worker stale/null last_success, 각 worker scan_had_skips, reconciliation clean_scans=0/1, 각 필수 worker 누락(다른 key로 대체해 count=2인 경우 포함), 관리자 admin_adjustment/projection_repair 미이관만 남은 경우, 적립 coverage 미완료, 기존 CRITICAL/audit 조건 유지. 전부 WALLET_RELEASE_GATE_BLOCKED여야 한다. write false/OFF는 기존 계약대로 계속 허용한다.
  3. 후속 migration에서 원본 gate의 비-worker 조건은 그대로 둔다. worker 검사는 두 정확한 key의 존재를 검증하고 모든 기존 최근 성공·skip 조건을 유지하면서 clean_scans 요구만 wallet-reconciliation에 한정한다. 기존 count=2 조건도 유지한다.
  4. expiry wrapper는 실제 inner 결과를 그대로 반환한다. last_result에 실제 processed/skipped_locked/next_cursor를 기록하고 scan_had_skips는 해당 배치의 skipped_locked>0로 설정한다. clean_scans를 인위적으로 늘리지 않는다. 성공 시각의 기존 갱신 의미는 유지하고 skip 여부가 release를 차단하게 한다. 행이 없으면 게이트가 fail-closed이며 wrapper는 행을 자동 생성하지 않는다.
  5. 실제 expiry 배치(빈 배치/처리/잠금 건너뜀/다음 정상 배치 회복)를 테스트한다. 잠금은 별도 세션으로 재현하는 것이 우선이며 불가피한 test double이면 실제 경계·한계와 이유를 보고한다. exception 시 health 갱신이 롤백됨을 확인한다.
  6. 격리 DB에 새 migration을 적용하고 동일 테스트의 GREEN을 확인한다. 기존 관련 release/admin cutover tests와 Node safety tests를 실행하고 결과·실행 명령·테스트 DB 식별·skip 구분을 보고한다. 금융 계산·운영 데이터가 이 migration 실행 자체로 바뀌지 않는지 확인한다.
