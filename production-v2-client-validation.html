3. 확인된 안전 속성

  • V2 model은 envelope/item exact keys, 정수 multiplier 11..30, 비어 있지 않고 unique+ascending인 ISO weekday, 시작<종료, explicit offset RFC3339 및 잘못된 달력/offset을 검증한다(promotion_campaign_v2.dart:15-32,73-119,151-255).
  • repository는 정확한 RPC get_active_promotion_campaigns_v2와 HOME/PAYMENT_BADGE wire value를 사용하며, PAYMENT_BADGE 응답에 HOME creative/ownership이 섞이면 거부한다(promotion_campaign_v2_repository.dart:8-47).
  • V2 active item은 authoritative하고, V2 empty 또는 PGRST202/raw socket/timeout만 V1 fallback 대상이다. permission/domain/decoder/programming 오류는 V1을 되살리지 않고 fail closed한다(promotion_badge_resolver_provider.dart:36-92).
  • HOME은 unreadable V2 creative를 숨기되 ownership을 유지하고, empty V2 fallback 시 V1/V2 owned banner ID를 합쳐 duplicate ordinary banner를 차단한다(promotion_badge_resolver_provider.dart:131-179).
  • HOME과 PAYMENT_BADGE provider family cache key가 분리되고 pull-to-refresh는 두 source provider와 resolver를 모두 invalidate한다(promotion_campaign_v2_provider.dart:12-16, home_page.dart:78-99, vote_home_page.dart:146-169).
  • Admin form은 KST +09:00, 시작<종료, weekday 필수, 1.1x..3.0x 정수 tenths, HOME/banner 결합, 독립 HOME/PAYMENT_BADGE toggle, V2 optimistic baseline을 구성한다(PromotionCampaigns.tsx:44-82,268-305,433-611).
  • Admin command route는 authenticated server actor를 주입하고 allowlist RPC만 호출하며 backend 오류 본문/secret을 노출하지 않는다(command-route-handler.ts:31-70).

9. 결론

현재 client 구현은 strict decoding, surface isolation, narrow fallback, server-authoritative settlement amount라는 좋은 안전 기반을 갖췄다. 그러나 동적 테스트 증거가 없는 상태이며 canonical badge fixture와 resolver code가 맞지 않고 pre-purchase V2/V1 표시가 분리되어 있으므로, production-first 활성화를 즉시 승인할 근거는 부족하다. 위 최소 재검증을 충족할 때까지 schema/RPC 배포가 이미 되어 있더라도 flag는 현 상태를 유지하는 것이 안전하다.
