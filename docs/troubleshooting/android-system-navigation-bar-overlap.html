안드로이드 시스템 내비 바 콘텐츠 겹침 (PICNIC-777)

작성일 2026-09-14. 2025-12 두 차례 수정(1.2.17+121732, 1.2.20+122003)에도 QA 재현이 계속된 건의 실제 원인과 수정 기록.

증상

Android 기기에서 투표 상세·리워드 상세·궁합·커뮤니티 게시글 등 스크롤 화면의 콘텐츠가 시스템 내비게이션 바(특히 3버튼 바) 밑으로 지나가며 겹쳐 보인다. iOS 에서는 재현되지 않는다.

원인

  • 앱은 targetSdk 36 이라 Android 15 이상에서 edge-to-edge 가 강제된다. 시스템 내비 바는 투명해지고 Flutter 뷰는 화면 끝까지 그려진다. Android 13 이하에서는 바가 자체 영역을 가져 겹침이 생기지 않는다(같은 코드로 실기기 SM-G781N 확인).
  • 앱은 SystemUiOverlayStyle(systemNavigationBarContrastEnforced: false) 로 대비 스크림까지 끄고, 각 페이지는 스크롤 끝에만 viewPadding.bottom 여백을 더한다. 그래서 스크롤 중간의 모든 행이 투명한 바 밑으로 그대로 지나간다. 이것이 QA 스크린샷의 상태다.
  • 2025-12 수정은 "Scaffold 제거 + 끝 여백 추가"였다. 끝 여백은 실제로 동작하고 있었지만 스크롤 중간 겹침은 구조상 해결되지 않았다.

기각한 가설: FixedWidthLayout 이 전역 스냅샷(globalMediaQueryProvider)으로 MediaQuery 를 덮어쓰지만, Android 15 에뮬레이터 진단 로그에서 스냅샷과 실제 값이 동일했다(padding.bottom = viewPadding.bottom = 48). "Android 15 에서 padding.bottom 이 0" 이라는 기존 코드 주석도 실측과 다르다.

수정

picnic_lib/lib/presentation/widgets/ui/system_navigation_bar_inset.dart 의 SystemNavigationBarInset 이 Android 에서 MediaQuery.padding.bottom 만큼 배경색 띠를 예약하고, 하위 트리의 padding.bottom·viewPadding.bottom 을 0 으로 만든다. 적용 지점은 두 곳이다.

지점이유
AppBuilder.applySystemNavigationBarInset → PageTransitionsTheme(Android 빌더를 SystemNavigationBarInsetPageTransitionsBuilder 로 감쌈)모든 MaterialPageRoute 본문(홈 Portal, 알림 → 투표 상세처럼 루트 내비게이터로 push 되는 라우트)이 자동으로 바 위에서 끝난다. 띠가 라우트 안쪽에 있어 모달 배리어가 띠까지 함께 어둡게 한다.
FullScreenDialog (리워드 상세 등)showGeneralDialog 라우트는 PageTransitionsTheme 을 타지 않는다.
FixedWidthLayout시작 시점 MediaQuery 스냅샷으로 하위를 덮어쓰던 곳. 스냅샷의 bottom 인셋(48)이 되살아나면 Portal 페이지가 이중 여백을 갖고 플로팅 내비가 48dp 위로 뜨므로, padding·viewPadding 은 라이브 값을 쓰도록 바꿨다.

거쳐 간 설계: (1) Portal + FullScreenDialog 개별 래핑 → Codex 교차 리뷰가 Navigator push 라우트 누락을 지적. (2) MaterialApp.builder 루트 래핑 → 에뮬레이터에서 모달 배리어가 Navigator 안만 어둡게 해 하단 띠가 밝게 남는 부작용 확인. (3) 최종: PageTransitionsTheme. 단, 래퍼 빌더에 값 동등성(==/hashCode)이 없으면 App 재빌드마다 ThemeData 가 달라져 Theme 의존 위젯 전부에 didChangeDependencies 가 돌고, Portal 페이지들이 settingNavigation 을 다시 호출해 투표 상세 위에 홈 헤더·플로팅 내비가 나타났다(에뮬레이터에서 다이얼로그를 열 때 재현). 회귀 테스트 test/core/utils/app_builder_dialog_dependencies_test.dart.

  • 높이 기준이 padding 이라 키보드가 바를 덮으면 띠도 사라진다(루트에서 라이브 MediaQuery 를 읽으므로 Portal 안에서도 성립).
  • 띠 색은 Theme.scaffoldBackgroundColor(흰색)다. 궁합 그라데이션 페이지에서는 하단에 흰 띠가 보이며, 삼성 One UI 는 그 위에 반투명 스크림을 덧그린다. 포털별 색 지정은 후속 판단 사항.
  • iOS·웹은 그대로다(홈 인디케이터 아래로 콘텐츠가 지나가는 기존 동작 유지).
  • 플로팅 하단 내비 마진 16 + viewPadding.bottom 은 16 + 0 이 되어 바에서의 거리는 이전과 같다.

함께 고친 잠재 결함: 다이얼로그가 열리면 내비게이션 상태가 뒤섞임

에뮬레이터 검증 중 투표 상세 위에 다이얼로그(로그인 필요 등)를 띄우면 헤더가 홈(Portal) 헤더로 바뀌고 플로팅 내비가 나타나는 현상을 발견했다. 원인은 이 티켓과 무관하게 이미 있던 경합이다.

  • RouteAwareStateMixin 이 ModalRoute.of(context) 로 구독하면서 32개 페이지 State 가 라우트 상태(isCurrent)에 영구 의존한다.
  • 다이얼로그가 열리고 닫힐 때마다 스택의 모든 페이지에 didChangeDependencies 가 돌고, 각 페이지가 post-frame 으로 settingNavigation 을 다시 호출한다. 마지막 호출이 이기며, 그 순서는 InheritedElement 의존자 해시 순서·트리 구조에 좌우된다.
  • 위젯 테스트로 확인: 같은 트리에서 인셋 테마 유무만 바꿔도 post-frame 순서가 home↔detail 로 뒤바뀐다. 즉 내 변경이 경합을 만든 게 아니라 결과를 뒤집어 드러냈다.

수정: AppRouteObserver 가 최상단 PageRoute 를 추적하고(currentPageRoute), 믹스인은 그 값으로 한 번만 구독한다. ModalRoute.of 는 옵저버가 없는 테스트 하네스에서만 폴백으로 쓴다. 이제 다이얼로그는 페이지의 didChangeDependencies 를 유발하지 않는다. 회귀 테스트 test/core/navigation/route_aware_mixin_test.dart 7건.

교차 리뷰(Codex GPT-5.6 Terra) 기록

  • 1차: Navigator push 라우트 누락(수용 → PageTransitionsTheme 적용), FixedWidthLayout 스냅샷(수용 → 라이브 padding/viewPadding), 궁합 그라데이션 띠 색(문서화).
  • 2차: (a) 외부 PageRoute pop 시 스택 전 페이지가 onRoutePopNext 를 받아 경합이 재현된다는 지적 — 변경 전에도 모든 페이지가 같은 홈 라우트에 구독돼 있었고, RouteObserver 는 구독자를 삽입 순서(LinkedHashSet)로 통지하므로 나중에 push 된 페이지의 post-frame 호출이 마지막에 적용된다(결정적). route_aware_mixin_test.dart 의 순서 테스트로 고정. (b) FixedWidthLayout 이 viewInsets 를 스냅샷으로 두어 키보드 리사이즈가 안 된다는 지적 — origin/main 과 동일한 기존 동작이며, 키보드 리사이즈를 새로 켜는 것은 이 티켓 범위 밖이다.

재현·진단 방법

  • 릴리스 APK 는 에뮬레이터에서 VM 감지로 종료된다. 디버그 빌드(disableInDebugMode)나 --dart-define=DISABLE_VM_CHECK=true 를 쓴다.
  • config/dev.json 은 로컬에 값이 비어 있어 ENVIRONMENT=prod 디버그 빌드로 확인했다.
cd picnic_app
flutter build apk --debug --target-platform android-arm64 \
  --dart-define=ENVIRONMENT=prod --dart-define=PANGLE_ENVIRONMENT=prod \
  --dart-define=PAYMENT_ENVIRONMENT=prod --dart-define=DISABLE_VM_CHECK=true
adb -s emulator-5554 shell cmd overlay enable com.android.internal.systemui.navbar.threebutton
adb -s emulator-5554 shell cmd overlay disable com.android.internal.systemui.navbar.gestural
