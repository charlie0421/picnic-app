Flutter 스플래시 일반 휴대폰 크기 복원 구현 계획

에이전트 작업 규칙: 이 계획은 superpowers:executing-plans 절차로 순서대로 실행한다. 각 단계는 테스트 우선으로 진행한다.

목표: 첫 번째 네이티브 시작 화면은 그대로 두고, 두 번째 Flutter 스플래시를 일반 세로형 휴대폰에서 이전 크기로 복원하면서 Fold와 태블릿에서는 안전한 최대 크기를 유지한다.

구조: ResponsiveSplash의 72% 축소 래퍼를 제거하고 중앙 ConstrainedBox에 최대 440x960 논리 픽셀을 적용한다. 기존 투명 이미지와 BoxFit.contain은 유지하며, 테스트는 일반 휴대폰의 화면 점유율과 Fold의 크기 상한을 실제 렌더 박스 크기로 검증한다.

기술: Flutter, flutter_test, Material 위젯 레이아웃

전역 제약

  • picnic_app/flutter_native_splash.yaml, Android·iOS 시작 리소스, 스플래시 이미지 에셋은 수정하지 않는다.
  • 배경색 #8B6CF6과 assets/splash_key.png를 유지한다.
  • BoxFit.contain과 모든 뷰포트의 오버플로 없음 검증을 유지한다.
  • 일반 휴대폰에 기기명 또는 화면비별 분기를 추가하지 않는다.
  • Fold·태블릿 이미지 레이아웃은 너비 440, 높이 960 논리 픽셀을 넘지 않는다.

파일 구조

  • 수정: picnic_app/test/presentation/splash/responsive_splash_test.dart — 일반 휴대폰 점유율, Fold 상한, contain 및 무오버플로 계약을 검증한다.
  • 수정: picnic_app/lib/presentation/splash/responsive_splash.dart — 두 번째 Flutter 스플래시의 반응형 크기만 결정한다.

작업 1: 일반 휴대폰 크기와 대화면 상한 계약

입력: 기존 ResponsiveSplash 위젯과 키 responsive-splash-fitted-box

출력: 일반 휴대폰에서는 가용 크기의 95% 이상을 사용하고, Fold에서는 440x960을 넘지 않는 중앙 FittedBox

  1. 실패 테스트 작성

    기존 공통 contain·무오버플로 반복 테스트에 360x800과 430x932를 추가한다. 별도 테스트에서 일반 휴대폰의 렌더 크기와 Fold의 상한을 다음과 같이 검증한다.

    const phoneViewports = <String, Size>{
  'compact phone portrait': Size(360, 800),
  'phone portrait': Size(393, 852),
  'large phone portrait': Size(430, 932),
};

for (final viewport in phoneViewports.entries) {
  testWidgets(
    'uses the available ${viewport.key} space without phone-specific branches',
    (tester) async {
      await tester.binding.setSurfaceSize(viewport.value);
      addTearDown(() => tester.binding.setSurfaceSize(null));
      await tester.pumpWidget(const MaterialApp(home: ResponsiveSplash()));

      final fittedSize = tester.getSize(
        find.byKey(const Key('responsive-splash-fitted-box')),
      );
      expect(fittedSize.width, greaterThanOrEqualTo(viewport.value.width * 0.95));
      expect(fittedSize.height, greaterThanOrEqualTo(viewport.value.height * 0.95));
    },
  );
}

testWidgets('bounds the unfolded Fold artwork', (tester) async {
  addTearDown(() => tester.binding.setSurfaceSize(null));
  for (final viewport in const [Size(1848, 2448), Size(2448, 1848)]) {
    await tester.binding.setSurfaceSize(viewport);
    await tester.pumpWidget(const MaterialApp(home: ResponsiveSplash()));

    final fittedSize = tester.getSize(
      find.byKey(const Key('responsive-splash-fitted-box')),
    );
    expect(fittedSize.width, lessThanOrEqualTo(440));
    expect(fittedSize.height, lessThanOrEqualTo(960));
  }
});

  2. RED 확인

    cd picnic_app
flutter test test/presentation/splash/responsive_splash_test.dart

    예상 결과: 기존 FractionallySizedBox의 72% 축소 때문에 일반 휴대폰 점유율 검증이 실패한다. 기존 contain 및 무오버플로 검증은 계속 통과해야 한다.

  3. 최소 구현

    FractionallySizedBox와 그 안쪽 Center를 제거하고 최대 높이를 960으로 변경한다.

    child: Center(
  child: ConstrainedBox(
    constraints: const BoxConstraints(
      maxWidth: 440,
      maxHeight: 960,
    ),
    child: FittedBox(
      key: const Key('responsive-splash-fitted-box'),
      fit: BoxFit.contain,
      child: Image.asset(
        'assets/splash_key.png',
        key: const Key('responsive-splash-key-image'),
      ),
    ),
  ),
),
