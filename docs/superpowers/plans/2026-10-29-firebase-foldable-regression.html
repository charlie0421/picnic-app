Firebase 업그레이드와 폴더블 회귀 검증

2026-10-29 · docs/foldable-ui-audit · 사용자가 Firebase 주요 버전 업그레이드와 기존 기능 검증을 승인했다.

업그레이드 구현과 빌드·회귀 검증을 마쳤다. 자동 테스트에서 새 회귀는 확인하지 못했다. 기존 실패 13건과 알림 탭·실서비스 검증 제한은 아래에 구분했다. 수정 후 독립 재확인도 완료했고 코드 차단 사항은 없었다. 실기기 알림 탭·서비스 QA는 남아 있다. 배포 승인 상태가 아니다.

빌드 및 테스트 중 확인한 제한

  • 기존 iOS 빌드 폴더에 Core 4 Objective-C 헤더와 Core 5 Swift 헤더가 함께 남아 충돌했다. 생성 산출물을 정리한 재빌드에서 해결했다. StoreKit 버전 정렬 후에도 이전 precompiled module을 clean했다.
  • Android에서 새 테스트용 Firebase 앱을 곧바로 삭제하면 Installations의 백그라운드 작업과 경합하여 FirebaseApp was deleted 충돌이 재현됐다. 실제 제품은 Firebase 앱을 삭제하지 않는다. 시작 검증에서는 앱 프로세스 종료까지 테스트 앱을 유지한다. SDK의 즉시 삭제 안전성을 검증했다고 주장하지 않는다.
  • Messaging 17의 notDetermined 원시 값은 -1이다. 테스트가 유효한 상태값을 빠뜨렸던 오류를 설치된 소스와 대조해 수정했다.
  • 실제 OAuth 제공자 로그인, APNs/FCM 서버 전달, 결제·복원 실거래, Analytics DebugView, Branch 연관 도메인의 서버 응답은 검증하지 않았다. 합성 알림과 단위 테스트를 이 검증의 대체로 표시하지 않는다.

Branch 초기화 근거

설치된 Flutter 엔진 revision e4b8dca3f1b4ede4c30371002441c88c12187ed6의 FlutterViewController.mm 308–328행에서 implicit engine 콜백으로 플러그인을 등록한 뒤 launch fallback을 호출한다. 일반 콜드 실행의 네이티브 로그에서도 Branch InitSession 결과 1회를 확인했다. Branch 연관 도메인의 실제 링크 응답과 라우팅 횟수는 별도 실기기 QA 대상으로 남긴다.

독립 리뷰

2026-10-29 Orca의 읽기 전용 Claude Opus 5.5/high가 Codex 구현의 F1–F5 지적 사항을 재확인했다. F1 구매 잠금 파일 정렬, F4 Firebase Podfile 핀과 lock 일치, F5 SceneDelegate의 프로젝트·Info.plist·테스트 포함을 확인했다. F3 Branch 초기화는 조정자가 제시한 엔진 근거와 InitSession 1회 로그로 수용했다. 검토자는 제한 범위 밖의 엔진·플러그인 소스나 커밋34abe5fd4의 내용을 직접 조회하지 않았다. 코드 차단 사항은 없었다. ctx_36b6ef1fb022 작업자의 worker_done(succeeded)가 수락됐다(msg_413be26ec771).

F2는 배포 전 실기기 QA 항목으로 유지한다. 원격·로컬 알림의 종료 상태 탭에서 초기 메시지와 목적 화면 전달을 확인하지 못했다. SceneDelegate가 notificationResponse를 직접 전달하지 않는 경로와 플러그인의 처리 여부를 실제 기기에서 검증해야 한다. 독립 재확인 완료를 알림 실서비스 QA 통과로 해석하지 않는다.

남은 확인 항목

  1. 실제 iOS 기기에서 원격·로컬 알림 각각을 종료 상태 및 백그라운드 상태에서 눌러 초기 메시지·탭 이벤트와 목적 화면을 확인한다.
  2. QA 계정으로 OAuth 복귀, Branch 연관 링크, 결제·복원, Analytics DebugView를 확인한다. Galaxy Fold8의 실제 화면·힌지·키보드 동작은 실기기로 확인한다.
