이미지 Progressive·Cache Key 구현 계획

목표: 각 이미지를 단일 최종 URL로 로드하고 URL을 그대로 cache key로 사용한다.

구조: URL resolver는 그대로 두고, widget의 variant 선택과 URL 배열/인덱스 key 결합만 제거한다. 위젯 lifecycle과 공개 API는 유지한다.

전역 제약

  • memCacheWidth/DPR·전역 ImageCache·lazy/priority·호출부 API는 수정하지 않는다.
  • URL 변경, 외부 URL, CDN URL, 동시 표시의 기존 계약은 유지한다.
  • production 코드는 반드시 실패한 테스트 뒤에 작성한다.

작업 1: 단일 URL/cache key 계약 (RED)

  • 수정: picnic_lib/test/presentation/common/picnic_cached_network_image_regression_test.dart
  • 테스트: medium/high CDN 이미지가 하나의 요청만 만들고, cache key가 최종 URL과 동일하며, URL 변경 뒤 이전 key를 재사용하지 않음을 검증한다.
  • 실행:
    flutter test test/presentation/common/picnic_cached_network_image_regression_test.dart
    예상: 기존 progressive URL/key 구현 때문에 새 단언이 실패한다.

작업 2: 최소 위젯 변경 (GREEN)

  • 수정: picnic_lib/lib/presentation/common/picnic_cached_network_image.dart
  • _getTransformedUrls가 resolver에서 얻은 최종 URL 하나만 반환하게 하고, _cacheKeyFor는 URL을 반환하게 한다. URL 배열 index와 low-quality 분기는 제거한다.
  • 작업 1 명령을 다시 실행해 통과시킨다.

작업 3: 회귀 확인

  • 실행:

dart analyze lib/presentation/common/picnic_cached_network_image.dart
  • 전체 picnic_lib 테스트 결과는 기존 실패와 변경으로 인한 실패를 분리해 기록한다.
