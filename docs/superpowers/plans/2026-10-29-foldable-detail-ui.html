이전 점검 보고서

고객문의 상세·입력·첨부 삭제, 달성형 투표, 제휴 투표 입력을 점검했다. 커뮤니티·댓글은 제외했다. 검증에는 로컬 데이터와 서비스 대역을 사용했다. 실제 문의·투표 전송, 결제, 광고 요청은 실행하지 않았다.

확인한 문제와 수정

영역재현 조건수정
고객문의 입력좁거나 낮은 창, 글자 2.6배, 키보드 표시. 안내문과 분류명이 고정 공간을 차지해 본문·입력 영역이 최대 154px 넘쳤다.분류명을 대화 목록에서 스크롤한다. 입력 영역은 사용 가능한 본문 높이의 최대 60%로 제한하고, 안내·첨부·입력을 스크롤할 수 있게 했다. 입력란은 아래쪽에서 바로 접근한다.
고객문의 오류·첨부큰 글씨에서 오류 안내와 재시도 버튼이 최대 95px 넘쳤다. 첨부 미리보기와 입력을 함께 표시하면 최대 101px 넘쳤다.오류 화면과 입력 영역에 스크롤을 제공한다. 재시도·첨부 삭제·전송 버튼의 접근성을 테스트했다. 실제 전송은 하지 않았다.
달성형 투표긴 제목·큰 글씨에서 고정 헤더가 최대 580px 넘쳐 보상 목록에 접근하지 못했다.제목·후보·보상 목록을 같은 페이지에서 스크롤한다. 당겨서 새로고침과 투표 폴링을 유지한다. 숫자 애니메이션의 중첩 스크롤 알림은 페이지 폴링 제어에서 제외한다.
달성 목표 숫자글자 2.6배에서 123,456,789가 고정 50px 높이를 벗어나 잘렸다.실제 글꼴·배율로 목표 숫자 높이를 측정해 단계 높이를 늘린다. 진행 막대에도 같은 단계 높이를 적용한다. 숫자는 생략하거나 축소하지 않는다. 큰 글씨의 긴 숫자는 여러 줄로 표시한다.
제휴 투표 입력키보드가 표시된 상태의 창 크기 전환.위젯 검증 18개에서 입력값과 커서가 유지됐다. 화면 코드의 추가 수정은 없었다.

첫 네이티브 실행은 제휴 입력 포맷터 처리 전에 커서를 설정해 커서 검증이 실패했다. 포맷터 처리 후 커서를 설정하고, 전환 직전 위치를 검증하도록 테스트를 고쳤다. 이후 두 플랫폼에서 통과했다.

독립 리뷰 후에는 테스트 보강과 글자 높이 측정의 중복 제거를 적용했다. 최종 위젯·회귀 검증은 이 변경을 포함한다. 네이티브 화면 증거는 측정 중복 제거 직전 실행에서 수집했다.

검증 범위의 한계

  • Duo는 iOS 27.1 Simulator를 사용한다. Galaxy Fold8은 Android API 35 에뮬레이터에서 커버 400×640과 펼침 800×600 비율을 재현한다. 실제 Fold8 하드웨어·One UI 결과로 해석하지 않는다.
  • 현재 연결된 실기기는 SM-G781N(Android 13)이다. 이 기기에 앱을 설치하거나 설정을 변경하지 않았다.
  • 첨부 검증은 선택된 파일의 미리보기·삭제 UI를 포함한다. OS 사진 선택기의 권한 전환, 실제 파일 업로드, 영상 재생·전체 화면 이미지 탐색의 폴드 전환은 이번 검증에 포함하지 않았다.
  • 실제 문의·투표·결제·광고 기능의 서버 통합은 별도 검증이 필요하다.
