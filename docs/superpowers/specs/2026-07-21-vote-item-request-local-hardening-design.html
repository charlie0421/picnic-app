Task #39: 투표 신청 로컬 안정화 설계

상태: 구현 전 승인 설계
대상: picnic_lib
제외: 실제 Supabase DB 변경, 마이그레이션 실행, 원격 RLS 변경

1. 배경과 확인된 문제

  • 초기 신청 내역 조회 실패가 빈 목록처럼 표시되어 서버·권한 오류를 사용자가 구분할 수 없다.
  • 검색 실패 시 _isSearching이 해제되지 않아 로딩 표시가 계속될 수 있다.
  • 대기 상태에 서로 다른 번역 문자열(대기중, 대기 중)을 비교해 배경색과 아이콘·글자색이 달라진다.
  • 저장소 래퍼가 기존 도메인 예외를 일반 VoteRequestException으로 다시 감싸 의미를 잃을 수 있다.
  • PostgreSQL 42P01 오류가 사용자에게 내부 예외 문자열 그대로 노출될 수 있다.
  • 현재 저장소에는 canonical DB migration/RLS 정의가 없어 실제 권한 정책은 로컬에서 확정할 수 없다.

2. 목표

  1. 네트워크·RLS·테이블 오류가 빈 상태나 무한 로딩으로 오인되지 않게 한다.
  2. 사용자에게 내부 DB 세부 정보를 노출하지 않는 안정적인 오류 메시지를 제공한다.
  3. 대기 상태 표시를 하나의 의미로 정규화한다.
  4. 실제 DB 없이 mock과 widget test로 회귀를 방지한다.

3. 설계

영역변경검증
다이얼로그 로딩 초기 조회와 검색을 try/catch/finally로 정리한다. 실패 시 로딩 상태를 반드시 해제하고, 빈 목록과 구분되는 일반 오류 상태를 표시한다. 실패 주입 후 오류 표시 및 spinner 종료를 widget test로 확인한다.
상태 표시 대기 상태 판단을 번역된 화면 문자열 두 개에 의존하지 않도록 단일 판정 함수로 모은다. 현재 API 호환성을 유지하기 위해 공개 모델 구조는 변경하지 않는다. 배경·테두리·아이콘·텍스트 색상을 함께 검증한다.
저장소 예외 VoteRequestException과 하위 도메인 예외는 그대로 재전파한다. 알 수 없는 오류만 작업별 문맥을 붙여 변환한다. 중복 예외 타입 보존과 각 래퍼의 실패 경로를 단위 테스트한다.
테이블 누락 PostgrestException.code == 42P01을 감지해 내부 테이블명이나 원문 대신 “현재 투표 신청 기능을 사용할 수 없습니다” 계열의 고정 메시지로 변환한다. 42P01 mock과 일반 오류 mock의 메시지를 각각 검증한다.

4. 테스트 범위

  • 저장소: 상태 hit/miss, 신청 여부 true/false, 정확한 필터·반환값, 예외 타입 보존, 42P01 변환.
  • 다이얼로그: 초기 로딩 실패, 검색 실패, 로딩 종료, 일반 오류 노출.
  • 상태 UI: pending/approved/rejected/mixed의 라벨, 아이콘, 색상, 카운트 표시.
  • 기존 투표 신청 관련 집중 테스트 전체를 회귀 테스트로 실행한다.

5. 범위 밖 및 후속 작업

vote_requests/vote_request_users와 현재 코드의 vote_item_requests/vote_item_request_users 중 어느 것이 운영 스키마인지 이 작업에서 추정하지 않는다. Task 39.6은 완료 처리하지 않는다.

후속 작업에서 read-only schema dump, RLS 정책, role grant, SECURITY DEFINER 함수, unique constraint를 운영 환경 기준으로 검증하고 canonical migration을 복구해야 한다.

6. 완료 조건

  • 실패 경로에서 로딩 상태가 항상 종료된다.
  • DB 내부 오류 문자열이 UI에 노출되지 않는다.
  • 대기 상태의 모든 시각 요소가 일관된다.
  • 추가 및 기존 집중 테스트가 모두 통과한다.
  • 실제 DB와 원격 RLS에는 변경이 없다.
