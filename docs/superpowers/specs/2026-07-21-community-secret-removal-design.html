커뮤니티 비밀키 제거 설계

목표

현재 비활성화된 커뮤니티 코드는 향후 재활성화를 위해 보존하면서, picnic_app에 번들되는 AWS, DeepL, YouTube 자격증명을 제거한다.

적용 범위

  • picnic_app/config/dev.json, local.json, prod.json의 AWS access key, AWS secret key, DeepL API key, YouTube API key를 빈 문자열로 교체한다.
  • 자격증명이 없으면 S3 업로드, DeepL 번역, 모바일 YouTube 메타데이터 요청을 실행하지 않는다.
  • 앱에 포함되는 환경설정 파일에 민감 자격증명이 다시 추가되지 않도록 자동 회귀 테스트를 작성한다.
  • 기존 설정 키는 유지하여 현재 설정 파싱 구조와 호환성을 보존한다.

제외 범위

  • 커뮤니티 소스 코드 및 관련 의존성 삭제
  • Supabase Edge Function 프록시 구축
  • Supabase anon key, Firebase 설정, OAuth client ID, 광고 SDK ID 변경
  • 커뮤니티 화면 재설계 또는 새로운 기능 비활성화 UI 추가
  • AWS, DeepL, Google 콘솔에서의 자격증명 폐기·재발급

구조

기존 설정 스키마는 유지하되 민감한 값만 비운다. 각 클라이언트 연동부는 네트워크 요청 전에 자격증명 존재 여부를 검사하고, 값이 없으면 일관된 설정 오류로 로컬에서 종료한다. 호출 위젯은 기존 오류 처리 경로를 그대로 사용하여 변경 범위를 최소화한다.

회귀 테스트는 picnic_app/config의 모든 JSON 파일에서 다음 경로가 비어 있는지 검증한다.

  • storage.aws.access_key_id
  • storage.aws.secret_access_key
  • api_keys.deepl
  • api_keys.youtube

처리 흐름

S3 업로드

  1. 커뮤니티 업로드 코드가 S3Uploader를 생성하거나 호출한다.
  2. S3Uploader는 요청 서명 전에 access key와 secret key가 비어 있지 않은지 검사한다.
  3. 자격증명이 없으면 외부 요청 없이 로컬 설정 예외를 발생시킨다.
  4. 기존 업로드 오류 처리 화면이 실패 상태를 표시한다.

DeepL 번역

  1. 댓글 번역 동작이 DeepLTranslationService를 생성한다.
  2. 번역 요청 전에 API key가 비어 있지 않은지 검사한다.
  3. 자격증명이 없으면 외부 요청 없이 로컬 설정 예외를 발생시킨다.
  4. CommentItem의 기존 번역 실패 스낵바를 사용한다.

YouTube 메타데이터

  1. 웹은 기존 Supabase youtube-preview 함수를 계속 사용한다.
  2. 모바일은 Google API 호출 전에 YouTube API key를 검사한다.
  3. 자격증명이 없으면 외부 요청 없이 기존 기본 VideoInfo를 반환한다.

오류 처리

  • 자격증명 존재 여부는 앞뒤 공백을 제거한 후 판단한다.
  • 예외 메시지와 로그에 자격증명 값을 포함하지 않는다.
  • S3와 DeepL은 자격증명 없이 의미 있는 결과를 만들 수 없으므로 명시적으로 실패한다.
  • YouTube는 API 메타데이터가 없어도 공개 썸네일과 기본 임베드를 표시할 수 있으므로 기존 fallback 동작을 유지한다.

테스트

  • 세 환경설정 파일과 네 민감 경로를 모두 검사하는 설정 테스트를 추가한다.
  • S3와 DeepL이 빈 자격증명을 네트워크 요청 전에 거부하는 단위 테스트를 추가한다.
  • 모바일 YouTube 서비스가 키 없이 HTTP 요청을 보내지 않고 fallback을 반환하는 테스트를 추가한다.
  • 집중 테스트 후 영향받는 테스트 디렉터리, picnic_app 및 picnic_lib 정적 분석을 실행한다.
  • 기존의 무관한 분석·테스트 실패는 숨기지 않고 별도로 보고한다.

운영 후속 조치

코드 변경 배포와 별개로 권한이 있는 운영자가 노출된 AWS, DeepL, YouTube 자격증명을 반드시 폐기해야 한다. 새로운 장기 비밀키를 모바일 환경설정에 다시 추가해서는 안 된다.
