이미지 Progressive·Cache Key 단순화 설계

PicnicCachedNetworkImage 2단계 · 2026-08-10

목표

다단계 progressive 이미지 요청을 제거하고, 각 이미지의 cache key를 최종 URL과 동일하게 만들어 URL·캐시 식별자·렌더링 순서를 하나의 값으로 정렬한다.

범위

  • 위젯이 low/medium/high에 따라 여러 URL을 생성하던 정책을 최종 URL 하나로 축소한다.
  • cache key에서 reload token, variant index, low-quality 접미사 의존을 제거하고 URL 자체를 사용한다.
  • URL 변경, 외부 URL, CDN URL, 동시 표시, 캐시 재사용을 회귀 테스트로 고정한다.

대안과 결정

  1. 기존 progressive 구조를 유지하며 key만 단순화: URL 배열과 인덱스 결합 위험이 남는다.
  2. 단일 최종 URL + URL 동일 cache key(선택): 중복 다운로드와 인덱스 기반 식별자를 없애고 테스트 가능성을 회복한다.
  3. 전역 이미지 캐시나 호출부까지 동시에 수정: 롤백 범위가 넓어져 이번 단계에서는 제외한다.

불변 조건

  • 공개 생성자와 호출부 API는 바꾸지 않는다.
  • URL resolver의 CDN·외부 URL 계약, timeout·retry·URL 변경 lifecycle은 유지한다.
  • memCacheWidth/DPR, 전역 ImageCache, lazy/priority 정책은 변경하지 않는다.

오류 처리와 검증

외부 URL과 초기화되지 않은 Environment 경로는 원문 URL을 유지한다. 구현 전 새 단일 URL/cache key 계약 테스트를 RED로 확인하고, 이후 focused 회귀·전체 picnic_lib 테스트·정적 분석을 실행한다. 전체 스위트의 기존 실패는 변경 범위와 분리해 보고한다.
