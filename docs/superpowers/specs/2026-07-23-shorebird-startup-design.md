# Shorebird Startup Design

## 목표

앱 시작 시 Shorebird 엔진의 자동 업데이트 확인과 애플리케이션의 수동
`checkForUpdate()`가 동시에 실행되지 않게 하여 내부 설정 잠금 경합 가능성을
제거한다. Shorebird 또는 네트워크 장애는 스플래시 화면과 홈 진입을 막지 않는다.

## 현재 문제

- Shorebird 엔진은 릴리스 앱 시작 시 자체적으로 업데이트를 확인한다.
- `checkForUpdates()`도 시작 과정에서 `ShorebirdUpdater.checkForUpdate()`를
  호출한다.
- 사용 중인 SDK 구현은 다른 스레드가 동시에 Shorebird 설정에 접근하면 내부
  Rust 설정 잠금을 기다리며 멈출 가능성을 명시하고 있다.
- 앱스토어 강제 업데이트 판정과 Shorebird 패치 확인이 한 함수에 결합되어 있어,
  Shorebird 작업이 끝나지 않으면 전체 초기화가 끝나지 않는다.

## 설계

### 시작 경로

- `AppInitializer`의 시작 단계에서는 Supabase `version` 정보를 사용한 앱스토어
  버전 판정만 실행한다.
- 시작 단계에서 `ShorebirdUpdater`를 생성하거나 `checkForUpdate()`를 호출하지
  않는다.
- Shorebird 엔진의 기본 자동 업데이트 확인을 유일한 시작 시 확인 경로로
  사용한다.
- 시작 단계의 버전 판정에는 기존 8초 제한시간과 실패 시 계속 진입하는 정책을
  유지한다.

### 명시적 수동 확인

- 설정 화면 등 사용자가 직접 요청한 확인에서는 수동 Shorebird 호출을 허용한다.
- 모든 수동 호출은 하나의 공유 실행 조정자를 통과한다.
- 동일 작업이 진행 중이면 새로운 네이티브 호출을 만들지 않고 진행 중인 Future를
  공유한다(single-flight).
- 수동 확인에는 10초 제한시간을 적용하고 실패 또는 시간 초과 시
  `UpdateStatus.unavailable`로 종료한다.

### 패치 다운로드

- 시작 스플래시에서는 패치를 직접 다운로드하지 않는다.
- 사용자가 수동으로 확인하거나 앱이 완전히 진입한 이후의 별도 경로에서만
  다운로드한다.
- 다운로드 실패는 로깅하고 앱 실행 상태에는 영향을 주지 않는다.

## 오류 처리

- Shorebird unavailable, 예외, 시간 초과는 모두 비치명적 상태다.
- Supabase 버전 조회 실패도 캐시 또는 `null`로 종료하고 앱 진입을 계속한다.
- 기기 차단 확인과 Shorebird 확인은 서로 독립적으로 유지한다.

## 테스트

- 시작용 업데이트 서비스가 Shorebird API를 호출하지 않는지 검증한다.
- 공유 실행 조정자에 동시 요청을 보내 네이티브 작업이 한 번만 실행되는지
  검증한다.
- 공유 실행 조정자가 제한시간 이후 fallback 값을 반환하는지 검증한다.
- 기존 업데이트 판정 및 시작 안정화 테스트를 함께 실행한다.
- 스테이징 설정으로 iOS 시뮬레이터 콜드 스타트가 홈 진입까지 완료되는지
  확인한다. Shorebird 자체 동작은 공식 제약에 따라 물리 iOS Release 빌드에서
  TestFlight로 최종 확인한다.

## 범위 제외

- Shorebird 패치 배포 정책 또는 트랙 구성 변경
- Supabase 스키마 변경
- 프로덕션 배포
- 기기 차단 정책 변경
