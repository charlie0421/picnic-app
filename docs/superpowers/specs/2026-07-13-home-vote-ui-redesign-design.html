1. 목표 / 비목표

목표

  • 홈 진입 구조 단순화 (미사용 상단 기능 제거).
  • 홈(요약형 허브)과 투표 페이지(탐색형 리스트)의 목적 분리.
  • 투표 종류 탭 도입(가로 스크롤·스와이프). 기존 area 필드 재활용 — 백엔드 신설 없이 최소 변경.

비목표 (이번 범위에서 건드리지 않음)

  • 투표 상세 페이지 세부 레이아웃 · 저장/공유 내부 로직.
  • 홈 진행중 투표 카드의 최종 비주얼(기능만 구현).
  • 궁합/PIC/커뮤니티 포탈 화면 자체(코드·딥링크 보존, 상단 진입점만 제거).

2. 확정된 의사결정 (사용자 승인 2026-07-13)

항목결정
투표 종류 탭 데이터 소스기존 area 필드 재활용 (스키마 변경 없음). 탭 목록은 앱 const config
탭 ↔ area 매핑PICNIC→kpop / PIC CHART→pic-chart / MUSICAL→musical / SPOTLIGHT→spotlight. 기존 재태깅 없음

상단 Vote/Goong-Hap 버튼 · 커뮤니티 탭 제거상단 진입점만 제거. 궁합/PIC/커뮤니티 포탈 코드·딥링크는 보존
홈 "현재 진행중인 투표" 대표 선정곧 종료되는 진행중 (active 중 stop_at ASC 첫 1건)

2.1 DB 실측 근거 (탭↔area 매핑)

vote.areas에 실제 존재하는 값은 kpop(179건), musical(24건) 둘뿐. pic-chart/spotlight는 데이터 없음.

탭area 코드현재 데이터비고
PICNICkpop179건생일/데뷔/위클리/image 등 기존 전부 커버
PIC CHARTpic-chart0건신규. 중앙데일리 콘텐츠 태깅 시 노출
MUSICALmusical24건기존 그대로
SPOTLIGHTspotlight0건신규. 지하철 콘텐츠 태깅 시 노출
스키마 변경·기존 재태깅 불필요. PIC CHART/SPOTLIGHT는 admin이 votes.areas에 값 추가 전까지 빈 목록(정상 동작).

3. 영향 범위 (단일 레포)

  • picnic-app 만 변경. 백엔드 마이그레이션 없음.
  • 신규 area 값(pic-chart/spotlight)은 스키마가 아니라 데이터 — admin이 vote 생성/편집 시 areas 배열에 값을 넣으면 즉시 해당 탭에 노출(앱 배포와 독립).

4. 현재 구조 매핑 (탐색 결과 요약)

4.1 하단 네비게이션

  • NavigationConfigs._screenInfoMap(navigation_configs.dart L16–139)가 실제 렌더 소스. vote 탭(L18–51): nav_vote/nav_community/nav_media/nav_store.
  • bottom_navigation_menu.dart의 voteScreenInfo는 vestigial(pages.length만 사용) → 정합 위해 함께 수정.
  • home.svg 아이콘 이미 존재.

4.2 상단 헤더 — portal.dart (L22–169)

  • 제거 Vote/Goong-Hap PortalMenuItem(L107–108), AttendanceIconButton(L131).
  • 유지 프로필 leading(L55–95), 알림 TopRightNotifications(L133), 민트 AppBar.

4.3 헤더 제어 메커니즘

  • settingNavigation({showPortal, showBottomNavigation, showTopMenu, showMyPoint, topRightMenu, pageTitle})를 각 페이지가 _updateNavigation()에서 호출.
  • showTopMenu:false → portal.dart의 if (showTopMenu) const TopMenu() 스킵 → 흰색 스트립(별사탕+area드롭다운+타이틀) 통째 제거. 홈/투표 화면에서만 false.

4.4 투표 페이지 — vote_list_page.dart

  • 상태 탭: TabBar+TabBarView(NeverScrollableScrollPhysics → 스와이프 불가). 인덱스 PageStorage persist.
  • 카테고리 드롭다운 AreaSelector(제거 대상).
  • 데이터 AsyncVoteList.build(page, limit, sort, order, area, {...}) — area != 'all'이면 이미 .contains('areas',[area]) 서버 필터 적용. 종류 탭이 이 area를 그대로 활용.
  • 카드 VoteInfoCard(1~3위) 유지.

4.5 홈 카드 · 리워드 · 배너 · 미디어

  • VoteInfoCard 공용(수정 금지) → 홈은 별도 카드. CountdownTimer / ShareSection 재사용.
  • 리워드 _buildRewardList(가로 스크롤, asyncRewardListProvider), 배너 CommonBanner('vote_home', 786/400).
  • 미디어 media id DESC, 모델 VideoInfo. 가로 캐러셀 없음 → 리워드 패턴 복제.

5. 변경 설계

5.1 하단 탭바 + 헤더

  1. navigation_configs.dart vote pages 재정의: community 제거, 홈0(HomePage)/투표1(VoteListPage)/미디어2/상점3. bottom_navigation_menu.dart 동기화.
  2. portal.dart: Vote/Goong-Hap 버튼 + 출석체크 제거. 프로필/알림/민트 유지.
  3. 홈·투표 페이지가 settingNavigation(showTopMenu:false) 호출 → 흰색 스트립 제거.
  4. 포탈 전환·궁합/PIC/커뮤니티 화면 코드 보존.

5.2 투표 종류 탭 (area 재활용, 백엔드 무변경)

탭 목록은 앱 const config. 신규 종류 추가 = config 1줄 + votes.areas 태깅(DB 테이블 불필요). 라벨은 영어 리터럴. provider/모델 변경 없음.

const _voteTabs = [
  ('PICNIC',    'kpop'),
  ('PIC CHART', 'pic-chart'),
  ('MUSICAL',   'musical'),
  ('SPOTLIGHT', 'spotlight'),
];

5.3 투표 페이지 재구성 (vote_list_page.dart)

  • 투표 종류 탭: _voteTabs 기반 TabBar(isScrollable:true) + TabBarView(스와이프 허용). TabController.length = _voteTabs.length.
  • 상태 필터 드롭다운: 진행중/종료됨/예정됨, 기본값 항상 진행중, 페이지 로컬 state(재진입 미저장 — PageStorage 제거).
  • 각 탭 = VoteList(status, VoteCategory.all, tab.area, portal: VotePortal.vote). area가 서버 필터로 걸림.
  • 페이지 타이틀은 본문에서 렌더(showTopMenu:false). admin 디버그는 드롭다운 (Admin) 항목으로 편입(선택).

6. 검증 계획

  • flutter analyze + 변경 파일 대상 flutter test(picnic_lib).
  • 코드 생성(신규 provider): cd picnic_lib && dart run build_runner build --delete-conflicting-outputs.
  • l10n: flutter gen-l10n(picnic_lib).
  • 수동: 하단탭 4개, 홈 4섹션, 종류 탭 스와이프 + 상태 드롭다운 기본 진행중 + 재진입 리셋, 미디어 6개. PIC CHART/SPOTLIGHT는 태깅 전까지 빈 목록(정상). 마이그레이션 불필요라 즉시 실행 가능.
