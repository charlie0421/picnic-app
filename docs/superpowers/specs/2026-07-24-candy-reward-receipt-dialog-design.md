# 캔디 적립 영수증 팝업 설계

## 1. 목적

광고 보상과 구매 완료 시 서로 다른 형태로 표시되는 적립 결과를 하나의
브랜드 경험으로 통합한다. 승인된 B 타입인 `공통 캔디 영수증`을 사용하며,
코튼캔디뿐 아니라 스타캔디와 보너스 스타캔디 적립에도 확장한다.

팝업은 서버가 확정한 적립 결과를 사용자에게 설명하는 표시 계층이다. 앱이
지급액이나 최종 잔액을 추정하지 않는다.

## 2. 범위

### 포함

- 내부 숏폼과 광고 보상으로 지급된 코튼캔디
- 인앱 구매로 지급된 스타캔디와 보너스 스타캔디
- 공통 영수증 UI, 국제화, 접근성, 반응형 레이아웃
- 광고 복구 흐름과 구매 검증 완료 흐름의 연결
- 위젯, 상태 변환, 중복 표시 방지 회귀 테스트

### 제외

- 출석, 운영자 수동 지급 등 아직 서버 확정 지급 DTO가 연결되지 않은 경로
- 적립 정책, 지급량, 만료 정책 변경
- 서버 원장이나 결제 검증 방식 변경
- 실패·대기 상태의 신규 디자인

## 3. 디자인 방향

팝업은 `캔디가 적립됐어요!`라는 공통 제목과 지급 항목 목록, 단일 확인
버튼으로 구성한다.

각 지급 항목은 다음 정보를 순서대로 표시한다.

1. 승인된 재화 아이콘
2. 재화명
3. `+지급량`
4. 적립 후 현재 보유량
5. 필요한 경우에만 보조 정보

코튼캔디의 보조 정보에는 서버가 제공한 만료 정보를 표시할 수 있다.
스타캔디와 보너스 스타캔디에는 만료 안내를 표시하지 않는다.

지급량이 0 이하인 항목은 만들지 않는다. 따라서 일반 구매에서는
스타캔디만 표시할 수 있고, 프로모션 구매에서는 스타캔디와 보너스
스타캔디를 함께 표시할 수 있다.

## 4. 컴포넌트 구조

### `CandyRewardReceiptDialog`

표시만 담당하는 공통 다이얼로그다. 광고나 구매 도메인을 직접 알지 않으며,
정규화된 `CandyRewardReceipt`만 입력받는다.

### `CandyRewardReceipt`

- 안정적인 지급 참조 ID
- 표시할 지급 항목 목록
- 선택적 보조 메시지

### `CandyRewardReceiptItem`

- `WalletCurrency currency`
- `int grantedAmount`
- `int? balanceAfter`
- 선택적 만료 시각 또는 이미 포맷되지 않은 만료 데이터

포맷된 문자열 대신 원시 값과 통화 enum을 전달한다. 다이얼로그가 현재
locale을 사용해 재화명, 숫자와 날짜를 표시한다.

### 어댑터

- 광고 어댑터는 확정된 `AdRewardStatusModel.grant`와 권위 지갑 snapshot을
  코튼캔디 한 항목으로 변환한다.
- 구매 어댑터는 서버 검증 결과의 기본 스타캔디와 프로모션 보너스를 각각
  항목으로 변환하고, 지급량이 0인 항목을 제거한다.

어댑터는 UI에 서버 응답 객체 전체가 퍼지지 않게 하는 경계다.

## 5. 데이터 흐름

### 광고

1. 광고 보상 callback 또는 복구 polling이 `GRANTED`를 확인한다.
2. 동일 지급 참조가 아직 표시되지 않았는지 확인한다.
3. 서버 확정 grant와 최신 wallet summary로 영수증을 만든다.
4. 팝업 첫 프레임이 렌더링된 뒤 기존 acknowledge 절차를 실행한다.
5. 사용자가 확인하면 다음 대기 보상을 처리한다.

광고 복구의 durable queue와 acknowledge 의미는 유지한다.

### 구매

1. 스토어 결제 이벤트만으로 팝업을 열지 않는다.
2. 서버 영수증 검증과 지갑 적립이 성공한 뒤 확정 지급 결과를 받는다.
3. 기본 스타캔디와 보너스 스타캔디 중 양수 항목만 영수증에 넣는다.
4. 같은 구매 결과에 성공 팝업이 두 번 열리지 않도록 기존 구매 시도
   식별자와 서버 지급 참조를 사용한다.
5. 팝업을 닫은 뒤 스토어의 지갑 표시도 같은 권위 snapshot을 적용한다.

## 6. 국제화

한국어 문자열을 위젯에 하드코딩하지 않는다.

다음 ARB 메시지를 추가한다.

- `candy_reward_receipt_title`: 캔디 적립 완료 제목
- `candy_reward_receipt_confirm`: 확인 버튼
- `candy_reward_receipt_amount`: 양수 지급량
- `candy_reward_receipt_balance`: 현재 보유량
- `candy_reward_receipt_balance_unavailable`: 잔액을 표시할 수 없을 때 안내
- `candy_reward_receipt_expiry`: 코튼캔디 만료 안내
- `candy_reward_receipt_semantics`: 한 지급 행의 접근성 요약

기존 `wallet_star_candy`, `wallet_bonus_star_candy`,
`wallet_cotton_candy`를 재사용한다. 숫자는 Flutter의 locale-aware
`NumberFormat`을 사용하고, 날짜와 시각은 사용자 locale 및 현지 시간대로
표시한다.

템플릿 locale에 메시지와 placeholder metadata를 정의하고 프로젝트의
기존 fallback 정책에 따라 모든 생성 localization 파일을 갱신한다.

## 7. 접근성 및 반응형

- 팝업 제목에 dialog semantics를 제공한다.
- 각 행은 `재화명, 지급량, 현재 보유량, 만료 안내` 순서로 읽힌다.
- 아이콘의 장식용 중복 읽기를 막고 행 전체에 의미 있는 semantics를 둔다.
- 확인 버튼은 locale별 번역과 충분한 터치 영역을 가진다.
- 작은 화면에서는 목록이 스크롤 가능하며 버튼은 접근 가능한 상태로 남는다.
- 큰 글꼴에서도 재화명과 지급량이 겹치지 않도록 행 내부를 유연하게 배치한다.
- 승인된 세 재화 PNG와 동일한 크기·그림자·배경 언어를 사용한다.

## 8. 오류 및 경계 조건

- 서버 확정 지급 항목이 없으면 성공 팝업을 표시하지 않는다.
- 대기, 거부, 실패 상태는 기존 오류 처리 흐름을 유지한다.
- 손상된 통화나 음수 지급량은 성공 UI로 전달하지 않고 기록 가능한
  변환 오류로 처리한다.
- 지갑 snapshot을 가져오지 못하면 앱이 잔액을 추정하지 않는다. 지급량은
  표시할 수 있지만 현재 보유량 영역은 번역된 중립 안내로 대체한다.
- 팝업 표시 실패가 서버 지급이나 acknowledge를 되돌리지 않는다.
- 동일 광고 grant 또는 동일 구매 지급 참조는 한 번만 표시한다.

## 9. 테스트

### 단위 및 위젯

- 코튼캔디 단일 항목
- 스타캔디 단일 항목
- 스타캔디와 보너스 스타캔디 동시 항목
- 지급량 0인 항목 제거
- 항목이 없는 영수증 거부
- 큰 숫자의 locale별 포맷
- 한국어, 영어와 fallback locale
- 코튼캔디 만료 안내와 비만료 재화의 안내 미표시
- 작은 화면과 큰 text scale에서 overflow 없음
- 스크린리더 semantics 순서

### 흐름 회귀

- 광고 `GRANTED` 이후 단 한 번 표시 및 첫 프레임 acknowledge
- 복구된 광고 보상의 중복 팝업 방지
- 구매 검증 완료 전 팝업 미표시
- 일반 구매의 스타캔디 단일 표시
- 프로모션 구매의 스타캔디와 보너스 스타캔디 동시 표시
- 구매 callback 중복에도 성공 팝업 한 번 표시
- 팝업과 지갑 패널이 동일한 적립 후 잔액 표시

## 10. 완료 기준

- 광고와 구매가 동일한 B 타입 영수증 컴포넌트를 사용한다.
- 코튼캔디, 스타캔디, 보너스 스타캔디가 승인된 아이콘으로 표시된다.
- 지급량이 양수인 재화만 표시된다.
- 모든 사용자 문구가 국제화되어 있다.
- 서버 확정값 외의 금액이나 잔액을 앱이 계산하지 않는다.
- 관련 단위, 위젯, 광고 복구, 구매 완료 회귀 테스트가 통과한다.
