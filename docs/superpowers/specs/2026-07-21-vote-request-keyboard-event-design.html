Task 39.4·39.5: 투표 신청 키보드 이벤트 대응 설계

대상: picnic_lib의 투표 신청 검색 UI와 개발 대응 문서
원칙: 재현되지 않은 Flutter 엔진 상태 오류를 앱 코드에서 임의로 가로채지 않는다.

1. 조사 결과

  • 투표 신청 코드에는 RawKeyboard, HardwareKeyboard, Backspace 직접 처리기가 없다.
  • Flutter의 해당 assertion은 KeyUp/Repeat 이벤트 시 physical key가 pressed 상태에 없을 때 발생한다.
  • 기존 기록에는 전체 오류, 스택, 플랫폼, Flutter revision, 재현 순서가 없어 앱 결함으로 재현할 수 없다.
  • 관련 검색·다이얼로그 테스트 41건은 현재 Flutter 3.41.4에서 통과했다.

2. 선택한 접근

항목설계
운영 코드변경하지 않는다. Raw key interception이나 pressed-key 상태 조작을 추가하지 않는다.
회귀 검증실제 투표 신청 다이얼로그에서 검색창을 활성화하고, 텍스트 입력 후 정상적인 paired Backspace 이벤트를 보내 focus 유지, 텍스트 삭제, 예외 부재를 확인한다.
문서오류 수집 항목, 즉시 복구 절차, 금지하는 임시 우회, 재발 시 Flutter 이슈로 분리할 판단 기준을 한글 HTML로 작성한다.
Task Master회귀 테스트와 문서가 검증되면 39.4와 39.5를 완료한다. 실제 RLS 작업인 39.6에는 영향을 주지 않는다.

3. 테스트 시나리오

  1. 가짜 서비스로 실제 VoteItemRequestDialog를 렌더링한다.
  2. 접힌 검색 영역을 눌러 TextField에 focus가 들어왔는지 확인한다.
  3. ab를 입력하고 LogicalKeyboardKey.backspace의 정상 down/up 이벤트를 보낸다.
  4. 텍스트가 a가 되고 focus가 유지되며 tester.takeException()이 null인지 확인한다.

4. 하지 않는 것

  • KeyUp만 보내 assertion을 인위적으로 만드는 테스트
  • Flutter 내부 pressed-key 상태 초기화
  • Backspace를 다른 삭제 동작으로 대체
  • Flutter SDK 업데이트나 실제 DB 접근

5. 재발 시 필요한 증거

전체 assertion과 stack trace, OS·기기, Flutter revision, debug/profile/release 모드, hot reload/restart 여부, 창 focus 이동 여부, 정확한 키 입력 순서와 완전 재시작 후 재현 여부를 수집한다. 정상 앱 실행에서도 재현되면 최소 재현 프로젝트와 함께 Flutter upstream 문제로 분리한다.

6. 완료 조건

  • paired Backspace 회귀 테스트가 통과한다.
  • 기존 투표 신청 검색·다이얼로그 테스트가 통과한다.
  • 대응 문서가 실제 명령과 수집 항목을 포함한다.
  • 운영 앱 코드와 DB/RLS는 변경되지 않는다.
