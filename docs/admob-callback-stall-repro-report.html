5. "멈춤" 발생 여부

발생하지 않았다. 로딩 오버레이(OverlayLoadingProgress)와 버튼 애니메이션 모두 stopAllAnimations() 로 정상 해제됐고, 안내 다이얼로그(닫기 가능)가 뜬 뒤 화면은 정상 조작 가능한 상태로 복귀했다. 사용자가 갇히는 지점은 없었다.

6. 해석 — 왜 재현이 안 됐는가

서버(check-ads-count)가 admob 플랫폼을 이미 차단 중이라는 사실은, AdMob 이 UI 에서 제거된 커밋(6fecae2fe, "무료 충전소 AdMob 글로벌 구좌 제거")과 시점·의도가 맞아떨어진다. 즉 클라이언트 UI 제거 + 서버 disabled 플래그가 세트로 걸린 상태로 보인다 — 이 조사에서 클라이언트만 되살렸을 뿐 서버 쪽 차단은 그대로이므로, 정작 재현하려던 "SDK 콜백 미수신" 코드 경로(RewardedAd.load 이후)에는 애초에 진입할 수 없었다.

바꿔 말하면: 이번 조사는 "현재 프로덕션 상태에서 사용자가 이 버그를 만날 수 있는가"에는 답을 줬다 — 못 만난다. 서버가 막고 있기 때문이다. 반면 "AdMob SDK 콜백이 실제로 유실될 수 있는가"라는 원래 가설은 이번 시도로는 확인도 반증도 되지 않았다.

7. 남은 선택지 (진행 안 함 — 결정 필요)

서버 disabled 게이트를 넘어 실제 RewardedAd.load() 콜백까지 시도하려면 다음 중 하나가 필요하다. 코디네이터에게 두 차례 질의(각 10분 타임아웃 무응답)했으나 응답을 받지 못해, 추가 시도 없이 이 결론으로 보고서를 마감한다.

  • 클라이언트에서 checkAdsLimit 의 disabled 분기만 조사용으로 우회 — 실제 광고가 뜨고 실제 보상 클레임이 발생할 수 있음(PROD).
  • 서버(check-ads-count 설정)에서 admob 의 disabled 플래그를 임시 해제 — 별도 인프라/설정 변경 승인 필요, 이 작업 범위 밖.
