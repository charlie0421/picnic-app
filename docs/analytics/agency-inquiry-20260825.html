2026-08-25 · Picnic 개발팀
회신하신 B-10(“중복 적재 확인 뒤 이벤트명 결정”) 조건을 충족하기 위한 실측 결과입니다.

먼저 결론부터
  1. ad_click 은 Google 이 앱에 허용하지 않는 예약 이벤트명입니다. 구현은 정상 동작하나 SDK 가 전송을 거부해 28일간 0건입니다. 이벤트명 변경 승인을 요청드립니다.
  2. B-10 에서 우려하신 자동 수집 중복이 실재합니다. 다만 영향이 큰 쪽은 ad_impression 이 아니라 purchase 매출이었고, 저희 쪽 GA4 설정으로 이미 차단했습니다.

2. ad_click — 이벤트명 변경 요청 (B-5 관련)

B-5 에서 “자체 숏폼 전체화면 CTA 클릭 시점”으로 트리거를 확정해 주셨고, 그대로 구현했습니다. 트리거 정의에는 이견이 없습니다. 문제는 이벤트명입니다.

28일간 ad_click 0건. 같은 화면에서 발생하는 ad_impression 은 같은 기간 102,405건 정상 수집됩니다.

원인 — 구현 결함이 아닙니다

실기기에서 CTA 버튼을 눌러 광고주 랜딩으로 이동하는 전 과정을 로그로 확인했습니다. 버튼 클릭 · 외부 브라우저 이동 · 파라미터 구성까지 모두 정상이고, 마지막 전송 단계에서 Firebase SDK 가 이름을 거부합니다.

  at _logEventNameValidation (firebase_analytics.dart:1346)

보시다시피 파라미터는 스펙대로 완전히 채워진 상태입니다. 이름만 거부됩니다.

Google 공식 문서의 앱 예약 이벤트명 목록에 ad_click 이 포함되어 있습니다 (ad_activeview, ad_click, ad_exposure, ad_query, ad_reward, first_open, session_start 등). 반면 ad_impression 은 예약어가 아니어서 정상 수집됩니다 — 같은 코드 경로에서 하나만 0건인 이유가 이것입니다.

우회 방법이 없습니다

“앱에서 다른 이름으로 보내고 GA4 에서 ad_click 으로 되돌리는” 방식을 검토했으나, GA4 이벤트 수정 공식 문서가 “새 이름이 예약어가 아닌지 확인하라” 고 명시하고 있어 불가합니다. 이름 변경 외에 방법이 없습니다.

어느 안이든 파라미터 구성과 트리거 시점은 현행 그대로 유지됩니다. 변경 대상은 이벤트명 하나뿐입니다.

참고: 이름이 확정되어야 앱 배포가 가능하고, 배포 전까지는 이 이벤트가 계속 0건입니다. 소급 수집은 불가능하므로 확정 시점 이후 데이터만 쌓입니다.

조치 완료: GA4 이벤트 수정 기능으로 자동 수집 in_app_purchase 를 매출 이벤트가 아닌 이름으로 변경해, 총 매출에 합산되지 않도록 했습니다. 앱 배포 없이 적용됩니다.

과거 데이터는 보정되지 않습니다. GA4 설정 변경은 소급 적용되지 않으므로 2026-08-13 ~ 08-25 구간의 매출 리포트에는 과대 계상이 그대로 남아 있습니다. 해당 구간을 정확히 보시려면 purchase 이벤트만 필터링한 리포트가 필요합니다. 필요하시면 저희가 탐색 분석을 만들어 공유드리겠습니다.

4. 회신을 요청드리는 사항

  1. 이벤트명 결정 — ad_cta_click / shortform_ad_click / select_promotion 중 택일, 또는 다른 안 제시. (가장 시급)
  2. ad_impression 처리 방향 — 자동 수집 추정분 1.1% 를 현행 유지할지, purchase 와 동일하게 분리할지
  3. 과거 매출 리포트 — 8/13~8/25 구간을 보정한 별도 리포트가 필요하신지
