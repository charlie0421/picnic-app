ad_click 이벤트명 변경 요청

ad_click은 Google이 앱에 허용하지 않는 예약 이벤트명입니다. 구현은 정상 동작하나 SDK가 전송을 거부해 28일간 0건입니다. 이름 변경 외에 방법이 없어 승인을 요청드립니다.

B-5 회신에서 확정해 주신 트리거 시점과 파라미터 구성은 그대로 유지됩니다. 변경 대상은 이벤트명 하나뿐입니다.

구현 결함이 아닙니다

실기기(Samsung SM-G781N, 프로덕션과 동일 빌드)에서 CTA 버튼을 눌러 광고주 랜딩으로 이동하는 전 과정을 로그로 확인했습니다. 버튼 클릭 · 외부 브라우저 이동 · 파라미터 구성까지 모두 정상이고, 마지막 전송 단계에서 Firebase SDK가 이름을 거부합니다.

파라미터는 스펙대로 완전히 채워진 상태입니다. 이름만 거부됩니다.

왜 ad_impression은 되는가

Google 공식 문서의 앱 예약 이벤트명 목록에 ad_click이 포함되어 있습니다 (ad_activeview, ad_click, ad_exposure, ad_query, ad_reward, first_open, session_start 등). ad_impression은 예약어가 아니라 앱 스트림에서 사용 가능한 이벤트입니다. 같은 코드 경로에서 하나만 0건인 이유가 이것입니다.

GA4에서 되돌리는 우회도 불가

“앱에서 다른 이름으로 보내고 GA4 이벤트 수정으로 ad_click으로 되돌리는” 방식을 검토했으나, 해당 기능의 공식 문서가 “새 이름이 예약어가 아닌지 확인하라”고 명시하고 있어 사용할 수 없습니다.

회신 요청

위 3안 중 택일, 또는 다른 안을 제시해 주세요. 어느 안이든 파라미터 구성과 트리거 시점(전체화면 CTA 클릭)은 현행 그대로 유지되며, 앱은 이벤트명만 교체해 배포합니다.

이름이 확정되어야 배포가 가능하고, 배포 전까지 이 이벤트는 계속 0건입니다. 소급 수집은 불가능하므로 확정 시점 이후 데이터만 쌓입니다.
