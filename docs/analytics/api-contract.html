3. 이벤트 메서드 10종

모든 String 파라미터는 nullable + required 명명 인자다. 값이 없으면(null/공백) 스펙 §2 규칙대로 'undefined' 로 대체되고 파라미터 자체는 남는다. 100자 초과 시 잘린다.

모든 Number 파라미터는 num? 이다. null 이면 파라미터를 생략한다(문자열 'undefined' 를 넣지 않는다). 근거는 §5 참조.

5. 확정된 설계 결정

#결정근거
1 파라미터 값은 스프레드시트 한글 예시값 그대로 ('별사탕', '광고에서 별사탕 받기', '글로벌 픽 #1', '광고 리워드') 영문 슬러그로 정규화하면 스펙과 수집값이 갈라져 대행사 검수가 불가능해진다. Ga4Parameters.stringValue 는 절대 값을 변환하지 않는다(길이 자르기 제외).
2 user_id 는 Supabase auth UUID 원본, 해시 없음 UUID 는 PII 가 아니고, 해시하면 BigQuery↔Supabase 조인과 기존 GA4 user_id 히스토리가 끊긴다. docs §1 및 코드 주석에 기록.
3 ad_impression 은 스펙대로 커스텀 logEvent AdMob↔Firebase 연동 시 SDK 자동수집과 중복될 수 있음. Ga4Event.adImpression / logAdImpression 주석에 경고 기록.
4a String 파라미터: 값 없으면 'undefined', 파라미터는 유지 스프레드시트 §2 규칙 그대로.
4b Number 파라미터: 값 없으면 파라미터 생략 + 경고 로그 GA4 는 커스텀 파라미터 키를 처음 관측된 타입에 따라 측정기준(text) 또는 측정항목(number) 중 하나로만 등록한다. reward_amount 에 숫자와 문자열 'undefined' 를 섞으면 등록된 타입과 다른 쪽 값이 리포트에서 통째로 누락된다 — 누락을 표시하려다 정상 값까지 잃는 교환. docs §4-6 에 대행사 확인 항목으로 기록.

6. login / sign_up 발송 규칙

발송 지점: AppInitializer.setupSupabaseAuthListener (AuthChangeEvent.signedIn). 소셜 로그인 3종이 모두 수렴하는 유일한 "통신 시점"이다. T3/T4 는 login/sign_up 을 직접 호출하지 않는다.

문제방어 수단
앱 재시작 시 세션 복원으로 signedIn 재발화 → login 중복 userId|last_sign_in_at 서명을 LocalStorage 에 영속 저장. 서명이 같으면 발송하지 않는다. 실제 재로그인은 last_sign_in_at 이 갱신되므로 서명이 바뀌어 정상 발송된다.
매 로그인마다 sign_up 오발송 created_at 과 last_sign_in_at 의 차이가 30초 이내일 때만 신규 가입으로 판정 (AuthAnalyticsResolver.isFreshSignUp). 추가로 사용자별 1회 마커를 영속 저장한다. 시각 파싱 실패 시 false — 잘못된 sign_up 폭주보다 1건 누락이 피해가 작다.
로그아웃 후 재로그인이 중복으로 오인 signedOut 에서 AuthAnalyticsReporter.onSignedOut() 이 저장된 서명을 지운다.
method 값 불일치 실측 결과 AuthService.signInWithProvider 가 OAuthProvider.{google,apple,kakao} 로 signInWithIdToken 을 호출하므로 app_metadata.provider 는 스펙 예시값과 동일하다. 매핑 테이블 불필요. 알 수 없는 값은 'undefined'.
