GA4 이벤트 택소노미 구현 회신

Picnic App (모바일 앱, Flutter) · 2026-08-07
대상 문서: 이벤트 택소노미 스프레드시트 (1JfC-wGcm…B6p8)

개요

전달해 주신 택소노미 기준으로 앱 구현을 완료했습니다. 정의된 10개 이벤트 중 9개와 사용자 속성 3종을 적용했습니다.

구현 과정에서 문서의 정의와 실제 앱 상태가 다른 지점 13건을 확인했습니다. 그대로 적용하면 수집 데이터가 부정확해지는 항목들이라, 아래와 같이 처리하고 회신드립니다.

회신이 필요한 사항 3건 (A절)

  1. click_attendance 이벤트 제외 — 해당 기능이 앱에서 폐지되어 발생 자체가 불가합니다
  2. 가상 재화 명칭 변경 — 문서의 별사탕 은 현재 앱에 존재하지 않는 명칭입니다
  3. vote 이벤트 파라미터 3종 추가 승인

나머지 10건은 판단 근거와 함께 통지드리며(B절), 별도 회신 없이 진행 가능합니다. 문서 갱신에 필요한 최종 전송값 대조표는 C절, GA4 맞춤 측정기준 등록 목록은 D절에 있습니다.

A. 회신이 필요한 사항

A-1. click_attendance 이벤트 제외 요청

상황 — 문서에는 "출석체크 팝업에서 '출석하기' 버튼 클릭 시" 발생하는 click_attendance 가 정의되어 있으나, 출석 보상 기능이 제품에서 폐지되었고 앱 코드에 이미 반영되어 있습니다.

  • 출석 버튼(AttendanceIconButton)은 어느 화면에서도 참조되지 않는 상태입니다
  • 무료 충전소의 출석 탭도 제거되었습니다

즉 사용자가 도달할 수 있는 진입점이 없어 이 이벤트는 발생시킬 방법이 없습니다. 계측을 위해 폐지된 기능의 UI를 되살리는 것은 적절하지 않다고 판단해 구현하지 않았습니다.

요청

택소노미 문서에서 click_attendance 이벤트를 제외해 주시기 바랍니다. 관련 파라미터(virtual_currency_name, reward_amount)는 다른 이벤트에서 계속 사용되므로 유지됩니다.

A-2. 가상 재화 명칭 — 별사탕 → 실제 명칭

상황 — 문서는 virtual_currency_name 의 예시값을 전부 별사탕 / 보너스 별사탕 으로 정의하고 있습니다. 그러나 현재 앱의 지갑 화면이 실제로 표시하는 명칭은 다음 세 가지입니다.

실제 명칭획득 경로소비 경로
스타캔디인앱 구매투표
보너스 스타캔디구매 프로모션투표
코튼캔디광고 시청 · 미션투표

이것은 단순한 명칭 변경이 아닙니다

스타캔디와 코튼캔디는 서로 다른 재화로 공존합니다. 구매로 지급되는 것은 스타캔디이고, 광고 시청으로 지급되는 것은 코튼캔디입니다. 데이터 모델에도 star_candy_usage / star_candy_bonus_usage / cotton_candy_usage 세 필드가 별도로 존재합니다.

문서의 예시값대로 양쪽 모두 별사탕 으로 전송하면, GA4 에서 "광고로 획득한 재화"와 "구매한 재화"가 하나의 디멘션 값으로 합쳐져 재화별 분석이 불가능해집니다. 이에 실제 제품 명칭을 전송하도록 구현했습니다.

section_name 도 같은 이유로 조정되었습니다. 문서의 광고에서 별사탕 받기 는 앱 화면에 존재하지 않으며, 실제 화면 문구는 광고에서 코튼캔디 받기 입니다.

요청

문서의 virtual_currency_name 예시값을 스타캔디 / 보너스 스타캔디 / 코튼캔디 로, section_name 을 광고에서 코튼캔디 받기 로 갱신해 주시기 바랍니다. 리포트·대시보드에서 재화를 구분해 집계하실 수 있도록 확인 부탁드립니다.

A-3. vote 이벤트 파라미터 3종 추가 승인 요청

상황 — 문서는 vote 이벤트에 재화 이름(virtual_currency_name)과 수량(reward_amount) 을 각각 하나씩 정의하고 있습니다. 그러나 실제 투표는 한 번에 여러 재화가 동시에 소모됩니다.

예: 보너스 스타캔디 40개를 먼저 사용하고, 부족한 60개를 스타캔디로 채워 총 100개 투표

단일 값으로는 이 상황을 표현할 수 없어 다음과 같이 처리했습니다.

파라미터전송 방식
virtual_currency_name사용된 재화가 하나면 그 명칭, 복수면 + 로 결합 (예: 보너스 스타캔디+스타캔디). 순서는 고정 정규화되어 같은 조합이 항상 같은 값으로 전송됩니다
reward_amount총 사용량 (문서 정의 유지)
아래 3개를 추가로 전송합니다 (문서에 없는 항목)
star_candy_usage스타캔디 사용량 (Number, 미사용 시 파라미터 생략)
star_candy_bonus_usage보너스 스타캔디 사용량
cotton_candy_usage코튼캔디 사용량

결합 라벨만으로는 "이번 달 코튼캔디 총 소모량" 같은 기본적인 질문에 답할 수 없어 추가했습니다. 파라미터명은 DB 필드명과 일치시켜 BigQuery 조인이 용이하도록 했습니다.

기존 정의를 변경하지 않는 가산 항목이므로 기존 리포트에는 영향이 없습니다. 다만 문서에 없는 항목이라 승인을 요청드립니다.

요청

위 3개 파라미터 추가에 대한 승인, 그리고 문서 반영 여부를 회신해 주시기 바랍니다. 불필요하다고 판단하시면 제거하겠습니다.

B. 통지 사항

별도 회신 없이 아래와 같이 적용했습니다. 이견이 있으시면 알려 주십시오.

B-1. user_id — 해시 처리하지 않음

문서는 "로그인한 ID의 해시값"을 요구하나, 본 앱의 로그인 식별자는 무작위로 생성되는 UUID 로 개인 식별 정보가 아닙니다. 이메일·전화번호 등은 애초에 GA4 로 전송하지 않습니다.

해시를 적용할 경우 ⑴ 프라이버시 이득이 없고, ⑵ BigQuery export 와 내부 DB 간 조인이 끊겨 퍼널·리텐션 분석이 불가능해지며, ⑶ 이미 원본 UUID 로 수집 중이라 동일 사용자가 신규 사용자로 갈라져 기존 코호트가 단절됩니다. 이에 원본 값을 그대로 전송합니다.

B-2. currency 는 undefined 로 대체하지 않음 (중요)

문서의 "정보가 없는 경우 값을 undefined 로 대체" 규칙을 currency 에 적용하면, GA4 가 ISO 4217 위반 통화 코드로 판정해 해당 purchase 의 매출(value)을 집계에서 통째로 제외합니다.

따라서 currency 는 값이 없을 경우 undefined 대신 파라미터 자체를 생략하며, 짝이 되는 value 도 함께 생략합니다.

B-3. Number 타입 파라미터도 undefined 대체 제외

GA4 는 하나의 파라미터 키를 맞춤 측정기준(문자열) 또는 맞춤 측정항목(숫자) 중 한 가지 타입으로만 등록합니다. 숫자 파라미터에 undefined 문자열이 섞이면 반대 타입의 값이 리포트에서 누락됩니다.

대상: reward_amount, value, base_amount, bonus_amount, 그리고 A-3 의 사용량 3종. 값이 없으면 파라미터를 생략합니다. 문자열 파라미터는 문서 규칙대로 undefined 를 사용합니다.

B-4. 광고 플랫폼 값 — AdMob / Google Ads 아님

문서는 ad_platform: AdMob, ad_source: Google Ads, ad_unit_name: reward_global_pick_1 로 정의하고 있으나, 현재 무료 충전소에서 실제 운영 중인 광고 구좌는 다음 두 가지입니다.

구좌ad_platformad_sourcead_unit_name
자체 숏폼 광고internal-shortforminternalundefined (SDK 유닛 개념 없음)
PanglePanglePangleSDK 제공값

ad_format 은 문서대로 rewarded 입니다.

AdMob 리워드 광고는 현재 무료 충전소 UI 구좌에서 제외되어 있고, 서버 사이드 검증(SSV) 방식이라 클라이언트가 적립 성공을 관측할 수 없어 계측 대상에서 제외했습니다.

B-5. ad_click 트리거 — 리워드 광고가 아닌 자체 숏폼 CTA

문서는 "광고 종료 후 '더보기' 버튼을 눌러 이동했을 때"로 정의하고 있으며, 해당 UI 는 자체 숏폼 광고 전체화면의 CTA 버튼으로 실재합니다. destination_type 은 이동 목적지 유형(예: youtube)을 전송합니다.

B-6. 언어 코드 — ja → jp 변환 적용

앱 내부 언어 코드는 ISO 639-1 기준이라 일본어가 ja 입니다. 문서는 jp 로 정의하고 있어, GA4 전송 시점에만 ja → jp 로 변환합니다. 변환하지 않으면 일본어 사용자 세그먼트가 문서 기준과 어긋나 잡히지 않습니다.

B-7. 지원 언어가 문서 정의보다 많음

문서는 ko, en, jp 세 가지만 예시로 정의하고 있으나, 앱은 한국어·영어·일본어·인도네시아어·태국어·베트남어·중국어 등을 지원합니다. 정의되지 않은 코드는 변환 없이 원본(id, th, vi, zh 등)으로 전송됩니다. 리포트 세그먼트 구성 시 참고 부탁드립니다.

B-8. 사용자 속성 이름 불일치 — language 로 통일

"파라미터 리스트" 시트는 language, "공통 파라미터" 시트는 selected_language 로 동일 항목을 다르게 표기하고 있습니다. 사용자 속성(User)은 language, 이벤트 파라미터(Event)는 selected_language 로 정리해 적용했습니다.

B-9. sign_up 판별 기준

인증 서버가 "이번 로그인이 신규 가입인지"를 응답에 직접 제공하지 않습니다. 이에 계정 생성 시각과 최근 로그인 시각의 차이가 30초 이내면 신규 가입으로 판정하고, 사용자별 1회 발송 마커를 기기에 영속 저장해 재발송을 차단합니다.

세션 복원으로 로그인 이벤트가 재발화하는 경우에도 중복 전송되지 않도록 처리했습니다. 판별 기준에 대한 의견이 있으시면 알려 주십시오.

B-10. ad_impression 자동 수집과의 중복 가능성

ad_impression 은 Firebase↔AdMob 연동 시 SDK 가 자동 수집하는 이벤트명과 동일합니다. 문서 정의대로 커스텀 전송하도록 구현했으나, 연동 상태에 따라 중복 집계가 발생할 수 있습니다.

GA4 콘솔에서 자동 수집 활성화 여부를 확인해 주시고, 중복이 확인되면 이벤트명 분리 등 대응 방향을 알려 주시기 바랍니다.

earn_virtual_currency 는 GA4 표준이 virtual_currency_name + value 조합을 사용하나, 문서 정의에 따라 수량을 reward_amount 로 전송합니다. (문서 기준 유지)

D. GA4 맞춤 측정기준 / 측정항목 등록 목록

수집을 시작하기 전 GA4 콘솔에 등록이 필요한 항목입니다.

사용자 범위 (User)

파라미터범위유형
is_login사용자측정기준 (텍스트)
language사용자측정기준 (텍스트)

이벤트 범위 — 측정기준 (텍스트)

method, selected_language, virtual_currency_name, mission_category, section_name, ad_category, ad_platform, ad_source, ad_format, ad_unit_name, earn_method, destination_type, vote_id, vote_name, vote_reward, vote_start_date, vote_end_date, vote_artist_name, vote_artist_group

이벤트 범위 — 측정항목 (숫자)

reward_amount, star_candy_usage, star_candy_bonus_usage, cotton_candy_usage (뒤 3개는 A-3 승인 시)

상품 범위 (Item)

virtual_currency_name, base_amount, bonus_amount — items 배열의 커스텀 파라미터로 전송됩니다. item_id, item_name 은 GA4 표준 필드입니다.

transaction_id, currency, value 는 GA4 전자상거래 표준 파라미터이므로 별도 등록이 필요하지 않습니다.
