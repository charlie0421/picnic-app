결론

스프레드시트의 10개 이벤트 중 9개와 사용자 속성 3종을 구현했습니다. click_attendance 는 출석 보상이 제품에서 폐지되어 진입 UI가 없으므로 구현이 불가능합니다.

구현 과정에서 반대 공급자 모델의 적대적 리뷰를 4회 돌려, 배포됐다면 매출 데이터를 망가뜨렸을 결함 5건을 잡았습니다. 마지막 검증에서 리뷰어는 배포 가능 판정을 냈습니다.

출시 전 제품 결정이 필요한 항목 1건이 남아 있습니다 (아래 §5).

durable analytics outbox

이벤트 payload를 sink 호출 전에 analytics_ga4_outbox_v1에 영속 저장하고, sink가 성공을 반환한 항목만 제거합니다. 스토어 거래·위젯·프로세스 수명과 독립적으로 재시도합니다.

  • 재시도: enqueue 직후 / Firebase 초기화 직후 / 실패 30초 뒤. I/O 2초, sink 5초 timeout
  • 동시성: storage-key 전역 mutex로 read-modify-write 직렬화, 항목별 in-flight 예약을 첫 await 전에 확보
  • 용량: pending 200건·30일(purchase 365일), delivered 500건·180일. 초과·만료는 전부 로그로 노출

이벤트별 중복/누락 정책을 갈랐습니다. GA4는 transaction_id로 purchase만 중복 제거하므로, 그 근거를 다른 이벤트에 일괄 적용하면 지표가 부풀려집니다.

이벤트정책
purchaseat-least-once — GA4가 중복 흡수
earn_virtual_currency · login · sign_upsink true 후 delivery_confirmed checkpoint 저장 → cleanup 실패는 재전송하지 않음

3. 리뷰가 잡아낸 결함

구현 → 리뷰 → 수정 → 재검증을 4회 반복했습니다. 2·3차 재검증은 직전 수정이 새로 만든 blocker를 잡았습니다. 1회로 끝냈다면 "고쳤다"고 믿으면서 같은 병을 다른 자리에 심은 채 배포됐을 것입니다.

라운드발견내용

추가로 드러난 것

  • currency: 'undefined' 가 GA4 매출을 통째로 무시하게 만들고 있었습니다. 스펙의 "값이 없으면 undefined" 규칙을 currency에 적용한 결과인데, GA4는 ISO 4217 위반 통화면 value를 집계하지 않습니다.
  • AnalyticsService가 이미 FirebaseAnalytics.instance.logEvent('purchase')를 직접 호출하고 있었습니다. 발견하지 못했다면 purchase가 2번 나가 매출이 2배로 잡혔을 것입니다.

4. 대행사 회신 항목

스펙과 실제 제품/코드가 어긋나는 지점입니다. 상세는 docs/analytics/ga4-event-taxonomy.md §4.

#항목처리
1click_attendance 구현 불가 — 출석 보상 폐지로 진입 UI 전량 제거이벤트 제외 요청
2user_id 해싱 불필요 — Supabase UUID는 PII가 아니고, 해싱하면 BigQuery↔DB 조인과 기존 히스토리가 끊김raw UUID 유지 통지
3user property 이름 불일치 — 시트마다 language / selected_languagelanguage로 통일
4ad_impression — AdMob↔Firebase 연동 시 GA4가 동일 이름을 자동 수집GA4 콘솔 중복 확인 요청
5earn_virtual_currency 비표준 — GA4 표준은 value, 스펙은 reward_amount스펙대로 구현
6Number 파라미터에 undefined 문자열을 넣으면 GA4가 키를 한 타입으로만 등록해 반대 타입이 통째로 누락Number는 값 없으면 파라미터 생략
7sign_up 판별 — Supabase가 신규 가입 여부를 주지 않아 created_at ≈ last_sign_in_at 30초 창으로 판정판별 기준 확인 요청
8currency는 undefined 대체 불가 (ISO 4217 위반 시 매출 무시)값 없으면 currency·value 동시 생략
9재화 이름 — 스펙은 별사탕이나 앱 지갑 UI 실제 표시는 스타캔디/보너스 스타캔디/코튼캔디. 스타캔디와 코튼캔디는 별개로 공존하는 재화라 스펙대로 보내면 둘이 한 값으로 합쳐짐제품 실제값 사용 통지
10vote 가산 파라미터 — 한 번의 투표에 여러 재화가 섞여 쓰이므로 star_candy_usage/star_candy_bonus_usage/cotton_candy_usage를 추가 (DB 필드명과 일치)승인 요청
11언어 코드 — 앱은 ja, 스펙은 jpanalytics 경계에서 ja→jp 정규화 적용

5. 출시 전 제품 결정이 필요한 항목

카탈로그 미적재 복구 구매의 매출 누락

정산 확정 시점에 스토어 상품 카탈로그가 메모리에 없으면 currency/value 없이 purchase를 확정합니다. 숫자를 지어내지 않고 거래 사실부터 durable하게 남기는 선택입니다.

결과: purchase 건수는 남지만 그 건의 매출액은 복원되지 않습니다. 수용 여부를 정해야 합니다.

그 외 문서화된 한계 5건은 docs/analytics/ga4-event-taxonomy.md §7에 있습니다 — non-purchase 이벤트의 좁은 중복 창, outbox 용량/만료, captured auth context의 귀속 경쟁, SharedPreferences 최초 실패의 고착, ad_impression 자동수집 중복.
