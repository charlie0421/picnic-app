운영상 함의. ads.internal_reward_mode를 bonus로 되돌려도 더보기 적립은 복구되지 않는다. 차단 지점이 모드 분기보다 앞에 있기 때문이다. 롤백으로 해결 가능한 사안이 아니다.

연혁 — 언제, 왜 이렇게 됐나

"나중에 제거했다"가 아니라 처음부터 넣지 않은 것이다. onMore() 가 호출된 이력은 저장소 전체에 한 건도 없다.

시점커밋무슨 일이 있었나
2025-10-16f15740d44 자체 숏폼 기능 전체가 이 단일 커밋으로 신규 추가됐다(--diff-filter=A 확인). 처음부터 onMore 는 배선되지 않았고, 코드가 이유를 말한다 — // 기본 보상만 보장 (More 보상 제거), 이후 URL 오픈
2025-10-17d44e6a34f 하루 뒤 _startReward() 신설로 재생 완료 시 자동 적립으로 전환. 더보기 핸들러의 수동 가드는 중복이 되어 제거됐다 — 당시 버튼이 enabled = finished 였으므로 타당했다
2026-07-254e79a32eb CTA 활성 조건을 finished → visible(잔여 5초)로 완화. "누를 수 있으면 이미 끝났다"는 전제가 깨졌는데 수동 가드는 복구되지 않았다 → 원인 B

최초 구현의 의도는 명확했다. 당시엔 자동 적립이 없어(// 재생 완료 시 자동 적립 호출 제거 (닫기/More 시점에서만 적립)) 더보기를 누르면 외부 브라우저로 나가며 화면이 닫혔다. 그 구조에서 More 보상까지 챙기려다 기본 시청 적립을 놓치는 위험을 감수하느니, More 를 포기하고 기본 적립을 확실히 보장하겠다는 트레이드오프였다.

// f15740d44 (2025-10-16) - 최초 구현
final bool enabled = finished;              // 영상 종료 후에만 활성
onPressed: () async {
  // 기본 보상만 보장 (More 보상 제거), 이후 URL 오픈
  if (!_viewReported) {
    _viewReported = true;
    debugPrint('[internal] ensuring view reward before more');
    await widget.onViewComplete();          // ← 시청 적립을 먼저 확정
  }
  await _openCta(cta);                      // ← 그 다음 외부 브라우저
  if (mounted) Navigator.of(context).maybePop();
  // widget.onMore()는 호출하지 않음 (More 보상 제거)
}

서버의 409 는 별개 결정이다. callback-ad-shortform-more 는 이 저장소에 커밋된 적이 없어 시점·PR 을 특정할 수 없고, 코튼캔디 지갑 마이그레이션 계열(_shared/wallet/*)인 것만 확실하다. 판단 근거는 함수 주석이 전부이며, docs/superpowers/ 의 지갑 플랜 문서에도 기록이 없다(SQL·정산은 picnic-supabase 소관).

사용자는 브라우저에서 돌아와 남은 재생을 마치면 적립이 정상 처리되고, 그 사이 X 버튼은 항상 눌린다.

근본 원인은 분류기에 하드코딩한 일반 라벨을 먹인 것이었다. isNonReportableAdError() 는 전적으로 message 문자열로 판정하는데, 예외를 잡는 경로가 'Pangle 광고 로드 실패' 라는 라벨을 넘겼고 그 안의 '광고 로드 실패' 가 no-fill 키워드였다. 결과적으로 SDK 초기화 실패·설정 오류·네트워크 예외까지 전부 "모든 광고 소진"으로 표시되고 Sentry 보고가 막혔다.

사용자 눈에 보이는 변화. 지금까지 "모든 광고가 소진되었습니다"로 보이던 경우 중 실제 오류였던 건은 이제 일반 오류 다이얼로그(label_ads_load_fail)로 바뀐다. 새 문구를 추가하지 않았고, 진짜 재고 없음은 그대로 "소진"으로 안내된다.
