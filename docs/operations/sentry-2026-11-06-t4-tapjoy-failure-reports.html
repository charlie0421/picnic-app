소스 수정·호스트 검증·독립 리뷰 완료. 무료충전소 테스트 폴더 514개가 통과했다. 독립 리뷰(Codex gpt-6.1-sol/high)는 두 번 CHANGES_REQUIRED였다. 지적 3건 중 2건은 수정했고, 1건은 근거를 제시해 리뷰어가 철회했다. 두 번째 재검증 결과는 APPROVE다. 실제 기기·실제 Tapjoy SDK·실제 네트워크 장애는 검증하지 않았다.

1. Tapjoy 문제와 원인

  • Tapjoy 실패는 SDK 원문 문자열을 그대로 Sentry에 보냈다. 원문에는 단계·종류·재시도 정보가 없고, 내용을 앱이 통제하지 못한다.
  • 플러그인 tapjoy_offerwall 14.6.0은 실패 콜백에 메시지 문자열만 넘긴다. Android는 TJError.message, iOS는 localizedDescription을 넘긴다. SDK 오류 코드는 버려지므로 보고할 수 없다.
  • Sentry MCP 집계(릴리스 1.3.5+130504):
    • 5KT: 22건, 전부 Android, 오퍼 요청 단계. 본문은 Tapjoy 서버 응답이다. {"code":500,...} JSON, HTML 페이지, {"error":"Internal error occured."}, 빈 문자열이 섞여 있다. 즉 대부분 Tapjoy 서버 측 실패다.
    • 5KN: iOS The network connection was lost. — 기기 측 네트워크 끊김.
    • 5KA: 앱 자체의 setUserID 10초 대기 시간 초과 문구.
    • 참고: SDK not connected -- connect must be called first...(PICNIC-APP-43N, 1건)도 같은 원문 보고 경로다.

2. 변경 결과

경계변경 결과
보고 형식새 tapjoy_failure.dart의 TapjoyFailure로 닫힌 값만 보낸다. 단계(setUserId·placementRequest·placementCreate), 종류(noUser·busy·otherAccountPending·timeout·sdkFailure·channelFailure·missingPlacement), SDK 메시지 유무, 원인, 서버 코드, 채널 코드, 재시도 여부, 망 종류.
원인 (리뷰 반영)SDK 원문에서 앱 안에서만 원인을 계산한다: network(연결 끊김·오프라인·시간 초과 등), server(JSON·HTML 본문, internal error), sdkNotReady(SDK 미연결), unknown, none. 원문은 보내지 않는다. Tapjoy 서버 JSON의 "code"가 100–599이면 3자리 숫자만 tapjoy_server_code로 남긴다.
오프라인·설정 오류·10초 지연 구분오프라인 → sdkFailure/network(재시도 yes), 설정 오류 → sdkFailure/sdkNotReady 또는 channelFailure(채널 코드), 10초 지연 → timeout/none(재시도 yes). fingerprint는 ['tapjoy-failure', stage, kind, cause]다.
다이얼로그·보고 제외기존 다이얼로그와 no-fill 키워드 제외 판단을 그대로 쓴다. AdPlatform에 원문 Sentry 보고 없이 같은 판단만 하는 showAdLoadFailureDialog를 추가했다. 다른 플랫폼은 바뀌지 않는다.
앱 공통 필터 (리뷰 반영)예전 원문 보고는 앱 공통 beforeSend의 String 필터를 거쳤다. 거기서 버려지던 전송 계층 문구(Failed host lookup, Connection reset 등)는 지금도 보내지 않는다. 판단 입력은 예전 코드가 보고하던 값과 같다. setUserID 단계는 채널 예외도 reason 문자열을 쓴다.
PICNIC-2682 소유권setUserID 소유권·타임아웃·계정 전환·연타 로직은 그대로다. settle이 종류와 오류 객체를 함께 기록하도록만 바꿨다.
지급·기기 차단변경 없음.

새 fingerprint를 쓰므로 배포 뒤 5KT·5KN·5KA에는 새 이벤트가 쌓이지 않는다. T9에서 새 이슈와 함께 비교한다. 사용자 id는 앱 전체 Sentry 사용자 바인딩(PICNIC-2743)에 따라 이전과 같이 붙는다. 이번 변경 범위가 아니다.
