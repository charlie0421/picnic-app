T7 · 업데이트 화면 스토어 열기 실패 (PICNIC-APP-45D · 4ED)

2026-11-06 · 기준 커밋 db9ad3f9c · 수정 커밋 b19e5aec7, f459c0b0b · 작업 브랜치 docs/sentry-release-analysis

소스 수정·호스트 검증·독립 리뷰 완료. 업데이트 화면·업데이트 공급자 테스트 239개가 통과했다. 독립 리뷰(Codex gpt-6.1-sol/high)는 APPROVE이며 비차단 P3 1건을 지적했다. 수정 후 재검증도 APPROVE다. 실제 iOS 27 기기·실제 스토어 열기·실제 Sentry 전송은 검증하지 않았다.

1. 원인

  • 45D String: 앱 스토어를 열 수 없습니다. 누적 131건·24명. 최근 이벤트는 1.3.2–1.3.4 등 현재 코드와 같은 릴리스에서도 발생한다. OS 는 전부 iOS(iOS 27.0.1 14건, 27.0 9건, 26.6.1 1건).
  • 예전 코드는 canLaunchUrlString이 false 이면 안내 문구를 String 으로 던졌다. 강제 업데이트 화면은 떠날 수 없는 화면인데, 버튼이 아무 반응 없이 끝났고 던진 문자열이 Sentry 오류가 됐다.
  • 운영 version 행의 스토어 URL 은 iOS·Android 모두 정상 https 형식이다. iOS 27 에서 canLaunchUrlString이 false 를 준 이유는 확인하지 못했다. 이번 수정은 그 이유에 의존하지 않는다.
  • 4ED(SafariViewController PlatformException)는 이전 수정 #27(externalApplication)으로 해결됐고, 남은 이벤트는 1.2.x 바이너리뿐이다. 추가 변경 없음.

2. 변경 결과

경계변경 결과
스토어 열기새 StoreLauncher.open이 사전 확인 없이 launchUrlString(externalApplication)을 바로 호출한다. 결과는 opened·emptyUrl·refused·failed(PlatformException) 중 하나다. 그 밖의 예외는 결함으로 보고 다시 던진다.
강제 업데이트 화면실패하면 기존 다국어 문구 update_cannot_open_appstore를 버튼 아래에 보이고 버튼은 남겨 다시 시도할 수 있다. 나중 시도가 성공하면 문구를 숨긴다. 늦게 끝난 이전 시도는 더 새 시도의 결과를 덮지 않는다(리뷰 P3 반영).
권장 업데이트 배너실패해도 앱 사용을 막지 않으므로 보고만 한다. 더 이상 던지지 않는다.
Sentrystore_launch_failed warning. 태그 store_launch_result, store_launch_surface(force_update·update_recommend), fingerprint ['store-launch-failed', surface, result]. URL 은 넣지 않는다. 새 fingerprint 이므로 배포 뒤 45D 대신 새 이슈로 쌓인다. T9 에서 함께 비교한다.
정책force_version과 강제 업데이트 진입 조건은 바꾸지 않았다. 웹·인앱 브라우저 폴백은 추가하지 않았다. iOS platformDefault가 4ED 를 만든 경로이고, 고정된 url_launcher_ios 의 externalApplication 은 universalLinksOnly=false 로 외부 브라우저도 허용한다(리뷰 확인).
