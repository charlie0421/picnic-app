INFO 6. policy: fit + BoxFit.cover 의 잠재 trade-off

위치
picnic_image_request.dart:62-68
내용
fit(contain) 은 cover 로 렌더할 때 필요한 배율(max)이 아니라 min 배율로 디코드한다. CDN URL에서는 요청 박스와 디코드 박스가 같은 값이고 CDN이 비율 유지로 이미 축소해 보내므로(common_banner.dart:244-253 의 프로덕션 실측 기록) allowUpscaling: false 가 걸려 결과가 HEAD와 동일하다 — 회귀가 아니다. 차이가 생기는 경우는 CDN이 리사이즈하지 않는 외부 절대 URL + 박스와 다른 원본 비율 + cover 뿐이고, 현재 범위에서 유일한 외부 URL 호출부는 정사각 아바타라 fit == cover 로 무해하다. 향후 외부 URL을 비정사각 cover 박스에 쓰는 호출부가 생기면 이 지점을 다시 봐야 한다.

  • 콜드 지연과 타임아웃 개시 시점. _startAttemptWhenAllowed 가 containsKey == false && recommendDeferredLoadingForContext 일 때 _loading 과 타임아웃 무장을 모두 미룬다(:885-894). scheduleFrameCallback 이 프레임을 직접 요청하므로 스크롤이 멎으면 반드시 재평가된다. 지연 중 요청 0건·해제 후 타임아웃 발화를 테스트가 단정한다(decode_test:407-415).

지적 #1 해소 근거

  • 디코드가 표시 해상도로 복원됐다. vote_home_reward_image_test.dart 는 mock Supabase 픽스처로 실제 VoteHomePage 를 띄우고 프로덕션 키 ValueKey('reward_901') 하위의 RawImage.image 를 직접 읽어 decoded.width == expected.decodeWidth 와 함께 expect(decoded.width, greaterThan(120 * 1.8)) 즉 > 216 을 단정한다. 수정 전 값(120, 정사각 원본이면 100)은 이 하한에서 즉시 실패하므로 회귀 가드로 유효하다. DPR 2·3 양쪽에서 돈다(2 → 288, 3 → 300).
  • 상대경로 아바타도 동일하게 복원됐다. avatar_container_test.dart:218-300 이 실제 ProfileImageContainer(48pt, 상대경로)를 DPR 2·3에서 렌더해 decoded.width == expected.decodeWidth 와 greaterThan(48 * 1.8) 즉 > 86.4 를 단정한다(DPR 2 → 115, DPR 3 → 120). 수정 전 48은 실패한다. 코디네이터가 제시한 red 로그의 "actual 48 vs 115" 와 일치한다.
  • 대역폭 낭비도 함께 사라졌다 — 이것이 지적 #1의 후반부였다. 두 호출부가 자동 경로로 옮겨졌고, 자동 경로에서는 요청 픽셀과 디코드 픽셀이 같은 값이다: picnic_image_decode_test.dart:203-208 이 DPR 1/2/3에서 resize.width == query['w'], resize.height == query['h'] 를 단정한다. 더 이상 w=300&h=250 을 받아 120×100으로 잘라내지 않는다.
  • 비율 보존이 실제 픽셀로 확인됐다. 리워드는 600×500 픽스처에 decoded.width / decoded.height closeTo(1.2, .02)(6:5 박스와 일치), 서명 HTTP 아바타는 400×200 픽스처에 closeTo(2, 0.02). policy: ResizeImagePolicy.fit 이 왜곡 없이 동작함을 픽셀로 재확인한다.
  • 중복 요청·중복 resolve 없음. 두 테스트 모두 harness.requestsFor(url) == 1, 서명 아바타 테스트는 추가로 displayed.image.obtainKey(config) == expected.obtainKey(config) 와 network.url == network.cacheKey == signedUrl(%2B 이스케이프 포함)를 단정한다.
  • 요구사항 조항 충족. "Shared image resolver auto-bounds remaining reward/media constrained callsites" 가 리워드 행에서 이제 충족된다. "explicit … keep existing PHYSICAL semantics (do not multiply explicit 78px again)" 도 계약과 78px 테스트가 그대로여서 동시에 성립한다 — 두 조항의 충돌이 호출부 쪽에서 해소됐다.
  • 요청 상한이 느슨해지지 않았다. 두 호출부 모두 width/height 를 계속 명시하므로 _resolveRequestForLayout 이 양축 요청을 유지하고(picnic_cached_network_image.dart:682-688) CDN 요청은 여전히 논리치수 × multiplier 로 묶인다. 외부 HTTP 아바타는 URL이 원문 유지돼 w/h 가 없지만 디코드는 _decodeSize 자동 경로(2000px/2MP 상한)로 묶인다 — 무제한 다운로드도, 무제한 디코드도 생기지 않는다.
