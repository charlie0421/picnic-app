AdMob 적립 추적·리워드 이미지 콜드 리사이즈 수정 결과

작성일 2026-09-14 · 저장소 charlie0421/picnic-app · 브랜치 fix/admob-claim-tracking-reward-images · 기준 1.3.4+130401 TestFlight 보고

TestFlight 1.3.4+130401 에서 보고된 두 문제 — 글로벌픽 #1(AdMob) 적립 안 됨, 리워드 상세 이미지 지연 — 를 조사했다. 둘 다 130401 의 코드 변경이 만든 회귀는 아니었다. AdMob 은 앱이 클레임 참조를 버려 정상 적립조차 화면에 반영되지 않는 설계 공백이 있었고, 리워드 이미지는 CDN 리사이저의 콜드 경로(5~10초)가 PR #219 의 렌더 크기 기반 사이즈 산출과 맞물려 기기별로 콜드 리사이즈를 맞는 구조였다. 수정은 이 문서의 3절, 원격으로 확정하지 못한 부분은 5절에 남겼다.

1. AdMob 적립 — 조사 결과

  • 24시간 콜백의 ad_network 는 전부 AdMob 네트워크(5450213213286189855). Meta·Pangle·Liftoff 미디에이션 소스는 0건. 미디에이션 채움이 SSV 없이 끝나 PENDING 이 되는지는 기기에서만 가릴 수 있다.
  • 7일 기준 클레임 PENDING 비율 iOS 3.9%(3,325/85,600) · Android 1.4%. 클레임 생성→콜백 지연 p10 6초 / p50 19~21초 / p90 61~66초.
  • 확정된 앱 설계 공백: Pangle 은 클레임을 pending store 에 저장하고 상태를 폴링해 적립 영수증을 띄우고 ack 하지만, AdMob 은 그 경로가 없었다(admob_platform.dart 는 보상 콜백에서 프로필 새로고침만). 광고 닫힘 직후 새로고침은 대개 적립(SSV)보다 먼저 실행되므로 정상 적립도 "안 들어옴"으로 보였다. 서버 get_ad_reward_status 는 이미 ADMOB_CLAIM 을 지원한다.
  • AdMob 관련 앱 코드는 130308 → 130401 사이 변경이 없다(diff 0). 앱 로그는 Sentry 로 가지 않아 기기 측 원인(로드·표시 실패, 조기 닫힘, 미디에이션 채움)을 원격으로 가릴 수 없었다.

2. 리워드 이미지 — 조사 결과

리워드 이미지(원본 1000×1000 PNG, 1.7MB)를 앱이 요청하는 방식대로 CDN 에서 받은 실측:

요청응답시간
/picnic/reward/<key>.png (원본)200, 1.7MB0.18초
?q=80&w=733&h=733 첫 요청302 → /cache/picnic/reward/<key>_w733_h733_fpng_q80.png4.9~7.1초
?q=80&w=1083&h=983 첫 요청302 → cache7.6~10.0초
같은 조합 재요청302 → cache (CloudFront hit)0.03~0.08초
14KB 이미지 새 조합302 → cache0.5~0.8초
  • 리사이저는 (w,h,q) 조합마다 별도 캐시 객체를 만들고 새 조합의 첫 요청은 원본 크기에 비례해 느리다.
  • PR #219(1.3.3+130301 이후 탑재)가 w/h 산출을 "위젯 인자"에서 "실제 렌더 크기"로 바꿔 리워드 상단 이미지 키가 달라졌다(iPhone 3x: w=1083 → w=983, 사이즈가이드: q만 → w/h 추가). 기존 캐시 변형이 전부 미스가 되어 기기 폭별 첫 사용자가 5~10초 콜드 리사이즈를 맞는다. Android 도 같은 구조.

3. 수정 내용

파일변경

picnic_lib/lib/presentation/providers/ad_reward_recovery_provider.dart 포그라운드 폴링 사다리에 30초 단계를 추가(총 30초 → 60초)해 AdMob SSV p90 을 덮는다.
picnic_lib/lib/presentation/dialogs/reward_dialog.dart 모든 리워드 이미지가 기기와 무관한 고정 변형 ?q=80&w=1000 하나만 요청한다(RewardDialogConstants.imageRequestWidth, rewardImageRequest → PicnicCachedNetworkImage.imageRequest). 높이는 보내지 않아 크롭 없이 비율을 유지한다. 콜드 리사이즈는 이미지당 전역 1회로 줄고, 같은 이미지를 두 번째 여는 사용자는 모두 CloudFront 히트를 받는다.

5. 남은 확인·주의

  • TestFlight 재검증 필요. 다음 TF 빌드에서 글로벌픽 #1 을 시청한 뒤 (1) 적립 영수증 다이얼로그가 뜨는지, (2) 안 뜨면 Sentry 의 ad.admob breadcrumb(earned 유무, ad_source_name/mediated)으로 조기 닫힘·표시 실패·미디에이션 채움 중 무엇인지 가른다. 미디에이션 채움에서 PENDING 이 반복되면 AdMob 콘솔의 미디에이션 그룹에서 해당 네트워크의 보상형 SSV 지원을 확인해야 한다.
  • 이 수정은 Google 이 콜백을 보내지 않는 경우(PENDING 3건)를 고치지 못한다. 그 원인은 기기 증거가 필요하다.
  • 리워드 이미지의 첫 요청은 여전히 이미지당 1회 콜드다. 운영자가 리워드 이미지를 올린 직후 ?q=80&w=1000 을 한 번 호출해 두면 사용자에게는 콜드가 보이지 않는다. 리사이저 자체(1.7MB PNG 5~10초)는 인프라 과제로 남긴다.
  • 홈 리워드 목록 카드는 기존대로 기기 크기 변형을 쓴다(≤12장, 다운로드 크기 우선).
  • 배포는 Dart 변경만이라 Shorebird OTA 대상이지만 130401 이 아직 스토어 심사 전이므로 배포 방식은 릴리스 담당 세션이 결정한다.
