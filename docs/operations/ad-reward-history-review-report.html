DefaultTabController 가 소유자 게이트 안쪽에서 만들어진다. 게이트가 닫히면 그 State 가 dispose 되고 다시 열릴 때 initialIndex: 0 으로 새로 생성되는데, _selectedCurrency 를 들고 있는 _CurrencyHistoryPageState 는 살아남는다. 결과적으로 인디케이터는 “코튼캔디”, 목록은 “보너스 스타캔디”가 될 수 있다.

검증 불가로 구분 — 재현 트리거를 이 세션에서 확정하지 못했다. userInfoProvider 는 invalidate 시 이전 값을 유지하므로, 게이트가 닫히려면 user_info_provider.dart:66 의 state = AsyncValue.error(...) 경로가 페이지 노출 중에 발생해야 한다. 이론상 도달 가능, 실측 미확인.

최소 수정 방향: DefaultTabController 를 게이트 위로 올리거나, 명시적 TabController 를 만들어 index 를 _selectedCurrency 에서 파생시킨다.

F7 Low 빈 페이지에 cursor 가 남아 있으면 더 못 넘긴다

파일/행 picnic_lib/lib/presentation/pages/my_page/currency_history_page.dart:153-161

itemCount 가 items.isEmpty 이면 nextCursor 와 무관하게 1 이라, 서버가 “빈 items + 다음 cursor”를 돌려주면 사용자에게는 “아직 내역이 없습니다.” 만 보이고 다음 페이지로 갈 수단이 없다.

검증 불가로 구분 — get_currency_history 가 그런 페이지를 낼 수 있는지는 서버 계약이고, 이 레포에 해당 함수 정의·마이그레이션이 없어 확인하지 못했다(설계 문서 :593 에도 명시 없음). 배제할 수 없는 상태.

최소 수정 방향: itemCount: items.length + (nextCursor == null ? 0 : 1) 로 두고, 빈 안내는 items.isEmpty && nextCursor == null 일 때만 별도 분기로 그린다.

F8 Low 관리자 메뉴에 같은 페이지로 가는 중복·비현지화 진입점이 남았다

파일/행 picnic_lib/lib/presentation/pages/my_page/admin_menu_page.dart:78-80, 116-120

관리자 메뉴는 여전히 하드코딩 '캔디 내역' 으로 같은 CurrencyHistoryPage 를 연다. 그런데 그 페이지는 이번 변경으로 “본인 내역”만 보여주므로, 관리자에게는 마이페이지와 관리자 메뉴에 동일 기능 진입점이 두 개 생기고 관리자 메뉴 쪽은 더 이상 관리자 고유 기능이 아니다. my_page_render_test.dart 의 keeps administrator tools separate from public history 는 마이페이지 진입점만 확인하고 이 중복은 다루지 않는다.

최소 수정 방향: 관리자 메뉴 항목을 제거하거나(권장), 남긴다면 wallet_history_title 로 현지화하고 “내 내역” 임을 라벨에 반영한다.

F9 Low loadNext() 의 bool 이 “성공”과 “아무것도 안 함”을 같은 값으로 합친다

파일/행 picnic_lib/lib/presentation/providers/wallet_provider.dart:267, 269, 272, 283, 298 · 소비 지점 picnic_lib/lib/presentation/pages/my_page/currency_history_page.dart:114-119

true 를 돌려주는 경우가 5가지다: 이미 로딩 중 / 세션 불일치 / cursor 없음 / 늦게 도착해 폐기 / 실제 성공. 위젯은 이를 _nextPageFailed = !succeeded 로 읽으므로 이름이 뜻하는 것과 값이 뜻하는 것이 다르다. 현재는 버튼이 nextCursor != null 일 때만 렌더되고 위젯 자체 세대 가드가 있어 실제 오동작은 재현되지 않는다.

최소 수정 방향: enum LoadNextOutcome { loaded, declined, failed } 같은 3값 결과로 바꿔 “선언적으로 아무것도 안 함”을 성공과 분리한다.

F10 Low _nextPageFailed 를 setState 밖에서 바꾼다

파일/행 picnic_lib/lib/presentation/pages/my_page/currency_history_page.dart:117-124

_nextPageFailed 대입은 setState 밖이고, 화면에 반영되는 것은 뒤따르는 finally 의 setState(() => _loadingNext = false) 덕분이다. 동작은 맞지만 두 문장의 순서에 암묵적으로 의존한다.

최소 수정 방향: 두 대입을 finally 의 단일 setState 안으로 합친다.

F11 Low ABA 보장의 전제(값 동등성 없음 + identical)가 테스트로 고정돼 있지 않다 / 세대 카운터가 둘이다

파일/행 picnic_lib/lib/presentation/providers/wallet_provider.dart:213-218, 269, 282 · picnic_lib/lib/presentation/pages/my_page/currency_history_page.dart:93

A→B→A 방어는 전적으로 WalletHistorySession 이 ==/hashCode 를 재정의하지 않는다는 사실과 호출부가 identical 을 쓴다는 사실 위에 서 있다. :213-214 주석이 의도를 적어 뒀지만, 나중에 freezed/Equatable 로 바뀌면 riverpod 의 updateShouldNotify 가 A→B→A 에서 재빌드를 건너뛰게 되고 목록이 재로그인 후에도 낡은 채 남는다(교차 계정 유출은 아님). 또 같은 역할의 세대 카운터가 _requestGeneration(위젯)과 _generation(provider) 둘로 존재해 추적이 어렵다.

최소 수정 방향: expect(WalletHistorySession('a') == WalletHistorySession('a'), isFalse) 한 줄짜리 테스트로 불변식을 고정한다.

잘 된 부분 (회귀 시 지켜야 할 계약)

  • 비로그인 0 RPC 가 3중으로 강제된다 — UI 진입점, 페이지 게이트, provider 의 repository 접근 전 throw. 그리고 provider 계층 테스트가 “repository 가 호출되지 않았다”를 직접 확인한다(간접 증거가 아님).
  • 늦은 응답·ABA 방어가 실제 반례를 재현한다 — 세션 identity(요청 전·후 2회 검사) + build 세대의 이중 가드이며, refresh 케이스는 세대 가드로만 잡히고 계정 전환은 identity 로만 잡히는 서로 다른 경로가 각각 테스트로 덮여 있다. 특히 wallet_provider_test.dart:410 은 기존 계약(늦은 페이지를 새 목록에 이어붙임)을 “cursor 는 자기 스냅샷 소유”로 뒤집는 판단이며, 이번 요구사항에 비춰 옳은 방향이다.
  • 페이지 게이트가 fail-closed 다 — 프로필 id 와 auth 세션 id 의 AND 라 어느 쪽이 지연되든 빈 화면으로 떨어진다. 두 출처가 프로덕션에서 같은 값임은 user_info_provider.dart:50(user_profiles.id == auth.currentUser.id)으로 확인했다.
  • 동일 사용자 token refresh 가 재조회를 만들지 않는다 — walletHistorySessionProvider 는 이벤트 종류가 아니라 소유자 변화만 본다. gotrue BehaviorSubject 리플레이로 인한 자기 무효화 루프(같은 파일 :104-113 에 기록된 실제 사고)를 구조적으로 피했고, firstPageCalls == 2 로 고정돼 있다.
  • on-demand 단일 통화 조회가 구조로 강제된다 — TabBarView 제거로 동시에 마운트되는 탭이 1개뿐이라 “실수로 3통화 조회”가 불가능하다.
  • 빈 목록에서도 pull-to-refresh 가 동작한다 — AlwaysScrollableScrollPhysics(:152). 놓치기 쉬운 디테일.
  • flutter analyze 무결, dart format 무결, 78/78 통과를 현재 트리에서 재확인했다.

차단 사유가 아닌 관찰

  • 무한 스크롤 자동 로드가 명시적 “다음 페이지” 버튼으로 바뀌었다(NotificationListener<ScrollEndNotification> 제거). 요구사항은 충족하지만 UX 변경이므로 제품 확인이 필요하다.
  • 버튼 라벨로 MaterialLocalizations.nextPageTooltip(툴팁 문자열)을 재사용한다. 현지화는 되지만 의미상 맞는 문자열은 아니다.
  • 빈 상태가 공용 NoItemContainer 대신 평문 Text 로 바뀌었다(import 제거). 다른 화면과 시각적으로 어긋난다.
  • 탭을 왕복하면 그때마다 해당 통화를 다시 조회한다(autoDispose). 이번 작업의 취지가 호출량 감소인 만큼, 짧은 유지 시간을 두는 편이 나을 수 있다.
  • 오류 화면에는 RefreshIndicator 가 없어 당겨서 새로고침이 불가하다(버튼만 가능).
  • isScrollable: true 인 3탭 TabBar 는 좌측 정렬되어 우측 여백이 크게 남는다.
