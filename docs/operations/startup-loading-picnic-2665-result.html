동의와 Mobile Ads 초기화가 여러 경로에서 중복 실행되고, 광고·딥링크 SDK가 스플래시 완료를 함께 막고 있었습니다.동시 호출은 한 초기화 작업을 공유합니다. 인증 완료는 기다리되 비인증 SDK를 추가로 기다리는 시간은 5초로 제한합니다. 실제 광고 SDK 준비 상태는 별도로 유지하고 실패 시 재시도합니다.
네트워크 상태 조회에 잘못된 빈 목록 조건과 제한 없는 대기가 있었습니다.빈 연결 목록과 연결 없음 상태를 처리하고 플랫폼 조회·DNS 확인에 시간 제한을 적용했습니다.
진단용 헬스체크와 분석 속성 설정도 시작 경로에 포함돼 있었습니다.오류를 관찰하는 비동기 작업으로 실행하고 초기화 단계별 소요 시간을 로그에 남깁니다.

사용자가 ATT·UMP 동의창에서 선택하는 시간은 강제로 종료하지 않습니다. 첫 ATT 동의창을 표시하기 위한 고정 1초 대기는 SDK 응답 예산과 별도로 유지하며, 이미 결정한 사용자는 이 대기를 건너뜁니다. 상태 조회 자체가 응답하지 않는 경우에는 동의나 광고 허용으로 처리하지 않고 시작을 진행합니다. 로그인 복구, 이용 제한·업데이트 확인, 결제 이벤트 구독 경로는 유지했습니다. 광고 요청은 실제 SDK 준비와 UMP 허용 여부를 확인한 뒤 실행합니다.

시작 단계에서 동의 조회가 실패하면 곧바로 같은 조회를 반복하지 않습니다. 이후 실제 광고 요청에서는 다시 시도할 수 있습니다. 광고 준비 후 동의 상태를 확인하고, 대기 중 화면이 닫혔다면 광고 요청을 취소해 늦은 배너 로드도 방지했습니다.

PICNIC-2665: 앱 전반 펄스 로딩

PICNIC-2665 — 앱 전반 로딩바를 펄스 애니메이션으로 개선의 제목을 기준으로 구현했습니다. 조회 당시 본문·댓글·첨부에 추가 요구사항은 없었습니다.

  • 알림, 프로필, 충전·이용 내역, 문의, 투표 버튼·팝업 등 앱이 표시하는 불확정 로딩을 공통 펄스로 통일했습니다.
  • 작은 버튼에서 인디케이터가 화면 전체 크기로 늘어나던 문제를 수정하고 지정 크기 안에서 그리도록 했습니다.
  • 시스템의 애니메이션 줄이기 설정에서는 펄스를 정지 상태로 표시합니다.
  • 업로드 진행률, 새로고침 조작, 동영상·외부 SDK의 기본 제어 UI는 기존 의미를 유지합니다.
