폐기 경로와 최종 화면 반영 가능성

  • 소유자/epoch 불일치: 이전 세션 정산을 현재 화면에서 버리는 것이 맞다. 원 계정 잔액은 그 계정으로 다시 로그인할 때 서버 build로 복구된다.
  • 성공 재조회 선행: 정산 완료 뒤 시작된 서버 읽기가 그 지급을 포함하는 최신 답이므로 정산 snapshot을 버려도 잔액은 재조회 결과에 남는다.
  • snapshotAt이 더 오래됨: 화면에 이미 더 최신 서버 snapshot이 있으므로 폐기된 잔액 변화가 최신 snapshot에 포함된다.
  • provider dispose: 더 이상 표시 대상이 없으며 다음 관찰 시 build가 서버 값을 다시 읽는다.

실패 재조회는 위 안전 근거가 없으므로 더 이상 폐기 트리거가 아니다. 검토한 폐기 경로마다 화면에 최신 잔액을 제공하는 경로가 남아 있다.

추가 테스트의 판별력

두 테스트의 조합이 핵심 분기를 구분한다. _reReads를 전혀 올리지 않는 구현은 성공 재조회 테스트에서 99가 70을 덮어 실패하고, 성공·실패 모두 올리는 직전 구현은 실패 재조회 테스트에서 88 대신 10이 남아 실패한다. 따라서 “성공 응답만 authoritative”라는 요구를 우회하기 어렵다.

logout→A 테스트는 비동기 auth 이벤트가 아직 전달되지 않은 실제 취약 창을 만들고 두 번 drain한 뒤 재단언한다. owner ID만 비교하거나 signed-out 전환을 무시하는 구현은 stale 99를 통과시켜 테스트가 실패한다.

기존 테스트의 지연 판별력 전수 확인

setSummary/applyWallet 호출 뒤 동기로 단언하는 테스트를 검색해 모두 확인했다. snapshot 순서 4건(wallet_provider_test.dart:2100-2195)은 인증 연동이 없어 Session이 동일하므로 의도대로 동기 적용된다. owner A→B 및 sign-out 테스트는 첫 소유권 검사에서 동기로 거부된다. Session 교체로 실제 지연되는 token refresh, 이벤트 미전달 왕복, logout→A, refresh 경합 테스트에는 drain이 있다.

기존 A→B→A 왕복 테스트(wallet_provider_test.dart:2295-2327)의 두 차례 drain은 현재 구현에서는 epoch 불일치로 즉시 거부되어 중복처럼 보이나, epoch 검사를 제거해 session-only 지연 경로로 퇴행하는 변이를 잡는다. 따라서 지연 도입 이후 테스트 판별력 보강으로 충분하다.
