광고 보상 배선 후속 — WidgetRef dispose 경계

2026-09-08 · 워크트리 /Users/charlie.hyun/orca/workspaces/picnic-app/hotfix-ad-reward-recovery-load · 브랜치 hotfix/ad-reward-recovery-load

root 독립 리뷰가 제기한 Medium 지적은 사실이었고, 재현했다. “팝업과 독립”이라고 보고했던 통계 경로가 실제 플랫폼 배선에서는 광고 화면 수명에 여전히 묶여 있었다. 이 문서는 그 재현·수정·검증만 다룬다 (앞선 ad-reward-app-redesign-core-report.html 은 참조용).

1. 결함

AdPlatform.ref 는 WidgetRef 다 (ad_platform.dart — final WidgetRef ref;). 내가 지난 작업에서 넣은 onGrantConfirmed 와 기존 poll 은 둘 다 클로저 안에서 지연 평가되는 ref.read(...) 였다. 

poll:             (owner, ref2) => ref.read(adRewardRecoveryProvider.notifier).poll(...)
onGrantConfirmed: (owner, status) => ref.read(adRewardRecoveryProvider.notifier).recordConfirmedGrant(...)

callback-ad-shortform-view 는 네트워크 왕복이고, 그 응답이 돌아올 때 사용자는 이미 광고를 닫았을 수 있다. 그러면 이 플랫폼을 만든 Consumer 는 dispose 됐고 ref.read 는 던진다. 그리고 그 예외는 InternalShortformViewRecoveryFlow._recordConfirmedGrant 가 onPollError 로 흘려보낸다 — 보상 흐름을 막지 않기 위한 의도된 처리이지만, 결과적으로 서버가 이미 확정한 GRANTED 가 로그 한 줄만 남기고 사라진다.

2. 수정

2-1. shortform_internal_platform.dart

_callView 안에 인라인돼 있던 배선을 buildViewRecoveryFlow(InternalShortformViewFlow view) (@visibleForTesting) 로 뽑고, 그 안에서 왕복을 시작하기 전에 keepAlive notifier 를 한 번 잡는다. 

// 왕복을 시작하기 전에, Consumer 가 아직 살아 있는 지금 잡는다.
final recovery = ref.read(adRewardRecoveryProvider.notifier);
return InternalShortformViewRecoveryFlow(
  view: view,
  poll: (ownerUserId, reference) =>
      recovery.poll(ownerUserId: ownerUserId, reference: reference),
  onGrantConfirmed: (ownerUserId, status) =>
      recovery.recordConfirmedGrant(ownerUserId: ownerUserId, status: status),
  onPollError: ...,
);

adRewardRecoveryProvider 는 keepAlive: true 라 notifier 의 수명은 위젯이 아니라 ProviderContainer 다. 잡아 둔 뒤로는 콜백이 언제 돌아오든 WidgetRef 를 다시 읽지 않는다. 메서드 추출은 배선을 실제로 테스트에서 태우기 위한 것이고, 새 상태·새 API 표면·구조 확장은 없다.

2-2. pangle_platform.dart — 같은 결함

Pangle 의 poll 도 동일하게 클로저 안에서 ref.read 를 한다. 이쪽은 SDK 시그널 스트림에서 광고 종료 후에 호출되고, 바로 그 자리의 주석이 “dispose 된 ref.read 처럼 poll 이 동기로 던지는 경우도 catchError 로 모은다” 라고 적혀 있다 — 즉 현재 설계는 이 예외를 막는 게 아니라 삼키고 있었다.

같은 캡처를 적용했다. 캡처 지점은 이미 존재하던 두 개의 ref.read (adRewardRepositoryProvider, pendingAdRewardStoreProvider) 와 같은 줄 묶음이라, 그 지점이 살아 있다는 것은 기존 코드가 이미 전제하고 있다. 따라서 이 변경은 기존 동작 대비 추가 위험이 없다.

3. 회귀 테스트

신규 picnic_lib/test/.../platforms/shortform_view_recovery_wiring_test.dart. flow 를 단위 테스트하지 않고 실제 프로덕션 경계를 태운다:

  • 실제 Consumer 로 살아 있는 WidgetRef/BuildContext 를 잡아 실제 ShortformInternalPlatform 을 만든다 (기존 shortform_showad_reentrancy_test.dart 의 하네스 선례와 동일).
  • 실제 platform.buildViewRecoveryFlow(...) 로 배선을 만든다 — 테스트가 배선을 흉내내지 않는다.
  • tester.pumpWidget(SizedBox) 로 진짜 dispose 시킨다.
  • 그 뒤에 지연된 시청 응답(Completer)을 완료시킨다.

5. 남은 것 / 한계

  • Pangle 전용 위젯 회귀는 없다. 그 배선을 끝까지 태우려면 Environment 의 Pangle 배치 ID, PangleAds SDK, supabase 전역이 필요해 비용이 과했다. 대신 수정 자체가 숏폼과 동일한 캡처이고, 캡처 지점의 안전성은 같은 자리의 기존 ref.read 두 개가 이미 보장한다. 별도 하네스가 필요하면 후속으로 잡는 편이 낫다.
  • _callView 의 나머지 부분(supabase.functions.invoke, supabase.auth.currentUser)은 여전히 전역에 직접 붙어 있어 테스트가 태우지 못한다. 이번 회귀가 고정하는 것은 보상 콜백 배선이지 시청 콜백의 네트워크 부분이 아니다.
  • 앱이 관측하지 못한 서버 지급(앱이 아예 죽은 경우 등)은 여전히 이 경로의 보장 범위 밖이다 — 계획서가 명시한 대로 서버 원장 집계가 그 자리를 맡는다.
  • 배포 전이므로 운영 호출량·통계 정확도 개선은 실측 전까지 주장하지 않는다.
  • 이전 보고서의 한계 1건은 해소됐다. 지난 보고서에 적었던 analytics_outbox_currency_test.dart 날짜 의존 실패는 root 가 독립 재현한 뒤 프로덕션 코드 변경 없이 테스트 픽스처만 고쳤다(기존 enqueueOrMergePurchase API 에 createdAt: now 전달). 해당 파일은 root 소유이며 지금은 46건 통과한다.
