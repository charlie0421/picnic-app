광고 기기 정책 Android 실기기 검증

2026-10-07 15:37 KST · Samsung SM-G781N · Android 13 / API 33 · 물리 기기

27회 정책 요청과 14개 언어 안내 검증을 통과했다. 기존 앱 코드와 실제 SQL 정책을 별도 QA 앱에서 연결했다. 첫 3계정은 계속 허용되고, 4번째 계정은 제한됐다. 시간 범위에서 첫 계정이 빠지면 4번째 계정의 다음 요청이 허용됐다.

검증 결과

조건자체 광고·AdMob·Pangle의 결과
같은 기기에서 A → B → C 순서로 요청9회 허용
D가 4번째 계정으로 요청3회 제한. AD_DEVICE_ACCOUNT_LIMIT를 실제 앱 예외로 변환
D 제한 후 A·B·C가 다시 요청9회 허용. 기존 3계정 보호
A의 기록을 25시간 전으로 이동 후 D 요청3회 허용. 자동 해제
A가 다시 요청하여 4번째가 됨3회 제한
기기 식별Android 네이티브 채널 응답 확인. DeviceManager 반복 호출의 값 일치. 서버에서 27회 요청의 기기 해시가 1개로 집계됨
제한 안내14개 locale의 실제 번역 표시·확인 버튼 닫기 통과. 내부 코드 미노출. 스페인어 200% 확대에서도 overflow 예외 없음

실제 화면

앱의 showRateLimitedDialog를 표시하고 Flutter integration_test로 캡처했다. 이미지는 수정하지 않았다. QA 앱의 기본 테마이며 운영 앱 전체 화면의 테마·동선 검증은 아니다.

연결 구성과 한계

별도 패키지 io.picnic.qa.ad_device_qa가 현재 picnic_lib를 직접 참조한다. AdRewardRepository, InternalShortformIssueFlow, DeviceManager, 오류 변환기와 제한 다이얼로그를 사용한다. 네이티브 SSAID 채널은 제품과 같은 방식으로 구현한 QA 핸들러다.

adb reverse로 로컬 전용 Python 브리지에 연결한다. 브리지는 격리 PostgreSQL 15.8과 PostgREST 14.8의 실제 정책 RPC를 호출한다. 전체 public baseline, 관련 기존 마이그레이션 18개와 새 정책 마이그레이션을 사용한다. 서버의 설정은 이 임시 DB에서만 활성화했다.

계정 헤더와 성공 시 발급 응답은 가상 데이터다. 실제 Edge 인증·서명 토큰 발급, 광고 SDK 재생, 보상 정산, 운영 앱의 전체 화면 전환, iOS 실기기는 이번 시험 범위에 포함하지 않는다. 시간 이동 시험은 운영에서 24시간 관찰한 결과가 아니다.

운영 앱 io.iconcasting.picnic.app의 버전은 전후 모두 1.3.5 / 130502, 마지막 갱신 시각은 2026-09-22 23:39:25로 같았다. 운영 환경 파일·서명·버전은 변경하지 않았다. 종료 후 QA의 Docker 컨테이너·네트워크와 adb reverse가 정리됐음을 확인했다.

재현

Docker, Flutter, Android SDK와 adb로 접근 가능한 테스트 기기가 필요하다. 아래 두 명령은 서로 다른 터미널에서 순서대로 실행한다. 첫 명령의 READY를 확인한 뒤 두 번째 명령을 실행한다.

cd /Users/charlie.hyun/Repositories/picnic-supabase-ad-reward-block
python3 scripts/anti-abuse/ad-device-android-bridge.py   --ready-file /tmp/picnic-ad-device-bridge-ready.json   --evidence-dir /tmp/picnic-ad-device-android-evidence
cd /Users/charlie.hyun/Repositories/picnic-app-ad-device-policy
python3 scripts/qa/run_ad_device_android.py   --device <adb 기기 ID>   --bridge-ready /tmp/picnic-ad-device-bridge-ready.json

QA 빌드는 임시 디렉터리에 생성된다. 기존 Android namespace 호환 설정과 호스트의 Tapjoy 의존성을 반영했다. 실제 광고를 요청하지 않는다. 테스트 종료 시 브리지가 임시 DB를 정리한다.

기록

실행 결과: 00:23 +1: All tests passed!, 종료 코드 0. 같은 변경에서 DB fixture 준비 부분을 공용 함수로 분리했고, 기존 PostgREST 통합 시험도 다시 통과했다. 독립 교차 리뷰와 운영 적용은 아직 완료하지 않았다.
