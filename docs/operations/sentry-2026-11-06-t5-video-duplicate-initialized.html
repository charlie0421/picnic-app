T5 · 영상 중복 initialized 원인 분류 (PICNIC-APP-50W)

2026-11-06 · 기준 커밋 3e25ce7db · 작업 브랜치 docs/sentry-release-analysis · 코드 변경 없음

원인 분류: 앱의 중복 initialize가 아니라 영상 플랫폼 구현(네이티브 플러그인)이 같은 플레이어에 initialized 이벤트를 두 번 이상 보낸 경우와 일치한다. 앱 Dart 코드에서 막을 수 있는 경로는 찾지 못했다. 수정 후보는 플러그인 업그레이드이며, 네이티브 변경이므로 신규 바이너리 경로(T8)가 필요하다. 업그레이드가 이 결함을 고친다는 근거는 아직 확인하지 않았다.

사건

50W: StateError: Bad state: VideoPlayerController already initialized. 최근 7일 10건·6명, 누적 243건·80명(2026-03-24 이후). 최신 이벤트는 iOS 17.1.1(iPhone12,1), 릴리스 1.3.5+130504다. 앱 쪽 유일한 프레임은 video_player.dart의 VideoPlayerController.initialize.eventListener 621행이며, 스트림 이벤트 처리 중 발생했다. 로컬 증거에는 이슈별 최신 이벤트 1건만 있어 OS별 분포는 확인하지 못했다.

앱 호출 경로

  • VideoPlayerController를 만드는 곳은 두 곳이다: ad_shortform_fullscreen_page.dart의 _initPlayer와 qna_video_player_page.dart의 _initializePlayer.
  • 두 곳 모두 컨트롤러 하나에 initialize()를 한 번만 부른다. 광고 페이지는 initState에서 한 번 실행되는 흐름에서만 컨트롤러를 만든다. QnA 페이지는 초기화가 끝난 컨트롤러를 Chewie에 넘긴다.
  • shortform_internal_platform.dart의 _controller 필드에는 값을 넣는 코드가 없다.

재현 (실제 video_player 2.11.0 Dart 코드 + 가짜 플랫폼)

가짜 VideoPlayerPlatform으로 플러그인의 Dart 계층만 실행했다. 네이티브 코드는 실행하지 않았다.

경우결과50W와 일치
A. 같은 플레이어에 initialized 이벤트 2회video_player.dart:614 assert 실패: "VideoPlayerController already initialized. This is typically a sign that an implementation of the VideoPlayerPlatform … has a bug and is sending more than one initialized event per instance." 오류는 이벤트 리스너에서 zone 미처리 오류로 나왔다. 컨트롤러는 initialized 상태로 남았다.예 (메시지·발생 위치)
B. 같은 컨트롤러에 initialize() 순차 2회플레이어를 새로 만들고(create 2회) 오류 없음.아니오
C. initialized 전에 dispose오류 없음. 초기화 Future는 끝나지 않음(호출자 타임아웃으로 확인).아니오
D. 같은 컨트롤러에 initialize() 동시 2회호출자에게 Bad state: Future already completed.아니오 (메시지 다름)

flutter test는 assert를 끌 수 없다. 그래서 릴리스 빌드에서 assert 대신 621행의 StateError가 난다는 점은 Sentry 스택의 행 번호·메시지와 assert 문구가 일치한다는 근거로만 판단했다. 플러그인 소스를 읽어 621행을 직접 확인하는 일은 남아 있다.

판단

  • 앱이 같은 컨트롤러를 두 번 초기화하는 경우는 50W와 다른 결과를 낸다(B, D). 늦은 완료와 dispose도 이 오류를 만들지 않는다(C). 50W의 메시지와 발생 위치는 플랫폼이 같은 인스턴스에 initialized를 두 번 보낸 경우(A)와 일치한다.
  • 오류는 플러그인 내부의 스트림 리스너에서 나므로 앱 코드가 잡을 수 없다. 계획에 따라 근거 없는 억제 플래그나 beforeSend 필터는 추가하지 않았다.
  • 재현 A에서 컨트롤러는 initialized 상태를 유지했다. 그래서 사용자 영향은 재생 중단보다 오류 보고 쪽일 가능성이 높다. 실제 기기에서는 확인하지 않았다.
  • 어떤 네이티브 상황(백그라운드 복귀, HLS 화질 전환, 재버퍼링 등)이 두 번째 initialized를 만드는지는 확인하지 못했다.

다음 조치

  1. Sentry에서 50W의 OS·플러그인 플랫폼 분포를 확인한다(iOS 전용인지).
  2. 현재 플러그인(video_player 2.11.0, video_player_avfoundation 2.9.4, video_player_android 2.9.4)의 소스에서 621행과 initialized 전송 조건을 확인한다.
  3. 최신 버전(로컬 pub outdated 기준 2.14.1 / 2.12.3 / 2.12.2)의 변경 기록에서 중복 initialized 수정 여부를 확인한다. 수정이 확인되면 업그레이드를 신규 바이너리 후보로 올리고, 정상 HLS 재생·닫기·재진입 회귀를 확인한다.
  4. 근거가 없으면 이번 통합 빌드에서 제외하고 원인 미확정으로 남긴다.

위 1–3은 현재 세션 권한 밖(Sentry 조회, pub 캐시 읽기, 네트워크)이라 사용자 승인 후 진행한다.
