T5 · 영상 중복 initialized 원인 분류 (PICNIC-APP-50W)

2026-11-06 · 기준 커밋 3e25ce7db · 작업 브랜치 docs/sentry-release-analysis · 코드 변경 없음

원인 분류: 앱의 중복 initialize가 아니라 영상 플랫폼 구현(네이티브 플러그인)이 같은 플레이어에 initialized 이벤트를 두 번 이상 보낸 경우와 일치한다. 앱 Dart 코드에서 막을 수 있는 경로는 찾지 못했다.

2026-11-06 추가 확인 — 이번 통합 빌드에서 제외: 플러그인 소스와 공개 변경 기록을 확인했다. 업그레이드가 50W를 고친다는 근거가 없으므로 수정 후보에서 뺀다. 원인이 되는 네이티브 상황은 확인하지 못했으며 미확정으로 남긴다. 세부 근거는 아래 "플러그인 소스와 변경 기록" 절에 있다.

사건

50W: StateError: Bad state: VideoPlayerController already initialized. 최근 7일 10건·6명, 누적 243건·80명(2026-03-24 이후). 최신 이벤트는 iOS 17.1.1(iPhone12,1), 릴리스 1.3.5+130504다. 앱 쪽 유일한 프레임은 video_player.dart의 VideoPlayerController.initialize.eventListener 621행이며, 스트림 이벤트 처리 중 발생했다. 로컬 증거에는 이슈별 최신 이벤트 1건만 있어 OS별 분포는 확인하지 못했다.

앱 호출 경로

  • VideoPlayerController를 만드는 곳은 두 곳이다: ad_shortform_fullscreen_page.dart의 _initPlayer와 qna_video_player_page.dart의 _initializePlayer.
  • 두 곳 모두 컨트롤러 하나에 initialize()를 한 번만 부른다. 광고 페이지는 initState에서 한 번 실행되는 흐름에서만 컨트롤러를 만든다. QnA 페이지는 초기화가 끝난 컨트롤러를 Chewie에 넘긴다.
  • shortform_internal_platform.dart의 _controller 필드에는 값을 넣는 코드가 없다.

재현 (실제 video_player 2.11.0 Dart 코드 + 가짜 플랫폼)

가짜 VideoPlayerPlatform으로 플러그인의 Dart 계층만 실행했다. 네이티브 코드는 실행하지 않았다.

경우결과50W와 일치
A. 같은 플레이어에 initialized 이벤트 2회video_player.dart:614 assert 실패: "VideoPlayerController already initialized. This is typically a sign that an implementation of the VideoPlayerPlatform … has a bug and is sending more than one initialized event per instance." 오류는 이벤트 리스너에서 zone 미처리 오류로 나왔다. 컨트롤러는 initialized 상태로 남았다.예 (메시지·발생 위치)
B. 같은 컨트롤러에 initialize() 순차 2회플레이어를 새로 만들고(create 2회) 오류 없음.아니오
C. initialized 전에 dispose오류 없음. 초기화 Future는 끝나지 않음(호출자 타임아웃으로 확인).아니오
D. 같은 컨트롤러에 initialize() 동시 2회호출자에게 Bad state: Future already completed.아니오 (메시지 다름)

flutter test는 assert를 끌 수 없다. 릴리스 빌드에서 assert 대신 621행의 StateError가 나는 것은 아래 "플러그인 소스와 변경 기록" 절에서 소스로 확인했다.

판단

  • 앱이 같은 컨트롤러를 두 번 초기화하는 경우는 50W와 다른 결과를 낸다(B, D). 늦은 완료와 dispose도 이 오류를 만들지 않는다(C). 50W의 메시지와 발생 위치는 플랫폼이 같은 인스턴스에 initialized를 두 번 보낸 경우(A)와 일치한다.
  • 오류는 플러그인 내부의 스트림 리스너에서 나므로 앱 코드가 잡을 수 없다. 계획에 따라 근거 없는 억제 플래그나 beforeSend 필터는 추가하지 않았다.
  • 재현 A에서 컨트롤러는 initialized 상태를 유지했다. 그래서 사용자 영향은 재생 중단보다 오류 보고 쪽일 가능성이 높다. 실제 기기에서는 확인하지 않았다.
  • 어떤 네이티브 상황(백그라운드 복귀, HLS 화질 전환, 재버퍼링 등)이 두 번째 initialized를 만드는지는 확인하지 못했다.

플러그인 소스와 변경 기록

130504 릴리스 태그와 현재 HEAD의 picnic_app/pubspec.lock은 같은 버전을 쓴다: video_player 2.11.0, video_player_avfoundation 2.9.4, video_player_android 2.9.4.

확인 대상결과
video_player.dart 613–622행두 번째 initialized에서 assert(614행)를 실행하고, assert가 꺼진 릴리스 빌드에서는 621행 throw StateError('VideoPlayerController already initialized')를 실행한다. 50W의 행 번호·메시지와 같다.
iOS 2.9.4 FVPVideoPlayer.m_isInitialized가 YES가 되면 다시 NO가 되지 않는다. initialized 송신은 이 값이 NO일 때만 한다. 플레이어 ID는 계속 증가한다. 이벤트 브리지는 구독 전 이벤트를 한 번만 내보낸다. KVO 등록은 Initial 옵션을 쓰지 않는다. 이 플래그는 잠금 없이 읽고 쓰므로, 서로 다른 스레드의 status 알림이 겹치면 두 번 송신할 수 있다. 이 경합은 코드에서 가능한 경로일 뿐이며 재현하지 않았다.
Android 2.9.4플레이어마다 ExoPlayer와 이벤트 리스너를 하나씩 만들고, 리스너의 isInitialized 가드로 initialized를 한 번만 보낸다. 표면을 다시 만들 때 플레이어를 새로 만들지 않는다. 플레이어 ID는 계속 증가한다.
다른 VideoPlayerPlatform 구현lock 파일에 대체 구현 패키지가 없다. chewie, video_player_web만 있다.
최신 변경 기록 (GitHub flutter/packages, 2026-11-06 조회)video_player_avfoundation 2.9.5–2.12.3과 video_player_android 2.9.5–2.12.3에는 중복 initialized 수정 기록이 없다. video_player는 2.9.2에서 이 경우에 설명이 담긴 StateError를 던지도록 바꿨고, 이후 버전에서 이를 허용하도록 바꾸지 않았다. avfoundation 2.12.2 이상과 android 2.9.6 이상은 현재 Flutter 3.41.4보다 높은 SDK가 필요하다.

결정과 남은 확인

  1. 이번 통합 빌드에는 50W 수정을 넣지 않는다. 업그레이드로 고친다는 근거가 없고, 앱에서 근거 없는 억제 코드를 넣지 않는다.
  2. Sentry에서 50W의 OS 분포를 확인한다. iOS에 집중되면 KVO 스레드 경합 가설을 실기기 재현(T7 성격)으로 검증한다. 이 조회는 Sentry 접근 방법이 정해진 뒤 진행한다.
  3. 실기기 재현 후보: HLS 광고 재생 중 백그라운드 전환과 복귀, 네트워크 전환, 저속망 초기화. 운영 광고 지급과 연결된 조작은 하지 않는다.
