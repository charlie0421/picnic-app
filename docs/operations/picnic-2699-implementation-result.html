PICNIC-2699 투표 완료 팝업 뷰포트 대응 구현 결과

상태: 커밋 460eba6ef. 신규 테스트 +74, voting 전체 +1343 실패 0, analyze 521(부모와 동일).

결론: 완료 팝업의 모든 상자가 고정 높이 대신 최소 높이를 말하게 하고, 그렇게 얻은 자연 크기를 창에 맞춰 통째로 축소한다. 축소는 한 배율을 전체에 적용하므로 화면과 공유 이미지가 계속 일치한다.

1. 실측한 결함

티켓은 "짧은 화면에서 위아래로 잘린다" 였으나, 실측 결과 두 축 모두 넘치며 기본 세로 화면 1.0배도 예외가 아니다.

2. 스크롤을 쓸 수 없는 이유

PICNIC-2694 는 입력 팝업을 스크롤로 해결했다. 완료 팝업에는 쓸 수 없다. 이 팝업은 RepaintBoundary 안에서 공유 투표 이미지로 캡처되는데, 스크롤 뷰는 화면에 있는 것만 렌더하므로 스크롤로 밀려난 부분이 이미지에서 사라진다.

캡처 경로 실측: ShareUtils._captureContent 는 boundary.toImage(pixelRatio: 2.0) 로 잡아 흰 캔버스에 합성한다. 그 경계는 Dialog 위에 있어 화면 전체 크기다. 즉 393×852 기기의 공유 이미지는 786×1704 이고 팝업은 그 가운데 놓인다.

따라서 수정 전에는 공유 이미지 자체가 잘려 있었다. 가로 화면에서 팝업이 437px 인데 캡처 영역이 393px 이므로 44px 이 이미지에서 사라졌다. 이 결함은 표시만의 문제가 아니었다.

3. 변경

3.1 내용을 내재 크기로

  • 머리말 알약 height: 51·43, 프로필 칸 height: 70 → BoxConstraints(minHeight:). 1.0배 디자인 높이는 그대로 유지되고 그보다 커질 때만 자란다.
  • 프로필의 닉네임·날짜 열을 Expanded 로 감쌌다. 폭이 정해져야 기존 ellipsis 가 비로소 동작한다. 닉네임에도 maxLines: 1 을 넣었다 — 사용자가 정하는 값이라 길이 상한이 없다.
  • 아티스트 열과 득표 카드를 IntrinsicHeight + CrossAxisAlignment.stretch 로 묶어 같은 높이를 유지하면서 내용을 따라 자라게 했다. 득표 카드의 height: double.infinity 와 MainAxisSize.max 는 제거했다 — 높이는 이제 행이 준다.

3.2 창에 맞춘 통짜 축소

Dialog 바로 아래에 FittedBox(fit: BoxFit.scaleDown) 을 넣었다. 카드는 자연 크기로 배치된 뒤 창보다 크면 통째로 줄어든다. 한 배율을 전체에 적용하므로 보이는 것과 공유되는 것이 계속 일치하고, scaleDown 은 확대하지 않으므로 여유 있는 창은 손대지 않는다.

3.3 그룹 이미지의 고정 크기 상자

장식이 아니라 필수다. PicnicCachedNetworkImage 안에 LayoutBuilder 가 있어 내재 크기 질의에 답하지 못하는데, 위의 IntrinsicHeight 가 그것을 묻는다. 고정 크기 부모는 하위로 내려가지 않고 60 을 답하므로 질의가 거기서 멈춘다. 아티스트 분기에는 원래 이 상자가 있었고 그룹 분기에만 없어서 그룹 경로만 단언 실패했다.

주의: 이 행 아래에 LayoutBuilder 를 새로 넣으면 같은 단언이 다시 터진다. 조용히 깨지지 않고 디버그에서 즉시 실패하므로 테스트가 잡는다.

4. 테스트

신규 voting_complete_viewport_test.dart 74건. 6개 뷰포트 × 3개 배율에서 네 가지를 확인한다.

  1. 넘침 0. 자산 로딩·타이머 잡음은 걸러내되 overflowed 는 절대 걸러내지 않는다. 기존 테스트가 그것을 걸러내서 결함이 보이지 않았다.
  2. 카드가 창 안에 있다. getRect 로 변환된 사각형을 본다. getSize 는 배율 적용 전 값이라 무엇을 하든 통과한다.
  3. 저장·공유 버튼이 그려진 자리에서 적중한다. 축소된 카드를 누를 수 없다면 잘리는 것보다 나쁘다. 행의 중심은 두 버튼 사이 빈 공간이라 버튼을 직접 겨냥한다.
  4. 캡처 영역이 카드를 포함한다. 넷 중 가장 중요하다. 공유 이미지는 화면의 스냅샷이므로 창을 벗어난 팝업은 공유 이미지에서도 잘린다.

RED 확인: 부모 커밋 8a24928ed 를 별도 워크트리에 띄워 같은 테스트를 돌렸다. overflows=1, 결과 +0 -1 로 실패한다.

뷰포트에 따라 판별력이 다르다. 가로 화면에서는 카드의 레이아웃 사각형이 화면에 맞춰 잘린 채 보고되므로 (2)번 단언은 부모에서도 통과한다. 그 조합을 잡는 것은 (1)번이다. 네 단언은 서로 다른 조합을 덮는다.

7. 남은 위험과 후속 후보

  • 공유 이미지가 대부분 여백이다. 캡처 경계가 화면 전체라 공유 이미지는 흰 바탕 가운데 작은 카드가 놓인 형태이고, 가로 화면에서는 가로로 긴 흰 이미지가 된다. 이번 범위 밖이지만 별도 티켓 후보다. 경계를 카드로 좁히면 해결되나 공유 이미지가 완전히 달라지므로 디자인 결정이 필요하다.
  • 2.0배 가로에서 축소율 0.621. 사용자가 키운 글자를 다시 줄이는 셈이라 접근성과 상충한다. 스크롤이 불가능한 제약에서 선택한 절충이며, 그 이유는 2절에 기록했다.
  • IntrinsicHeight 는 하위에 LayoutBuilder 가 없어야 한다. 3.3절 참조.
  • 기존 voting_complete_test.dart 는 여전히 넘침을 억제한다. 신규 파일이 그 축을 덮으므로 남겨 뒀으나, 억제를 걷어내는 것은 후속 정리 후보다.
