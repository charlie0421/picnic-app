3. 자동 검증 (이 워크트리, HEAD 9d0469c7f)

  • picnic_lib 전체 테스트: 17,471 통과, 6 skip, 13 실패.
  • 실패 13개는 이번 변경과 무관하다. 골든·시각 테스트 12개(candy_boost_banner, usage_policy_dialog 8, reward_breakdown 2, wallet_summary_panel)는 호스트 렌더링 차이(예: 0.18%, 139px)로 실패하고, longest_app_localizations_test는 생성 파일과 arb 해시가 다르다. 이번 diff는 l10n·arb·wallet·store/common·폰트·pubspec 의존성을 바꾸지 않았다. 통합 워크트리에서 main 기준 결과와 비교한다.
  • 변경 파일 analyze: 신규 이슈 없음. voting_complete.dart의 기존 경고 2개(invalid_use_of_visible_for_testing_member)는 이전부터 있었다.
  • 네이티브 파일 변경 없음(pubspec 버전 줄 제외). 모든 제품 변경은 Dart다.

4. 통합 워크트리 절차 (Flutter 릴리스 정책 기준)

  1. 최신 origin/main에서 통합 브랜치를 만들고 1절 제품 커밋을 순서대로 반영한다. 테스트·QA 커밋 포함 여부는 통합 담당이 정한다.
  2. 버전을 정한다. 1.3.6이 스토어에 정식 출시되지 않았다면 같은 표시 버전의 다음 빌드 순번을 쓴다. 업로드된 최대값보다 크고 130606을 건너뛴 1.3.6+130607이 후보다. 정확한 값은 App Store Connect·Google Play에 업로드된 최대 Build number를 확인한 뒤 확정한다.
  3. 통합 브랜치에서 전체 테스트·analyze를 실행해 3절과 비교한다.
  4. PR 리뷰 → main 병합 → HEAD == origin/main·작업 트리 깨끗함 확인.
  5. 태그 이름·버전·커밋을 보여주고 사용자 명시 승인 → annotated tag 푸시(codemagic.yaml 태그 패턴, 예: 기존 picnic-v1.3.6+130605-skip-tests 형식).
  6. Codemagic 워크플로·artifact·TestFlight/Play 내부 업로드·Shorebird release 생성을 확인한다. 태그 푸시만으로 성공 처리하지 않는다.

모든 제품 변경이 Dart이므로 기존 1.3.6 바이너리에 Shorebird OTA로도 전달할 수 있다. 사용자 결정은 테스트 빌드이므로 위 절차를 기본으로 한다. OTA를 택하면 정확한 Shorebird release 확인과 별도 승인이 필요하다.

5. 테스트 빌드 QA 항목

항목확인
Branch 공유정상 공유. 비행기 모드·느린 망에서 10초 안에 다운로드 링크로 공유 시트가 열린다.
Tapjoy 오퍼월정상 표시. 오프라인에서 실패 안내 1회. Sentry에 TapjoyFailure(stage, kind)와 tapjoy_cause 태그, SDK 원문 없음.
강제 업데이트 화면iOS 27 기기에서 버튼이 App Store를 연다. 실패 시 "앱 스토어를 열 수 없습니다." 문구와 재시도. Sentry store_launch_failed warning, URL 없음. (QA에서 강제 업데이트 조건을 만들려면 운영 force_version을 바꾸지 말고 테스트 환경을 쓴다.)
푸시·계정 전환·프로필 이미지1차 후보 인계 문서의 QA 조건을 따른다.
구매·광고 회귀실제 결제·보상은 테스트 계정·샌드박스에서만 확인한다.
