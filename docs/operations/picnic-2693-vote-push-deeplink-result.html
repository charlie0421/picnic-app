투표 현황 푸시 탭 시 상세 이동

PICNIC-2693 · 2026-09-15 · fix/picnic-2693-vote-push-deeplink · 앱 1.3.4+130403

앱 결함 4건 수정 완료. 교차 공급자 적대적 리뷰 3라운드 종료, 잔여 차단 지적 없음. Dart 전용 변경이라 OTA 범위를 유지합니다.

증상과 범위

투표 현황 푸시를 탭하면 해당 투표 상세가 아니라 초기화면으로 이동했습니다. 조사 결과 서버는 정상이고 원인은 전부 앱에 있었습니다.

서버는 정상이다

발송 코드는 이 저장소가 아니라 별도 picnic-supabase 저장소에 있습니다. 앱 저장소 안의 supabase/ 사본만 보고 판단하면 발송처를 찾지 못해 서버 결함으로 오진하게 됩니다.

같은 구조로 notify-my-artist-vote-start도 동일한 형식을 보냅니다.

앱 결함 4건

1. 콜드 스타트 탭이 콜백 설치 전에 소비돼 버려졌다

앱이 포그라운드로 올라올 때마다 호출되는 PushTokenService.resume()이, 초기화가 탭 콜백을 설치하기 전에 coordinator를 만들었습니다. 구독을 설치하면 1회성인 getInitialMessage()가 소비되는데, 이때 콜백이 없으면 목적지를 로그만 남기고 버렸습니다. 복구 수단이 없어 사용자는 초기화면에 남았습니다.

수정 재개 경로는 지연 생성을 유지합니다. 백그라운드 초기화에 도달하지 못한 프로세스에서는 이것이 유일한 복구 경로이기 때문입니다. 대신 콜백 없이 도착한 목적지를 상한이 있는 보류 큐에 담고, 초기화가 콜백을 설치한 직후 한 번만 배출합니다.

2. 포털 전환이 스택을 홈으로 초기화했다

투표 딥링크가 이미 투표 포털에 있어도 포털 전환을 호출했고, 이 함수는 항상 스택을 홈 페이지부터 다시 만듭니다. 그 홈 페이지가 제보된 초기화면입니다. 상세 페이지는 그 뒤 프레임 콜백에서야 얹혔습니다. 공지 딥링크는 스택을 유지하는 다른 경로를 써서 무사했습니다.

수정 포털 전환 여부를 순수 함수로 판단합니다. 링크가 현재 포털을 가리키면 전환 없이 바로 얹고, 다른 포털이면 전환과 얹기를 같은 턴에 처리해 홈 페이지가 단독으로 보이지 않게 했습니다.

3. 프레임 콜백이 프레임을 요청하지 않았다

Flutter의 프레임 후 콜백은 등록만 할 뿐 프레임을 요청하지 않습니다. 콜백 목록을 배출하는 도중 등록된 콜백은 아무도 요청하지 않은 다음 프레임으로 밀립니다. 탭 경로에 이런 콜백이 두 겹 중첩돼 있어서, 앱이 멈춰 있으면 이동이 무관한 사용자 입력을 기다렸습니다.

수정 중첩을 없애고 소유권을 검사하는 단일 dispatch로 바꿨습니다. 콜백 등록 뒤 프레임을 명시적으로 요청합니다.

4. 종료 상태의 로컬 알림 탭은 목적지 자체가 없었다

앱이 실행 중이 아닐 때 탭한 로컬 알림은 FCM이 아니라 플러그인의 실행 상세 조회로 전달되는데, 이 조회가 앱 전체에 없었습니다.

수정 초기화에서 프로세스당 한 번 읽습니다. 읽기에 성공한 뒤에만 소비 플래그를 세워, 예외가 난 읽기는 다시 시도할 수 있게 했습니다. 또한 이 읽기를 coordinator 초기화 뒤가 아니라 나란히 시작합니다. coordinator의 권한 단계는 사용자 입력을 무한정 기다릴 수 있는 OS 시트이기 때문입니다.

부수적으로 서비스가 payload 생성과 URL 추출을 헬퍼에 위임해 알림 왕복의 양쪽이 하나의 정의를 공유하도록 했고, 투표 딥링크가 0 이하의 ID를 거부합니다.

테스트가 실제 배선을 탄다

초기 구현의 테스트는 디버그 훅을 직접 호출해 진짜 경로를 우회했고, 리뷰어가 이를 지적했습니다. 최종 테스트는 플랫폼 채널만 가짜로 두고 실제 배선을 통과합니다. 원격 경로는 최초 메시지 조회와 열림 이벤트를, 로컬 경로는 실제 실행 상세 조회와 프로덕션 응답 핸들러를 거쳐, 양쪽 모두 렌더된 투표 상세 페이지 도달을 확인합니다.

교차 공급자 적대적 리뷰

계획은 Astra, 구현은 Opus, 리뷰는 Sol이 맡아 구현자와 리뷰어가 서로 다른 공급자가 되게 했습니다. 리뷰어에게는 구현자의 사고 과정을 전달하지 않고 요구사항과 변경 내용만 제공했습니다.

리뷰가 잡아낸 것 중 셋은 실제 사용자 영향이 있는 결함이었습니다. 특히 프레임 미요청 문제는 원래 고치려던 증상이 다른 경로로 그대로 남아 있던 경우이고, launch 읽기 직렬화는 권한 시트를 기다리는 동안 사용자가 초기화면에 머무는 같은 증상을 만들었습니다.

구현자가 리뷰 지적 하나를 근거를 들어 반박한 사례도 있습니다. 정규식이 결함이라는 초기 지적에 대해 Dart raw string이라 정상 동작한다고 반박했고, 이것이 맞았습니다.

배포 판단

Dart 전용 변경입니다. 네이티브, pubspec, 에셋, 서버를 전혀 건드리지 않았고 버전은 1.3.4+130403 그대로입니다. 따라서 OTA 범위를 유지합니다. 실행 상세 조회는 이미 번들된 플러그인의 기존 네이티브 핸들러를 쓰므로 신규 빌드가 필요하지 않습니다.

다만 이번 검증은 위젯 테스트 수준입니다. 실기기에서 백그라운드 탭, 종료 상태 탭, 포그라운드 로컬 알림 탭, 로컬 알림을 남긴 채 종료 후 탭을 iOS와 Android 각각 확인하는 것은 별도입니다. 배포 실행과 버전 결정은 이 문서의 범위가 아닙니다.
