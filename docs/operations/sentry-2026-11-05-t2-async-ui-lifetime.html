화면 이탈·계정 전환 후 비동기 UI 동작 차단

구현·호스트 검증·독립 코드 리뷰 완료.

화면이 사라지거나 요청을 시작한 계정이 바뀌면, 늦게 끝난 작업이 화면의 ref를 읽거나 이전 요청으로 이동·다이얼로그·로그아웃을 실행하지 않도록 수정했다. 계정 A→B→A 전환과 이미 큐에 들어간 인증 이벤트도 회귀 테스트로 확인했다.

조정자가 최종 소스에서 직접 실행한 집중 테스트는 55개 통과, 기존 1개 건너뜀이다. 변경한 5개 파일의 정적 분석은 문제없으며, 독립 리뷰 결과는 APPROVE다.

이 결과는 소스와 합성 호스트 테스트에 관한 것이다. 수정본 배포, 실제 기기의 타이밍, Sentry 오류 재발·소멸은 확인하지 않았다. Sentry와 Jira 상태는 변경하지 않았다.

변경한 동작

상황수정 후 동작유지한 동작
상점 새로고침 중 화면 이탈지갑 조회가 끝난 뒤 화면 생존 여부를 먼저 확인한다. 폐기된 WidgetRef를 읽거나 프로모션을 갱신하지 않는다.지갑이 소유한 조회는 끝까지 진행한다. onRefresh의 Future<void> 계약을 유지한다.
프로필 조회 중 화면 이탈·로그아웃·계정 전환탈퇴 확인 함수가 true를 반환해 호출자의 후속 동작을 중단한다. 캐시 읽기, 다이얼로그와 로그아웃을 실행하지 않는다.살아 있는 같은 계정의 정상 조회와 탈퇴 차단을 유지한다.
탈퇴 안내가 열린 뒤 계정 변경이전 다이얼로그의 확인 버튼이 이후 로그인한 계정을 로그아웃하지 않는다. 다이얼로그는 즉시 닫는다.logoutUser=false와 기존 ProviderContainer 기반 콜백을 유지한다.
A→B→A 전환 후 원래 작업 완료최종 사용자 ID뿐 아니라 관측한 계정 전환 횟수를 검사해 이전 UI 작업을 무효화한다.같은 계정의 토큰 갱신은 계정 전환으로 세지 않는다. 이후 새로 시작한 새로고침은 정상 동작한다.
Session은 바뀌었지만 인증 이벤트 전달이 대기 중한 프레임의 끝을 기다린 뒤 화면·컨테이너 수명과 요청 소유자를 다시 확인한다.같은 계정의 새 Session 및 토큰 갱신을 일괄 차단하지 않는다.

탈퇴 확인은 await 전에 ProviderContainer와 인증 소유자를 포착한다. 컨테이너당 한 인증 구독을 사용하고, 컨테이너 폐기 시 구독을 해제한다. 상점의 인증 구독은 State 수명에 속한다. Session 객체는 동일성 비교에만 사용하며 내용은 읽거나 기록하지 않는다.

알려진 현재 계정과 ID가 다른 캐시 프로필은 사용하지 않는다. 다만 화면이 살아 있고 같은 계정인데 프로필 조회 실패와 캐시 없음이 겹치는 기존 false 반환은 유지했다. 이 경우까지 기능을 차단할지는 별도 제품 결정이다.

영구 회귀 테스트

  • 지갑 조회 완료 전 화면 이탈과 계정 전환을 검사한다. 프로모션 갱신을 생략하면서 지갑 조회 완료와 정상 새로고침을 유지한다.
  • 프로필 조회의 null·예외 응답 이후 화면 이탈, 로그아웃, 계정 전환을 검사한다. 정상 탈퇴 차단, 외부 계정 캐시 배제와 조회 실패·캐시 없음의 기존 반환값을 함께 확인한다.
  • 실제 TopRightPost 연필 콜백이 오래된 조회 결과로 PostWritePage를 열지 않는지 확인한다.
  • 전달된 A→B→A와 대기 중인 A→B→A를 검사한다. 실제 다이얼로그 확인 콜백, 프로필 조회 후속 동작과 상점 새로고침을 사용한다.
  • 같은 계정의 토큰 갱신·새 Session을 허용하는 대조군을 둔다. 지연 확인 중 ProviderScope·상점 폐기와 컨테이너별 구독 정리도 검사한다.

리뷰에서 확인한 반례

첫 보완 전에는 사용자 ID가 원래 값으로 돌아오면 오래된 작업이 다시 유효해졌다. 조정자의 합성 반례 3개는 실제 글쓰기 화면 이동, 이전 다이얼로그의 로그아웃, 두 프로모션의 불필요한 갱신을 재현했다. 같은 계정 갱신 대조군 2개는 통과했다.

관측된 계정 전환 횟수를 추가한 뒤에는 지갑 완료가 인증 이벤트보다 먼저 처리되는 별도 반례를 검사했다. 대기 중인 A→B→A에서 로그아웃 1회와 프로모션 재빌드가 발생했고, 같은 계정 대조군 2개는 통과했다. Session 동일성 검사와 프레임 후 재검사로 이를 보완했으며, 해당 반례를 영구 테스트에 포함했다. 최종 독립 재검토에서 두 P2 지적이 해결된 것으로 승인됐다.

이 반례는 호스트 테스트에서 콜백 순서를 의도적으로 구성한 결과다. 운영체제 포인터 이벤트나 실제 기기·Sentry에서 같은 타이밍이 관측됐다는 뜻은 아니다.

남은 확인과 적용 범위

한 프레임 대기는 이미 큐에 들어간 인증 알림을 처리하기 위한 경계다. 이후 저장소·네트워크 작업이 끝난 뒤 새로 발생할 인증 이벤트까지 보장하지 않는다. 앱이 백그라운드여서 프레임이 중단되면 지연 확인은 앱 복귀 후 끝날 수 있다.

  • 제품 호출자 중 TopRightPost를 직접 검사했고, 관련 투표/JMA 테스트 결과도 확인했다. 모든 탈퇴 확인 호출자를 개별적으로 실행한 것은 아니다.
  • 테스트는 합성 인증과 데이터 응답을 사용했다. 실제 로그인·로그아웃, 기기 타이밍과 운영 데이터는 이번 검증 대상이 아니다.
  • 배포 후 해당 Sentry 오류의 재발 여부는 기존 계획의 배포·효과 측정 단계에서 확인해야 한다. 이번 결과만으로 이슈 해결이나 QA 승인을 선언하지 않는다.
원시 테스트 로그와 합성 반례 자료는 비공개 QA 증거로 보관한다. 이 보고서는 재현 명령, 결과, 검증 대상 해시와 한계를 기록한다. T3 이후 작업 상태는 변경하지 않았다.
