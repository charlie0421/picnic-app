T4-B · Branch 공유 링크 실패 복구 (PICNIC-APP-5N6)

2026-11-06 · 기준 커밋 8964f9926 · 수정 커밋 e5a90d03d, 4d6c551d4, 4447e9427 · 작업 브랜치 docs/sentry-release-analysis

소스 수정·호스트 검증·독립 리뷰 완료. 조정자가 직접 실행한 집중 테스트 25개와 영향 테스트 35파일 2384개가 통과했다. 첫 리뷰는 P2 1건으로 CHANGES_REQUIRED였다. 수정 후 같은 리뷰어의 재검증은 APPROVE다. 실제 기기·실제 Branch API·실제 네트워크 장애는 검증하지 않았다.

문제와 원인

5N6의 최신 이벤트(2026-10-30, 릴리스 1.3.5+130504, Android 16)는 Exception: Failed to create Branch link다. 앱 프레임은 home_featured_vote_card.dart의 _handleShareToTwitter → deeplink.dart의 createBranchLink다. 누적 이벤트는 2건, 사용자는 2명이다.

  • createBranchLink는 Branch가 200이 아닌 응답을 주면 예외를 던졌다. 요청 시간 제한도 없었다.
  • 공유 화면 6곳이 ShareUtils.shareToSocial의 인자를 만드는 중에 이 함수를 await했다. 그래서 링크 생성이 실패하면 공유 시트가 열리지 않았다. 사용자에게 안내도 없었다. 예외는 zone 오류 처리로 넘어가 Sentry에 기록됐다.
  • 계획서의 T4 파일 목록에 있던 branch_link_service.dart와 share_section.dart는 이 경로가 아니다. 앞의 것은 수신 링크를 처리하고, 뒤의 것은 버튼 UI다. 이 정정은 커밋 8964f9926에서 계획서에 기록했다.

변경 결과

경계변경 결과
링크 생성 실패createBranchLink는 서명을 유지한다. 200이 아닌 응답은 BranchLinkFailure(httpStatus)로 던진다. JSON이 아니거나 url이 없거나 host가 있는 https 링크가 아니면 BranchLinkFailure(invalidResponse)로 던진다.
공유 계속새 createShareLink는 Branch 링크 또는 null을 돌려준다. null이면 shareToSocial가 기존 설정값 Environment.downloadLink를 쓰고 공유를 계속한다. 새 URL을 하드코딩하지 않았다.
시간 제한링크는 최대 10초 기다린다. 이 값은 실제 Branch 지연 시간으로 측정한 값이 아니다.
통신 실패http.ClientException과 모든 IOException(SocketException, TLS HandshakeException 포함)을 통신 실패로 분류한다. IOClient는 HandshakeException을 감싸지 않으므로 별도로 처리해야 했다.
예상 밖 오류위 분류에 없는 오류는 결함으로 보고 다시 던진다. 보고 함수가 실패해도 공유는 계속한다.
시간 제한 뒤 늦은 완료Future.timeout은 늦은 결과를 버린다. 그래서 자체 시간 제한이 난 경우에만 요청을 계속 지켜본다. 늦은 예상 밖 오류는 그 요청이 실행된 zone의 미처리 오류 경로로 보낸다. 앱에서는 이 경로가 Sentry 보고로 이어진다. 늦은 HTTP 상태 오류와 잘못된 응답은 실패 보고로 보낸다. 늦은 링크와 늦은 통신 실패는 무시한다. 공유는 이미 다운로드 링크로 진행됐다.
호출부6곳(home_featured_vote_card.dart, vote_info_card.dart, vote_detail_page.dart, voting_complete.dart, fortune_dialog.dart, goonghap_result_page.dart)이 createShareLink를 쓴다. 각 파일의 변경은 식별자 1개다.

Sentry 보고 정책

  • 보고 내용은 닫힌 값만 쓴다. 실패 종류와 HTTP 상태(100–599)만 넣는다. 제목·목적지 URL·Branch 키·응답 본문은 보고 텍스트·태그·fingerprint에 넣지 않는다.
  • Sentry에는 Branch 응답 이상(httpStatus, invalidResponse)만 warning으로 보낸다. 태그는 branch_link_failure_kind, branch_link_status, fingerprint는 ['branch-share-link-failure', kind]다.
  • 통신 실패와 시간 제한은 로그에만 남긴다. 앱의 beforeSend가 다른 경로의 같은 오류(ClientException, SocketException, HandshakeException, 감싼 timeout)를 사용자 네트워크 노이즈로 버리는 규칙과 같다.
  • 새 fingerprint를 쓰므로, 이 수정이 배포된 뒤에는 5N6에 새 이벤트가 쌓이지 않고 새 이슈로 묶인다. T9 효과 측정에서는 두 이슈를 함께 본다.
  • 이 보고를 위한 별도 beforeSend 정제는 추가하지 않았다. 리뷰어는 스크린샷·view hierarchy 첨부 설정을 찾지 못했다.

한계와 남은 확인

  • 대체 링크는 콘텐츠별 링크가 아니라 다운로드 페이지다. 재시도 UI는 추가하지 않았다.
  • 링크를 기다리는 최대 10초 동안 로딩 표시가 없다. 로딩 표시(onStart)는 링크를 받은 뒤 shareToSocial 안에서 시작한다. 이 시간에 버튼을 다시 누를 수 있는 문제는 수정 전부터 있었고, 이번에 바꾸지 않았다.
  • 실제 기기, 실제 Branch API, 실제 네트워크 장애에서는 검증하지 않았다. 호출부 구조 가드는 실제 화면의 공유 실행 테스트를 대신하지 않는다.
  • 통합 빌드 QA 후보: 6개 공유 진입점에서 정상 공유가 Branch 링크로 열리는지 확인한다. 네트워크를 끊은 상태에서 공유 시트가 다운로드 링크로 열리는지 확인한다. 운영 Branch에 실패를 강제하는 조작은 하지 않는다.
