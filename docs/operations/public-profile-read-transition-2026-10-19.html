공개 프로필 앱 조회 전환

2026-10-19 · picnic-app · 기준 커밋 601d48efda0a5f24fb71068af174276655162d6f

게시글·댓글의 공개 작성자 조회 7곳을 user_profiles_public 뷰로 전환했다. 앱 관련 테스트 255개와 별도 DB 검증 72개가 통과했다. 독립 코드 리뷰에서 이 변경의 병합을 막는 신규 문제는 없었다. 앱 배포와 운영 RLS 활성화는 이번 변경에 포함하지 않는다.

변경 범위

운영 DB의 공개 뷰는 picnic-supabase PR #243에서 먼저 추가됐다. 뷰의 공개 열은 id, nickname, avatar_url, created_at, updated_at, deleted_at이다. 이번 앱 변경은 각 조회의 기존 열 목록과 JSON 별칭을 유지한다.

조회변경한 관계와 별칭
아티스트별·게시판별·검색 게시글, 게시글 상세: 4곳user_profiles:user_profiles_public!posts_user_id_fkey(...)
댓글·대댓글: 2곳user_profiles:user_profiles_public!comments_user_id_fkey(...)
내 댓글: 1곳user:user_profiles_public!comments_user_id_fkey(...)
  • 수정 파일: picnic_lib/lib/presentation/providers/community/post_provider.dart, comments_provider.dart. 소스 변경은 조회 문자열 7개다.
  • 호출처가 없는 picnic_lib/lib/presentation/widgets/community/common/post_list_provider.dart를 삭제했다. 이 파일은 원본 프로필의 모든 열을 읽었다. 삭제 전 저장소 전체에서 참조가 없음을 확인했다.
  • 본인 글·스크랩은 호출 화면에서 supabase.auth.currentUser!.id를 전달한다. 해당 조회와 프로필 모델, 필터, 페이지 처리, 조회수 RPC는 유지했다.

배포와 RLS에 남은 조건

  1. 배포 경로 확정. picnic_app/pubspec.yaml은 1.3.6+130601이다. 2026-10-19 17:12 KST에 해당 앱의 Shorebird 릴리스 193개를 조회했으나 이 버전은 없었다. 목록의 최신 릴리스는 1.3.5+130504이며 iOS·Android가 active다. 따라서 기존 인계 문서의 현재 버전 OTA 절차를 그대로 실행할 수 없다. 이전 버전에 main을 임의로 패치하지 않는다. 새 바이너리 배포 준비 또는 별도 구버전 패치 범위를 먼저 확정해야 한다.
  2. 배포 승인과 실환경 확인. 배포할 앱·전체 버전·플랫폼·커밋을 확정한 뒤 승인을 받는다. 로그인·비로그인 상태의 다른 작성자 게시글·댓글·대댓글과 본인 프로필을 실제 환경에서 확인한다. 새 앱이 뷰를 사용하기 시작하면 뷰를 삭제하는 기존 사전 소비자 롤백을 실행하지 않는다.
  3. RLS 정책 검증. 이 테스트의 본인 행 정책은 검증용이다. 운영에 잠복한 기존 정책을 그대로 켜면 재귀 오류가 발생할 수 있다. 최신 정책 교체안, 기존 앱 호출 관측, pocapop·picnic-web·관리자·Edge·Realtime 소비자 확인이 별도로 필요하다. 운영 RLS는 변경하지 않았다.

리뷰에서 확인한 기존 문제

다음 두 문제는 기준 커밋에도 존재한다. 이번 조회 전환의 신규 회귀는 아니며, 별도 변경과 회귀 테스트가 필요하다.

  • P2 · 댓글 차단. comments_provider.dart의 루트·대댓글 조회에 최상위 user_id가 없다. 따라서 comment.userId가 null이고 comments_provider_helper.dart의 차단 사용자 필터가 작성자를 비교하지 못한다. 조회 열에 user_id를 추가하고 실제 응답 형태로 차단을 테스트해야 한다. 대댓글까지 완전히 차단하려면 자식 목록 필터도 필요하다.
  • P3 · 내 댓글 작성자. 내 댓글 조회는 작성자를 user로 받지만 CommentModel은 user_profiles를 읽으므로 CommentModel.user는 null이다. 별칭 또는 파서를 별도 변경에서 맞춰야 한다. 이번 테스트에는 현재 동작을 명시했다.

근거

  • 원래 공개 프로필 인계 문서: 5.2절 앱 변경 범위. 이후 진행 상황은 아래 대조 문서를 우선한다.
  • RLS 준비 브랜치와 현재 상태 대조: 공개 뷰 운영 반영 및 남은 RLS 단계.
  • Supabase Dart select 문서: 뷰 조회와 응답 별칭.
