2. 아키텍처에서 반드시 지켜야 하는 불변식

  1. 미확정 스토어 트랜잭션은 절대 finish/consume 하지 않는다. 서버가 지급을 확정(grantConfirmed/정산 결과)했을 때만 종료한다. 과거에 이 규칙을 깨서 캔디 손실 + Android 3일 자동환불 경로 소멸이 동시에 일어났다.
  2. 서버가 authoritative. 클라이언트는 영수증을 전달할 뿐, 금액·환경·지급 여부를 주장하지 않는다.
  3. 인박스는 멱등, 터미널 행은 불변. 같은 구매의 재전송은 replay로 응답한다(신원 컬럼 비교). StoreKit 은 재전달마다 JWS 를 재서명하므로 페이로드 해시로 동일성을 판단하면 안 된다.
  4. 422 = 영구 거부, 503 = 재시도 가능. 클라이언트 큐는 200 또는 422 에서만 항목을 제거한다.
  5. 레거시 경로는 1b 전까지 손대지 않는다. user_profiles·star_candy_% 직접 쓰기 권한, 레거시 RPC 실행권, 레거시 트리거는 1b 세트에 있다.

3.2 프로덕션 앱 릴리스

버전은 picnic_app/pubspec.yaml 의 version: 이 결정하고, picnic-v* 태그 푸시가 곧 릴리스 트리거다(Codemagic 이 태그 패턴으로 타깃을 유도). 릴리스 가드는 Option B 로 단순화돼 있어 릴리스마다 넣는 값이 없다 — picnic_env 그룹의 정적 마커 3개만 유지하면 된다.

CI_PROVIDER=codemagic
PRODUCTION_RELEASE_EVENT=production-release
ENVIRONMENT=prod

가드가 확인하는 것: 진짜 Codemagic 프로덕션 레인 · 클린 체크아웃 · CM_TAG 가 가리키는 커밋 = HEAD = main 에 포함. UI 수동 빌드는 CM_TAG 가 없어 설계상 차단된다.

4. 반드시 알고 있어야 할 함정

  • Edge 런타임: node:crypto X509Certificate.checkIssued/.verify 미구현. 애플 체인 검증은 WebCrypto+DER 파서 구현 — 되돌리면 전 애플 정산 사망.
  • 함수 배포: 크론 전용 함수는 반드시 --no-verify-jwt. 빠뜨리면 게이트웨이 401 로 정산 레인 전체가 죽는다. Docker 번들링이 실패하면 --use-api 로 우회.
  • Vault ops 시드: wallet_worker_attestation_secret 는 어떤 마이그레이션에도 없다. 엣지 env WALLET_WORKER_ATTESTATION_SECRET 와 같은 값이어야 하며, 없으면 전 구매가 재시도 가능 실패로 조용히 적체된다(실제 사고).
  • 로컬 리허설: baseline 스키마에 프로덕션 URL 이 박힌 DB 웹훅 트리거가 있다(alarm-receipt on receipts 등). db reset 직후 tgfoid='supabase_functions.http_request'::regproc 인 트리거를 전부 드롭하지 않으면 로컬 픽스처가 실제 Slack 알림을 쏜다.
  • 레포 위생: picnic-app 메인 폴더의 로컬 main 이 뒤처져 있을 수 있다 — 작업 전 git fetch 후 origin/main 기준으로 워크트리를 만들 것.
  • SQL 스위트: 프로덕션형 상태에서만 유효한 테스트가 있고, 스위트가 커밋된 픽스처를 남겨 연속 2회 실행 시 일부가 실패한다(사전 존재 특성). 판단 전 db reset.

select
  (select count(*) from public.wallet_provider_event_inbox
     where status not in ('SUCCEEDED','DEAD'))                        as inbox_open,
  (select count(*) from public.ops_alerts where resolved_at is null)   as alerts_open,
  (select json_agg(json_build_object('k',flag_key,'v',value_json) order by flag_key)
     from public.wallet_runtime_flags)                                 as flags,
  (select json_agg(jobname order by jobname) from cron.job
     where jobname like 'wallet%')                                     as crons;
