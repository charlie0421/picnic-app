완료한 앱 변경

새 앱의 시작·복귀·인증 경로에서는 list_unacknowledged_ad_rewards와 과거 기록의 getStatus 호출이 0회다. 현재 시청한 광고의 최대 6회 확인 및 1/2/4/8/15초 지연, 결과 안내·ACK는 유지한다. ACK는 안내 완료 기록이며 실제 지급은 서버가 수행한다.

복귀 시 이미 읽은 지갑 잔액만 갱신한다. 겹친 요청은 합치고 성공 후 60초 제한, 6초 읽기 상한을 적용한다. 계정 전환·로그아웃·A→B→A의 늦은 응답을 버리며 더 최신 잔액을 보존한다.

일반 사용자도 마이페이지에서 이용 내역을 열 수 있다. 선택한 재화만 조회하고 명시적 다음 페이지·새로고침·재시도를 제공한다. 첫 페이지/다음 페이지 읽기 상한 6초, 자동 재시도 없음. 인증 사용자와 화면 사용자가 다르면 내역을 숨기고 내부 원장 메타데이터는 표시하지 않는다.

앱이 서버의 양수 GRANTED를 관측하면 팝업 표시와 독립적으로 durable analytics outbox에 기록한다. 광고 화면이 먼저 닫힌 뒤 응답이 와도 notifier를 미리 확보해 기록·현재 광고 확인이 지속된다. 중복 이벤트는 동일 reference로 합친다.

기기 내 UI 복구 메타데이터는 사용자별 다음 저장 시 최근 100건으로 제한한다. 서버 지급 내역·원장·잔액 데이터는 변경하지 않는다. 과거 팝업 재표시 및 과거 ACK 자동 재시도는 제거한다.

다음 작업 / 완료 조건

릴리스 전 기존 코드 생성/테스트 문제를 정리하거나 현행 CI에서 영향 범위를 확인하고, 현재 광고·화면 닫기·계정 전환·잔액·내역을 기기에서 검증한다.

앱 병합·배포는 별도 승인과 현행 Flutter 릴리스 정책에 따라 진행한다. 버전/빌드 번호는 실행 시점에 다시 결정한다. 이번 작업에서 버전 변경, 빌드, OTA, 앱 배포, 서버 추가 배포는 수행하지 않았다.

배포 후 앱 버전 도입률과 함께 list/status/wallet/history 호출률, RPC 지연·오류, 광고 결과 확인 실패, 서버 원장 지급을 비교한다. 새 앱의 자동 목록 조회가 제거됐어도 구버전의 호출은 남으므로 PICNIC-2637은 계속 관리한다. 앱 배포 전 CPU 개선 수치를 이번 앱 변경 효과로 주장하지 않는다.

앱이 종료된 뒤 서버에서만 완료된 지급은 앱 통계의 보장 범위 밖이며 서버 원장이 기준이다. logical timeout은 전송 자체 취소가 아니다. 양 플랫폼 배포 결과와 운영 검증 근거를 기록한 뒤 완료 처리한다.

서버 조치와 앱 변경의 효과 구분

이미 운영 적용한 조치는 cotton_candy_grants 통계 갱신과 자동 분석 임계값 조정이다. 09/08 18:08 KST까지 확보한 서버 단독 측정에서 get_ad_reward_status 평균은 약 37.709ms → 1.142ms로 감소했다. 같은 2XL의 서로 다른 비교 구간 CPU 평균은 약 33.8% → 14.0%였다. 트래픽과 배치 차이가 있으므로 CPU 감소 전체를 해당 조치의 순수 효과로 단정하지 않는다.

이번 앱 변경은 서버에 요청하는 횟수를 줄인다. 아직 배포하지 않았으므로 위 서버 측정에 이번 앱 변경의 효과는 포함되지 않는다. 배포 후에는 새 버전 도입률과 목록·상태·잔액·내역 호출률을 함께 비교해야 한다. 2XL에서 XL로 복귀할지는 자정·피크 검증 후 판단한다.

보상 데이터와 앱 통계의 범위는 다르다. 앱 종료 뒤 서버에서만 확정된 지급은 서버 원장에 존재하더라도 앱 관측 기반 GA4 이벤트에는 없을 수 있다. 실제 지급의 기준은 서버 원장이다. 구버전 목록 RPC는 계속 호환되어야 한다.
