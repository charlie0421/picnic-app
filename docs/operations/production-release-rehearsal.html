Production 릴리스 게이트 리허설

2026-07-27 · 실제 태그 푸시·Codemagic 실행 없이 로컬에서 전체 게이트를 시뮬레이션. 리허설 기준 커밋: d422673e0 (태그 picnic-staging-v1.2.39+123902 가 가리키는, main 에 포함된 커밋).

결론: production 경로는 설계대로 fail-closed 로 동작한다. 증거가 하나라도 빠지면 각기 다른 정확한 사유로 NO-GO, 완전한 증거 세트에서만 GO. 변조(매니페스트·SHA·더러운 체크아웃)는 전부 감지된다.

1. 태그 → 배포 타깃 파생 (codemagic.yaml)

CM_TAG결과
picnic-v9.9.9+99999DEPLOY_TARGET=production
picnic-staging-v9.9.9+1DEPLOY_TARGET=staging
picnic-v1 (경계)DEPLOY_TARGET=production
release-1.0 (비규격)거부 — "maps to no deploy target", 빌드 중단
picnic-v 로 시작하기만 하면 무엇이든 production 이다 (picnic-v1 포함). 태그 이름 규율이 곧 배포 규율이므로, production 태그는 반드시 picnic-vX.Y.Z+BUILD 형식만 쓸 것.

2. NO-GO 사다리 — 증거가 부족하면 어디서 멈추는가

제공한 것결과
(없음)NO-GO: protected production runner required
+ CI_PROVIDER, PRODUCTION_RELEASE_EVENTNO-GO: production environment required
+ ENVIRONMENT=prodNO-GO: exact release SHA mismatch
+ RELEASE_SHA, RELEASE_TAGNO-GO: approval reference missing
+ RELEASE_APPROVAL_REFERENCENO-GO: release manifest checksum mismatch
+ 매니페스트 + 체크섬 + 증거 2종GO: protected production target verified

3. 변조 감지

시나리오결과
체크섬 등록 후 매니페스트 내용 변조NO-GO: release manifest checksum mismatch
RELEASE_SHA ≠ 체크아웃된 HEADNO-GO: exact release SHA mismatch
체크아웃에 임의 파일 추가 (더러운 트리)NO-GO: checkout must be clean
main 에 없는 커밋의 태그가드 유닛 테스트로 고정 — "an off-main commit is never releasable, however well attested" (test/config/release_target_test.dart, 15/15 통과). e2e 재현은 불가: 그 시절 커밋 트리에는 게이트 스크립트가 아직 없다.
변조 시나리오 후 정상 세트 재실행GO (게이트 상태 오염 없음)

4. 릴리스 당일 체크리스트

production 태그를 푸시하기 전에 Codemagic 워크플로 환경에 아래가 모두 준비되어야 한다. 하나라도 빠지면 위 사다리의 해당 지점에서 빌드가 멈춘다 (의도된 동작).

환경변수값
CI_PROVIDERcodemagic
PRODUCTION_RELEASE_EVENTproduction-release
ENVIRONMENTprod
RELEASE_SHA릴리스할 커밋의 전체 SHA. 태그가 가리키는 커밋과 같아야 한다
RELEASE_TAG푸시한 태그 이름 (picnic-vX.Y.Z+BUILD). CM_TAG 와 동일해야 정합
RELEASE_APPROVAL_REFERENCE승인 근거 (PR 번호, 결재 링크 등 — 비어있지만 않으면 됨)
RELEASE_MANIFEST릴리스 매니페스트 파일 경로 (러너에서 접근 가능해야 함)
RELEASE_MANIFEST_SHA256shasum -a 256 <매니페스트> 결과
ENVIRONMENT_ISOLATION_EVIDENCEcomplete
SECURITY_EVIDENCEcomplete

그 외 전제: 태그 커밋이 main 에 머지되어 있을 것 (tip 일 필요는 없음 — ancestry 판정), 러너 체크아웃이 깨끗할 것, 개발자 스크립트 8종이 존재하고 unsafe 명령이 없을 것.

5. 이번 리허설로 검증되지 않은 것

  • 실제 Codemagic production 워크플로 실행 — 태그 파생·게이트 스크립트는 staging 빌드 (picnic-staging-v1.2.39+123902) 에서 실전 검증됐지만, production 분기(署名·Shorebird release·스토어 업로드)는 실제 태그로만 확인 가능.
  • Codemagic 쪽 환경변수 그룹에 위 체크리스트 값들이 실제로 설정돼 있는지 — 대시보드에서 확인 필요.
