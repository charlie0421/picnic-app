3. TDD 및 추가 테스트

신규 파일 voting_dialog_submit_label_test.dart에 기존 측정 하네스와 같은 7개 로케일 × 3개 배율의 운영 VotingDialog 테스트 21개와, 매우 좁은 라벨 슬롯의 2줄 상한 스트레스 테스트 1개를 추가했다.

  • 1단 운영 경로인지 확인한다.
  • 버튼이 예전 172 토큰보다 넓되 조작부 폭을 넘지 않는지 확인한다.
  • 버튼 사각형이 실제 캡슐 RRect를 침범하지 않는 성질을 확인한다.
  • 렌더 라벨이 최대 2줄이고, 말줄임 여부가 실측 가능한지 확인한다.
  • preferredHeight(maxWidth: 실제 버튼 폭)과 실제 렌더 높이가 같은지 확인한다.

최초 RED: 부모 프로덕션 코드에서 신규 22개가 모두 실패했다(+0 -22). 21개 매트릭스는 122.54px 고정 폭을, 스트레스 케이스는 무제한 7줄·370.28px 높이를 잡았다.

하네스 교정: 스트레스 위젯을 폭만 제한한 Align 아래에서 곧바로 재면 480px 뷰포트 높이를 읽는 함정이 있었다. Column(mainAxisSize: min)으로 내재 높이를 재도록 고쳤다. 이는 PICNIC-2697에서 반복된 “재는 층과 그려지는 층 불일치”와 같은 종류다.

코너 회귀 발견: 최초 폭 확장 뒤 신규 22개는 통과했지만 전체 투표 스위트가 캡슐 모서리 침범 68건을 찾아냈다. 실제 반경 기반 안전 폭을 적용한 뒤에도 AlertDialog 제약과 카드 실폭이 11.399px 달라 3.25px 호 침범이 남았고, 카드 실폭을 단일 기준으로 통일해 제거했다.

되돌림 검증: 최종 프로덕션에서 폭·2줄 정책을 부모 동작으로 일시 되돌린 뒤 신규 테스트가 RED인지 확인하고 원복했다. 최종 수치는 검증 절에 기록한다.

5. JMA 처리 선택지

JMA Dart 구현은 이번 티켓에서 변경하지 않았다. 다만 공유 label_button_vote 번역 축약은 현재 태국어·미얀마어·일본어의 JMA 높이도 완화한다. 구조적으로는 여전히 무제한 줄이므로 새로 긴 번역이 들어오면 같은 결함이 재발할 수 있다.

  1. 후속 티켓에서 JMA도 같은 구조 보장: 활성 아이콘 폭 정책을 보존하면서 측정과 렌더에 같은 2줄 상한·말줄임을 적용하고 JMA 전용 기하 테스트를 추가한다. 권고안이다.
  2. 현재처럼 번역 완화만 유지: 당장 수치는 좋아지지만 미래 번역에 대한 보장은 없다.
  3. 172 계열 폭을 유지한 채 2줄만 제한: 현재 긴 문구가 잘리므로 배제한다.

JMA 영역 소유자가 범위를 승인하기 전에는 1안을 이번 변경에 섞지 않는다.

F2두 커밋이 독립적으로 되돌려지지 않는다수용 — 문서로 처리. 출하되는 조합에서는 잘리는 라벨이 없음을 14개 로케일로 확인했다. 되돌림 경로의 위험은 커밋 메시지·테스트 주석·PR·Jira 네 곳에 명시했다.
F3키보드가 열리면 버튼 폭이 변한다사실 확인 — 미수정, 결정 대기. 393×852 에서 293.2 → 225.6 (23% 감소). 버튼이 바닥에 가까워지면 코너 여유가 더 필요해지는 기하상 정직한 결과지만, 키보드 전환 중 기본 CTA 가 크기를 바꾸는 것은 별개 문제다.
F4요구사항을 넘어 CTA 를 재설계했다일부 수용 — 결정 대기. 아래 실측 참조. 2.0배까지는 고정 172 로도 잘림이 없고, 2.0배를 넘어서야 폭 확장이 실제로 필요해진다.
F5라우트 여백 예산의 보수성 방향이 뒤집혔다수용 — 미수정, 기록. 되돌리려면 제거한 두 번째 폭 기준을 되살려야 해 단일 기준 원칙과 충돌한다. 448 조합 실측에서 관측되지 않았고, 어긋나도 고정→스크롤로 완만히 저하한다.
F6테스트 축이 비어 있다수용 — 테스트 추가. 전 로케일·키보드·뷰포트 축을 여는 448건 회귀 테스트를 넣었고, 그 축이 실제로 F1 을 잡는다.

리뷰어가 근거와 함께 기각한 항목도 기록한다. 코너 여유 기하는 [0, R] 위에서 자기역원이라 원형 모서리에 대해 정확하고, 4회 반복 루프는 폭이 단조 감소하며 목표가 4개 상태의 함수라 발산·진동이 불가능하다. cardWidth 통일은 2단 경로가 이 코드에 도달하기 전에 반환하므로 안전하다. _expectsColumns 의 return 식은 부모와 바이트 단위로 동일해 회귀를 가릴 수 없다.

F4 판단 근거 — 고정 172 로 되돌리면 어디서 잘리는가

축약 번역 적용 후, 버튼 폭을 예전 고정값(140.1px 실폭)으로 두고 2줄 상한만 적용했을 때 14개 로케일의 말줄임 여부를 실측했다.

배율고정 172 에서의 결과
1.0 / 1.3전 로케일 1줄, 잘림 없음
2.0잘림 없음. fil·my·th·vi 가 2줄(110.3px)이 된다
2.6my·vi 말줄임. 나머지는 2줄(142.3px)

즉 폭 확장이 실제로 막아 주는 것은 2.0배를 넘는 배율의 버마어·베트남어 잘림이다. 베트남어는 이번에 축약하지 않은 로케일이라 번역만으로는 닫히지 않는다. 그 대가는 기본 393×852 한국어 화면에서 버튼이 140.1 에서 293.2 로 넓어져 가운데 알약이 거의 전폭 바가 되는 것, 그리고 F3 의 키보드 전환 시 크기 변화다.

이 맞바꿈은 엔지니어링이 아니라 디자인 결정이다. 되돌리는 비용은 낮다 — _buildFooter 가 넘기는 width 를 VotingSubmitButton.preferredWidth() 로 바꾸면 되고, 그러면 2.0배 이하에서는 잘림 없이 예전 모양이 돌아오며 2.6배의 버마어·베트남어만 말줄임된다. 제3안은 말줄임 대신 자동 축소(FittedBox)를 넣어 고정 폭을 유지하는 것이다.

9. 남은 위험과 확인사항

  • 세 축약 번역은 기하 검증과 별개로 원어민 의미·톤 검토가 필요하다.
  • JMA의 무제한 줄 구조는 남아 있다. 공유 번역 축약은 완화일 뿐 구조 보장이 아니다.
  • 일반 1단 잔액 라벨의 maxLines/ellipsis는 명시적으로 이번 범위 밖이며 별도 후속 후보다.
  • 실기기 폰트 폴백은 테스트 폰트와 글리프 폭이 다를 수 있으나, 최대 2줄 상한은 높이 폭주를 독립적으로 막는다.
  • CTA 폭 확장과 키보드 전환 시 크기 변화(F3·F4)는 디자인 확인이 필요하다. 8절의 실측과 되돌림 경로 참조.
  • 라우트 여백 예산의 보수성 방향 뒤집힘(F5)은 남겨 뒀다. 448 조합에서 관측되지 않았으나 구조적 보장은 아니다.
  • _expectsColumns는 번역 문자열 길이에 의존하는 정적 기대표다. 이번처럼 라벨이 바뀌면 함께 움직인다. 전환 자체를 성질로 검증하는 축은 아직 없다.
