PICNIC-2694 — 재검증 차단 지적 2건 대응

재검증 대상 77410c707 · 재검증 문서 docs/operations/picnic-2694-sol-recheck.html · 브랜치 fix/vote-dialog-short-viewport · 2026-09-15

결론: 새 차단 지적 2건 모두 수용, 실측으로 재현한 뒤 수정했다. 두 건 모두 리뷰어가 제시한 실패 조건을 실제 렌더 측정값으로 먼저 재현(RED)하고, 수정 후 통과를 확인하고, 각 수정을 따로 되돌려 다시 실패하는 것까지 확인했다. 2번은 리뷰어가 제시한 두 방향 중 “상태 간 높이를 같게 하는 폭 정책”을 골랐다 — 다른 방향(현재 렌더 상태의 실제 폭으로 재기)을 실제로 구현해 측정했더니 빈 입력→활성 전환에서 여백이 19px 점프하고 밴드 순서가 뒤집히는 시각 점프가 생겼기 때문이다(아래 2-3). 이 2건을 닫으면서 원 지적 2·3 의 부분 종결분도 함께 닫혔다.

1. [중간] 이동한 validation 밴드의 높이 예산이 실제 Row 보다 작다

수용 종결

1-1. 사실 확인 — 재현됨

리뷰어의 두 지적(아이콘 박스 최소 높이 누락, 가로 border 미차감) 모두 코드 구조상 사실이고, 앞의 것은 실제 렌더 측정으로 재현했다.

  • 렌더(_buildValidationMessage)는 Container(border 1, padding 12/8) 안에 Row 를 놓고, 그 왼쪽 자식은 padding: EdgeInsets.all(2) 에 Icon(size: 16) 이라 한 변 20 의 고정 박스다. Icon 의 applyTextScaling 은 기본 false 이고 레포 어디에도 지정이 없어 (grep applyTextScaling lib/ → 0건) 배율과 무관하게 20 이다.
  • 예산(_inputFeedbackHeight)은 문구 높이만 썼다. 1.0 배 한 줄은 12 × 1.45 ≒ 17.5 이라 아이콘 박스가 행 높이를 결정하고, 예산은 그만큼 작다.
  • BoxDecoration 의 border 는 안쪽 폭에서 좌우 1 씩 먼저 떼어 가는데 측정용 폭에서는 빼지 않았다. 현재 문자열·뷰포트 조합에서 줄 수가 바뀌는 지점은 찾지 못했지만, 상한이 아니라는 성질 자체가 결함이므로 함께 고쳤다.

1-3. 변경

picnic_lib/lib/presentation/widgets/vote/voting/jma_voting_dialog.dart

  • 밴드 높이 계산을 파일 최상위의 공개 함수 jmaValidationBandHeight() 로 뽑고 (폭은 jmaVoteDialogContentWidth()), 측정 폭에서 kJmaValidationBorderWidth * 2 를 빼고, 세로 본문을 math.max(kJmaValidationIconSide, 문구 높이) 로 바꿨다.

3. 원 지적 2·3 의 부분 종결분

원 지적재검증이 남긴 잔여분이번 결과근거
2. JMA 유효성 설명이 캡슐 밖에 위치 문구 이동·live region 은 종결. “새 높이 계산이 아이콘 최소 높이와 가로 border 를 빠뜨려 실제 높이의 상한이 아니다” 는 예산 측면 미종결 함께 종결 차단 지적 1 의 수정으로 jmaValidationBandHeight() 가 border 를 폭에서 빼고 아이콘 박스를 세로 하한으로 쓴다. 24개 조합에서 실제 ≤ 예산 을 직접 단언하고, 경계 부모 높이 스윕으로 모드 오판이 사라진 것까지 확인했다.
3. 활성 JMA 버튼 라벨 폭 과소 예산 활성 overflow 는 종결. “활성 폭을 비활성에도 무조건 적용해 첫 화면의 모드·여백을 불필요하게 바꾸는 반대 방향 회귀” 미종결 함께 종결 차단 지적 2 의 수정으로 두 상태의 라벨 폭이 같아져 예산이 어느 쪽도 과대·과소하지 않다. 기존 활성 경계 테스트(th·my 280×320, 4크기×2배율)는 그대로 통과하고, 새 테스트가 비활성 쪽 여백·순서를 고정한다.

5. 남은 위험

  1. 활성 전환 시 버튼 폭이 20 + 8.w 만큼 넓어진다. 의도한 시각 변화이며 세로 점프를 없애기 위한 대가다. 아이콘·그라데이션·그림자와 함께 나타나므로 상태 변화로 읽히지만, 디자인 확인이 필요하면 이 지점이다.
  2. 극단적으로 좁은 카드에서는 활성 폭이 contentWidth 에 잘려 비활성보다 라벨이 좁아지고, 두 상태 높이가 다시 갈린다. 예산은 그 좁은 쪽을 쓰므로 상한은 유지되지만 동일 높이 보장은 깨진다. 실제 도달 조건은 뷰포트 폭 약 80 미만이라 실기기에서는 나오지 않는다.
  3. 아이콘 박스 20 을 상수로 두는 것은 Icon.applyTextScaling 기본값 false 에 기댄다. 테마가 IconThemeData.applyTextScaling: true 를 켜면 배율에서 아이콘이 커져 예산이 다시 상한이 아니게 된다. 현재 레포에 해당 설정은 없다.
  4. 유효성 문구가 나타나고 사라질 때는 여전히 route inset 이 바뀔 수 있고, 그 100ms AnimatedPadding 중간 프레임은 테스트하지 않는다(재검증 non-blocking 관찰 2). 이번 변경으로 빈 입력→활성 전환의 inset 변화는 사라졌지만 유효/무효 전환분은 남는다.
  5. 긴 로케일 라벨의 무제한 감김(선행 결함, 별도 티켓 대상)은 그대로다. 활성 폭이 28 넓어져 최악 줄 수는 줄었다.
