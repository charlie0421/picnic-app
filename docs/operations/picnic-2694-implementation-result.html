갤럭시 플립 플렉스 모드, 폴더블, 휴대폰 가로, 태블릿 분할 창에서 키보드가 없어도 금액 입력창이 보이지 않고 ‘전체 사용’ 행만 보이며 스크롤이 생기던 결함을 수정했다. 화면비·기기 분기를 쓰지 않고, 라우트가 실제로 남겨 준 높이(부모 constraints)만으로 조작부를 먼저 배치하고 장식이 양보하도록 레이아웃 정책을 바꿨다.

1. 근본 원인 (코드로 확인한 것)

원인확인한 코드결과
세로 치수를 폭 배율 .w 로 씀 voting_dialog_widgets.dart 초상화 80.w, 로고 60.w/100.w, jma_voting_dialog.dart 초상화 60.w, 로고 120.w×60.w 가로 851 에서 scaleWidth = 851/393 = 2.17 → 초상화 173, 로고 130. 장식만으로 세로 예산을 소진해 입력·버튼이 첫 화면 밖으로 밀림.
카드 폭도 폭 배율 large_popup.dart:22 defaultLargePopupWidth() = 345.w 가로 851 에서 카드가 747 로 커지고 내부 장식도 함께 커짐.
티어 계산이 ‘입력 한 줄 + 8’ 만 예약 구 voting_dialog.dart _pinnedChromeFor() 스크롤 창이 입력을 담을 가능성만 보장. 오프셋 0 에서 입력 앞에 놓인 잔액·전체 사용 높이를 예약하지 않음.

JMA 는 고정 임계값 분기 구 jma_voting_dialog.dart budget < 360 || textScaler.scale(14) > 18.2 실제 조작부 높이를 재지 않아, 고정 티어에서도 잔액·일일 한도 패널이 입력을 화면 밖으로 밀어냄.
초기 화면 보정 없음 Scrollable.ensureVisible 은 _focusNode.hasFocus 일 때만 실행 포커스 전(=팝업이 막 열린 상태)에는 숨은 입력이 저절로 드러나지 않음.

2. 구현 — 조작부 우선 밴드 레이아웃

2.1 신규 공유 정책 voting_dialog_layout.dart

  • VoteDialogBands — 본문을 장식 / 조작부 / 투표 버튼 / 꼬리 4 밴드로 나눈다. 조작부·버튼·꼬리는 비-flex 로 먼저 자연 높이를 가져가고, 장식만 Flexible(loose) + SingleChildScrollView 로 남은 높이를 받아 모자라면 스크롤한다. 시각 순서는 기존과 동일하다.
  • selectVoteDialogLayout({bodyHeight, essentialHeight}) — 조작부조차 담기지 않는 예산에서만 allScroll 로 떨어지고, 그때는 조작부를 맨 위로 올려 전체 스크롤한다.
  • voteDialogDecorationExtent(design) = min(design.w, design) — 세로 치수는 좁은 화면에서는 줄되 넓은 화면에서 커지지 않는다.
  • resolveVoteDialogWidth() = min(345.w, 560) — 투표 팝업 전용 논리 폭 상한. voteDialogCardExtent(design) 가 내부 가로 여백·버튼 폭을 같은 비율로 함께 줄인다.
  • resolveVoteDialogPortraitSide() — 장식 밴드가 받은 높이에서 이름·잔액 몫을 뺀 만큼으로 초상화를 80 → 최소 32 까지 줄인다. 배분되는 높이는 비-flex 형제들의 높이로만 결정되므로 측정이 자기 자신으로 되먹임되지 않는다.
  • voteDialogCardBorderRadius(bodyHeight) = circular(min(120.r, bodyHeight/4)) — 짧은 카드에서 Clip.antiAlias 둥근 모서리가 가장자리에 붙은 조작부를 깎지 않게 한다.

2.2 일반 VotingDialog

  • _PinnedChrome{full,compact,none} 3 티어 제거. 대신 실측 _essentialHeight() (전체 사용 + 입력 + 간격 + 오류문구 + 버튼 상단 여백 + 버튼 + 하단 여백) 하나로 판정.
  • 밴드 구성 — 장식: 초상화·이름·잔액·보너스 버블 / 조작부: 전체 사용·입력·오류 / 버튼: 투표 / 꼬리: 로고 + 하단 여백.
  • 로고는 가장 먼저 양보한다. 조작부 + 로고 + 장식 최소치 ≤ 예산 일 때만 버튼 아래 자리를 지키고, 아니면 스크롤되는 장식 밴드 끝으로 내려가 접근성은 유지한다. 키보드가 올라오면 기존처럼 숨는다.
  • 입력 높이 공식을 실제 구조(48 지우기 버튼 + 테두리 2)에 맞게 고쳤다.

2.3 JmaVotingDialog

  • budget < 360 || scale(14) > 18.2 고정 임계값 제거 → 같은 실측 정책 사용.
  • 0.75 / 0.85 선호 비율은 평소 모습으로 유지하되 budget = min(max(preferred, essential), fits) 로 바꿔, 비율 때문에 조작부가 밀리지 않게 했다.
  • 밴드 구성 — 장식: JMA 배지·아티스트·잔액·일일 한도·계산/검증 패널·정책 안내 / 조작부: 전체 사용·입력·투표 안내 문구 / 버튼: 투표 / 꼬리: JMA 로고 + 하단 여백.
  • maxWidth: MediaQuery.size.width - 32.w → resolveVoteDialogWidth() (기존 값은 카드보다 넓어 의미가 없었고 가로에서는 더 커졌다).

3. 계획 대비 편차와 근거

계획(3장·4장)실제 구현근거
VoteDialogLayoutMode { comfortable, actionsPinned, allScroll } 3 모드 + fullContentHeight 측정 { actionsPinned, allScroll } 2 모드. fullContentHeight 는 측정하지 않는다. comfortable 은 “전체 콘텐츠가 들어간다”는 뜻인데, 그 판정에는 bubble_box 내부 기하까지 모델링해야 해서 오차가 곧 재발로 이어진다. 대신 Flexible(loose) 가 남는 높이에서만 줄어드는 성질을 이용해, 여유가 있으면 장식이 자연 높이를 그대로 가져가 기존과 픽셀 동일하고 모자라면 자동으로 스크롤한다. 측정은 ‘절대 밀리면 안 되는 조작부’에만 쓴다.
짧은 모드에서만 혜택/안내를 부가 영역으로 이동 보너스 버블을 항상 잔액 아래(입력 위)로 옮겼다. 조작부(전체 사용·입력·오류·버튼)를 연속된 한 덩어리로 만들어야 밴드 하나로 먼저 배치할 수 있다. 버블이 입력과 버튼 사이에 남으면 양보 가능한 영역이 두 군데로 쪼개지고, Flex 는 두 개의 loose flexible 사이에 우선순위를 줄 수 없어 넓은 화면에서 로고가 잘리는 반대 회귀가 생겼다(측정으로 확인). 기존 테스트의 불변식(bubble.top ≥ names.bottom, bubble.bottom ≤ submit.top)은 그대로 유지된다.
JMA 계산·정책을 입력 아래 상세 스크롤로 계산/검증 패널과 정책 안내가 입력 위 장식 밴드로 이동. 같은 이유(조작부 연속성). 정보는 삭제하지 않았고 스크롤로 접근 가능하다. 입력 직후 피드백인 “N개의 투표를 진행합니다” 문구(_buildErrorMessage)는 조작부 밴드에 남겨 항상 입력 바로 아래에 보인다.
카드 반경: 짧은 모드에서 circular(24) circular(min(120.r, bodyHeight/4)) 연속 클램프. 모드 경계에서 반경이 120 → 24 로 튀지 않는다. 예산 480 이상(일반 폰)에서는 기존 값과 동일하다.

6. 남은 위험

위험내용대응 / 판단
같은 방식으로 깨질 수 있는 다른 팝업 — voting_complete.dart LargePopupWidget content 를 스크롤 없이 Column + 고정 높이(51·120 등)로 쌓아 합계 약 450~500. 짧은 세로 뷰포트에서 상·하단이 잘릴 수 있다. 이번 범위 밖(미수정). 공유 이미지 캡처 기하와 얽혀 있어 별도 검증이 필요하다. LargePopupWidget 기본 반경·기본 폭을 바꾸지 않았으므로 이번 변경으로 악화되지는 않는다.
