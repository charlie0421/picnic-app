작업 1 — 목록 자동 복구를 제거하고 현재 사용자 흐름 유지

  1. 먼저 실패 테스트: 시작/복귀/인증 갱신에서 전체 목록 및 과거 보상 status 호출이 없음; 방금 본 광고는 PENDING→GRANTED 확인; 동일 광고 중복 콜백이 하나의 표시/analytics 기록만 만듦; 로그아웃/계정 전환 중 늦은 응답 무시.
  2. app.dart의 _syncRewardOwner / _initializeRewardRecovery / resumed 연결을 재구성한다. owner 전환 시 광고 상태를 초기화하되 recover 전체 스윕은 실행하지 않는다. 동일 사용자 token refresh는 광고·지갑 재조회 원인이 되지 않는다.
  3. 현재 잔액은 초기 provider 로드와 명시적 새로고침을 사용하고, 앱 복귀에서는 이미 로드된 지갑에 한해 겹친 요청을 합쳐 갱신한다. 성공 후 60초 이내 반복 복귀는 재조회하지 않는다. 최초 앱 로드와 즉시 재생된 인증 이벤트가 중복 조회를 만들지 않아야 한다. 요청은 기존 6초 잔액 읽기 제한을 적용한다. 계정/세대별 요청 결과를 검증한 뒤 setSummary로 적용해 오래된 잔액을 덮지 않는다. 기존 표시값은 네트워크 실패 시 유지한다.
  4. GRANTED를 앱이 확인하는 순간 금액/통화/광고 reference를 검증해 기존 EarnAnalyticsStore에 저장한다. 팝업이 마운트되지 않았거나 사용자가 광고 화면을 떠나도 유효한 현재 사용자 결과의 통계 저장이 가능해야 한다. SDK 성공만으로 기록하거나 DENIED/EXPIRED를 적립으로 기록하면 안 된다. 기존 내부 숏폼 직접 표시 경로와 중복을 방지한다.
  5. 과거 popup 재생과 목록 페이지 순회를 제거한다. 불필요해진 로컬 복구 상태는 앱 내부 상태로만 정리할 수 있으나 서버 보상/원장을 삭제하거나 임의 만료 처리하지 않는다. 원격 ACK API는 현재 표시 건의 호환 동작으로 유지 가능하다.
  6. 의미 있는 테스트를 먼저 RED 확인 후 구현한다. 기존 recover 테스트는 새 계약으로 바꾸고 foreground 보상 표시/ACK/owner 방어·analytics outbox 회귀 테스트는 보존한다. 앱 lifecycle 연결도 실제 호출 경로로 검증하며 소스 문자열 검사로 대체하지 않는다.
  7. flutter test --no-pub: 변경된 광고 provider/host, 플랫폼, storage, analytics 및 새 lifecycle 테스트. flutter analyze --no-pub: 소유 변경 파일. dart format 및 git diff --check. 결과와 한계를 /tmp/picnic-app-redesign-core-report.html에 기록하고 worker_done 제출. 커밋/푸시는 루트가 통합 후 수행한다.
