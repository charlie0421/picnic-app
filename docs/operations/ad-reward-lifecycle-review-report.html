N2 Low · 견고성 provider 가 재빌드되면 lifecycle 이 조용히 무장 해제된다

파일/행 picnic_lib/lib/core/services/ad_reward_lifecycle.dart:80-88

adRewardLifecycleProvider 는 walletAuthGatewayProvider(:82)와 walletResumeRefresherProvider(:83)를 ref.watch 한다. 이 둘 중 하나라도 재빌드되면 ref.onDispose(lifecycle.dispose) 로 기존 인스턴스가 dispose 되고 새 인스턴스가 만들어지지만 아무도 start() 를 부르지 않는다. _AppState._rewardLifecycle(app.dart:158)은 이미 dispose 된 옛 인스턴스를 계속 들고 있다.

실패 조건: 그 시점 이후 프로세스가 끝날 때까지 resume 잔액 갱신도, 소유자 변경 시 광고 상태 무효화도 전혀 일어나지 않는다. 오류도 로그도 남지 않는다.

현재 도달 불가: walletAuthGatewayProvider(wallet_provider.dart:67)는 의존성이 없고, picnic_lib/lib·picnic_app/lib 전역 grep 에서 invalidate/refresh/프로덕션 override 대상이 아니다. 따라서 오늘의 결함이 아니라 미래 회귀에 대한 취약점이다. 차단하지 않는다.

최소 수정 (택1): (a) 두 의존성을 ref.read 로 바꿔 재빌드 자체를 없앤다 — 프로덕션에서 override 되지 않으므로 손실이 없다. (b) _AppState 가 provider 를 ref.listen 해 새 인스턴스에 start() 를 다시 건다. ※ provider 본문에서 start() 를 부르는 방식은 “SDK 준비 후” 요구를 깨므로 적절하지 않다.

확인한 잠재 문제 — 결함 아님

  • startup 에서 adRewardRecoveryProvider 를 즉시 생성(:84의 ref.read(...notifier)) — AdRewardRecovery.build() 는 const AdRewardRecoveryState() 로 I/O 가 없다(ad_reward_recovery_provider.dart:119-120). 시작 비용 0.
  • 재마운트 시 재무장 — _isAppInitialized 는 State 인스턴스 필드라 새 _AppState 에서 _initializeAppBasics 가 다시 돌고, keepAlive provider 가 같은 인스턴스를 돌려주며 _started == false 이므로 start() 가 정상 재무장한다.
  • !mounted 창 — app.dart:154 의 가드로 sdkReady 대기 중 unmount 되면 lifecycle 을 아예 만들지 않는다. _rewardLifecycle 은 null 이라 dispose() 도 무해하다.
  • auth 스트림이 죽는 경우 — onError 는 로그만 남기고 cancelOnError:false 로 구독이 유지된다. 게다가 didChangeAppLifecycleState 가 resume 마다 currentSession 을 다시 읽어 _syncOwner 를 돌리므로 스트림이 끊겨도 소유자 변경을 놓치지 않는다.
  • resume 시 _syncOwner → refreshOnResume 순서 — 소유자가 바뀐 resume 이면 reset 이 먼저 돌아 이전 계정의 쿨다운·진행 중 읽기를 물려받지 않은 상태에서 새 계정 읽기가 시작된다. 순서가 맞다.
  • isEnabled == false — 구독을 걸지 않고 observer 만 등록하되 didChangeAppLifecycleState 가 즉시 반환하므로 완전한 no-op 이다.

잘 된 부분

  • 테스트가 소스 문자열 검사가 아니라 실제 바인딩 이벤트를 쓴다. tester.binding.handleAppLifecycleStateChanged(paused) → (resumed) 쌍으로 Flutter 의 상태 기계가 실제 전이를 내보내게 만들고, AdRewardLifecycle 은 주입 없이 WidgetsBinding.instance(테스트 바인딩)에 등록된다. 요구된 “실제 lifecycle 이벤트” 조건을 정확히 만족한다.
  • “0회”를 음성 단언 + 구조 양쪽으로 보장한다. 테스트가 listCalls/statusCalls/readAll 을 0으로 못박을 뿐 아니라, 페이크가 호출 시 throw 하도록 되어 있어 우회 호출도 즉시 드러난다. 코드베이스에 recover() 호출부가 남아 있지 않은 것과 이중으로 맞물린다.
  • dispose 테스트가 세 가지를 한 번에 증명한다 — 구독 해제, observer 해제, in-flight 응답 폐기. 특히 dispose 이후 emit 과 resume 을 모두 흘려보낸 뒤 늦은 응답까지 버려지는지 확인하는 구성이 정확하다.
  • 책임 분리가 깔끔하다. _AppState 에 흩어져 있던 auth 구독·owner 추적·resume 훅이 한 클래스로 모였고, app.dart 는 “SDK 준비 후 start, dispose 시 dispose” 두 줄만 안다. WalletResumeRefresher 의 공개 메서드 2개만 소비해 소유권 경계도 지켜진다.
  • AppLifecycleInitializer.disposeAppListeners(null, _appLinksSubscription) 로 auth 구독 정리 책임을 lifecycle 로 완전히 이관하고 app.dart 에 잔재를 남기지 않았다.
