로컬 저장 실패 복구: 앱 수정과 확인된 범위

앱 수정·호스트 검증·독립 코드 리뷰 완료.

비핵심 포털·탭 저장 실패를 호출자가 처리하도록 수정했다. 화면 이동은 완료되고 미처리 Future 오류는 발생하지 않는다. SharedPreferences의 false 저장 결과는 고정 문구의 StateError로 상위 호출자에게 전달한다. 사용자별 저장 키는 해당 오류 메시지에 넣지 않는다.

조정자 직접 실행: 계획된 7개 테스트 파일에서 189개 통과. 변경한 8개 Dart 파일 분석은 No issues found. 독립 리뷰는 APPROVE다.

T3 전체는 부분 완료다.

로그인 후 5N2 전체 12개 이벤트의 실제 스택과 1.3.5+130504 릴리스를 확인했다. 모두 Pangle 참조 저장 경로다. 운영 함수 정의는 읽기 전용으로 확인했지만, 실제 저장 실패 후 앱 재시작 복구와 표시되지 않은 claim의 전체 수명·한도 영향을 검증한 것은 아니다. 배포·실제 광고·보상 지급·Sentry 재발 여부는 이번 결과에 포함하지 않는다.

변경과 유지한 계약

경계결과
NonWebLocalStorage.saveDatasetString=false에서 StateError('SharedPreferences failed to persist a value')를 던진다. 기존 reload·이전 값 복원 순서와 실패 전파를 유지했다. 메시지에서 전체 키를 제거했다. 임의 키를 잘라내 사용자 ID 일부가 남는 방식은 사용하지 않았다.
NavigationInfosetPortal과 pic/vote/community/novel 탭의 총 5곳을 private 저장 도우미로 처리한다. Future.sync로 저장을 즉시 시작하고 동기 throw와 비동기 실패를 처리한다. 고정 경고 1개만 남기며 오류 객체·스택·키·값을 경고에 넣지 않는다. UI 상태 갱신 순서와 기존 함수 계약은 유지했다.
기본 화면현재 NavigationInfo.build는 초기 화면을 사용한다. 사용되지 않는 Navigation.load를 연결하거나 새로운 탭 복원 기능을 추가하지 않았다. 저장 실패 뒤 재생성한 기본 상태도 테스트했다.
광고 표시 전 참조 저장Pangle·숏폼의 create/issue→persist→표시 경계를 유지했다. persist 실패 시 같은 호출에서 claim/issue는 1회이고 load·폴링 구독·재생 가능한 결과·세션 결합이 진행되지 않음을 테스트했다. 플랫폼 showAd·실제 네이티브 렌더링을 직접 실행한 검증은 아니다.
markAckPending 실패서버 ACK 전 예외가 전달되고, 큐와 pendingDisplay 상태가 유지되며 적립 통계는 1회다. discardDialog 뒤 같은 세션의 동일 참조 poll은 로컬 표시를 1개 다시 열 수 있다. 추가 ACK·적립은 없고 저장 복구 후 ACK는 1회다. 기존 재표시 계약을 유지했다.
복귀·재시작WalletResumeRefresher의 계정별 잔액 조회를 유지했다. 시작 시 pending 목록 재생·폴링, 메모리 전용 폴백, 새 claim 자동 재시도를 추가하지 않았다.

테스트와 리뷰 근거

구현자가 보고한 수정 전 RED 결과는 163개 통과·12개 실패다. 개인정보 메시지 사례 2개와 포털·탭 5곳 각각의 동기/비동기 저장 실패 10개가 실패했다. 정상 저장·reload 실패 시 복원·보상 persist·ACK 경계 사례는 기존 동작을 고정한 대조군이며, 이들이 원래부터 통과했다는 점을 구분했다.

구현자는 Pangle 테스트의 LocalStorage import 이름 충돌을 고친 뒤 테스트를 실행했다. 최초 분석에서 암묵적 pub resolve가 있었지만 추적된 pubspec·lock 변경은 없었다. 전역 정책 파일 읽기는 작업자 권한에 막혔고, 작업트리의 TDD·검증·테스트 작성 스킬 사본을 읽었다고 보고했다. 구현자의 전역 정책 로딩은 확인된 것으로 기록하지 않았다.

조정자는 리뷰 대상 8개 해시를 확인하고 같은 소스에서 아래 테스트와 분석을 직접 실행했다. 오류 주입 테스트의 경고 출력은 의도한 실패 처리 경로에서 발생했다. 리뷰어는 실제 전역 policyRevision 2를 읽었고, 전체 diff와 관련 저장·복구·대화상자·지갑 소스를 검토했다. 리뷰어는 테스트를 실행하지 않았다.

운영 서버에서 확인한 정의

Supabase 연결 도구로 PICNIC-PROD의 PostgreSQL 함수 정의와 배포된 Edge 함수 소스만 읽었다. 고객 행 조회, 업무 RPC 호출, 광고·지급·ACK·스키마 변경은 하지 않았다. 관측 시점의 정의이며 과거 130504 실행 당시의 정의를 증명하지 않는다.

  • create_ad_reward_claim: 사용자·채널·client_request_id 조합 충돌 시 기존 claim을 반환한다. platform·placement·environment·payload가 다르면 충돌 오류를 낸다. 최초 expires_at은 DB 시각에서 10분 뒤다. 앱이 새 UUID로 다시 요청하면 별개 claim이 될 수 있다.
  • get_ad_reward_status와 wallet_private.ad_reward_status_for: 사용자·참조·채널에 해당하는 저장 상태와 기존 지급 결과를 읽는다. 이 함수 정의에는 만료 시각 경과만으로 상태를 EXPIRED로 바꾸는 코드가 없다.
  • settle_pangle_ad_reward: 사용자·claim 잠금과 토큰 필드 대조 후 처리한다. 이미 GRANTED이고 같은 provider transaction/payload이면 기존 지급 결과를 반환한다. PENDING이며 DB 시각이 expires_at을 지났으면 EXPIRED로 갱신한다. 자동 스케줄러 만료를 검증한 것은 아니다.
  • acknowledge_ad_reward: 현재 사용자 소유의 PENDING이 아닌 참조에 확인 시각을 최초 1회 기록한다. 이 함수에는 새 지급을 만드는 코드가 없다.
  • 현재 Edge 소스 ad-reward-claim v32와 ad-shortform-issue v67을 확보했다. 보조 anti-abuse 검사와 별도 저장 경로가 있으므로 claim 수만으로 시청·지급 한도를 단정하지 않았다. 숏폼 발급의 전체 만료·한도와 외부 콜백 동작은 추가 확인 사항이다.

사건과 릴리스 비교의 한계

기존 분석의 5KG는 처리되지 않은 vote 탭 저장 Future와 연결된다. 2026-11-06 로그인 후 5N2 전체 이벤트를 2페이지로 조회했다. 그룹 총 12개와 조회 결과 12개가 일치하고 다음 페이지는 없다. 모두 io.iconcasting.picnic.app@1.3.5+130504이며, UTC 2026-10-16 02:16:06부터 2026-10-31 13:59:01까지다. 기존 분석의 10개는 당시 보고 수치로 보존하고, 이번 전체 조회 12개를 별도로 기록한다.

12개 모두 PanglePlatform._loadPangleAd:349 → PangleClaimPreflight.execute:70 → PendingAdRewardStore.add:110 → NonWebLocalStorage.saveData:25 경로다. 130504 태그에서 execute:70은 createClaim 결과를 받은 뒤 await persist(...)를 실행하는 줄이다. 폴링 구독과 광고 load는 그 뒤에 있다. 이 사건 표본은 Pangle의 표시 전 로컬 참조 저장 실패로 연결되며, markAckPending·숏폼·AdMob 실패 표본이라는 근거는 없다.

SharedPreferences가 false를 반환한 기기 측 원인(저장공간·플랫폼 저장소 등)은 이 스택으로 확정할 수 없다. 생성된 서버 claim의 현재 행 상태나 실제 지급 여부도 조회하지 않았다. 이벤트의 사용자별 키·사용자 정보·예외 원문은 보고서와 새 증거에 보관하지 않고, 시각·릴리스·예외 타입·호출 프레임만 추출했다.

picnic-v1.3.5+130504-skip-tests와 수정 전 f12088de7을 비교했다. non_web 저장·pending 저장·navigation·recovery 파일은 같고, Pangle·shortform 파일은 달랐다. 따라서 최신 경로 테스트만으로 과거 광고 경로가 완전히 같았다고 주장하지 않는다.

남은 확인

  • 5N2 실제 스택·릴리스 확인은 완료했다. 저장 실패의 기기 측 원인과 배포 후 재발 여부는 아직 확인하지 않았다.
  • 표시되지 않은 claim의 전체 수명·한도 영향, 숏폼 계약과 저장 실패 후 앱 재시작 복구를 확인한다. 기존 계약으로 해결할 수 없는 서버 변경이나 새 로컬 재생 설계는 별도 승인 범위다.
  • AdMob persist 경계는 T6에서 검증한다. 모든 광고 네이티브 표시와 실제 보상 지급은 이번 호스트 검증 범위 밖이다.
  • 오류 문구 변경으로 Sentry 그룹이 달라질 수 있다. T9 효과 측정에서 기존 그룹 건수만 비교해 해결로 판단하지 않는다.
배포·Sentry·Jira 상태 변경 없음. 원시 로그와 서버 소스는 비공개 QA 증거로 보관한다. 이 보고서는 원문 토큰·사용자별 키·고객 행을 포함하지 않는다.
