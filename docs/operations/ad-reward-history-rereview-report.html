새 회귀 탐색 결과

수정으로 새로 생긴 결함은 확인되지 않았다. 확인한 경로는 다음과 같다.

  • 계정 전환 중 이전 세대 행 노출 — 임시 프로브로 A→B→A 를 한 배치로 발생시켜 게이트가 다시 열린 순간을 관측했다. 결과 rows=0 / spinner=1, 재조회 calls=2(즉 1회). 두 번의 auth 이벤트가 한 번의 재빌드로 합쳐져 요청 증폭도 없다.
  • 다른 내부값 노출면 — picnic_lib/lib/presentation 전역 grep 에서 operationId/eventType/origin 렌더링 0건.
  • initialIndex 도입의 부작용 — DefaultTabController 는 length 변경 시에만 컨트롤러를 재생성하므로 탭 탭핑과 충돌하지 않는다. 길이는 3 고정. 기존 탭 전환 테스트가 그대로 통과하는 것으로도 확인된다.
  • 타임아웃 도입의 부작용 — loadNext 타임아웃 후 catch → false → finally 로 _loadingNext 가 풀려 버튼이 재시도 상태로 복귀한다. :178-208 테스트가 이 복귀와 실제 재시도 성공을 함께 단언한다.
  • 재시도 정책 제거의 부작용 — 로그아웃 상태의 StateError 도 이제 확정적으로 재시도되지 않는다. 1차의 불확실성이 제거되는 방향.
1차 리뷰 정정 2건. (1) F11 은 이미 wallet_provider_test.dart:575 로 간접 고정돼 있었다(위 표 참조). (2) 재검증 중 “skipLoadingOnRefresh: false 가 계정 전환 표시 창을 닫는 load-bearing 불변식”이라는 가설을 세웠으나, 반사실 프로브로 측정한 결과 사실이 아니었다 — 세션 provider 변경은 의존성 변경(reload) 이라 riverpod 기본값 skipLoadingOnReload: false 가 이미 로딩 분기를 강제한다. 따라서 skipLoadingOnRefresh 값은 명시적 ref.invalidate 경로(오류 재시도 버튼, 당겨서 새로고침)에만 영향을 주며 프라이버시 차원이 없다. 이 항목은 지적으로 올리지 않는다.
