고친 것 — 실재하던 결함

원 구현(admob_platform.dart)은 로드·표시 두 단계 모두 타임아웃이 없었다. stopAllAnimations() 를 부르는 경로가 SDK 콜백 5종뿐이라 콜백이 안 오면 로딩 UI 가 영구히 남는다. 콜백과 무관하게 UI 를 되돌리는 코드가 저장소 전체에 없었다. Pangle 은 로드 단계에 5초 타임아웃이 있어 명확한 비대칭이었다.

커밋 6fecae2fe(UI 구좌 제거)는 배선만 떼어냈고 결함은 그대로 남겼다. AdmobPlatform 은 죽은 코드로 남아 initialize() 는 지금도 호출된다.

미확정: 사건 보고서의 판별 기준이 "2026-03-02 이후 콜백 10건+" 인데, STRICT 검증이 같은 날 켜졌음에도 이후 콜백이 기록됐다는 점은 검증 통과 없이도 기록되는 경로가 있었거나 판별이 "시도" 기준이었음을 시사한다. 되살리기 전에 이 한 가지는 확인하는 편이 좋다.

PICNIC-2377 의 Pangle 과 정확히 같은 구조다. 조사 중 재현용으로 복원한 AdMob 구좌는 UI 에 "+코튼캔디 1 획득" 이라 표시했지만 서버에 그 코튼을 지급할 경로가 없다. 이 상태로 켜면 사용자가 광고를 보고 아무것도 못 받거나 레거시 보너스 스타캔디를 받는다.

isCottonRewardMode('admob') 은 COTTON_SOURCE_PROVIDERS 에 키가 없어 항상 false 를 반환한다.

4. 알려진 공백 — 정직하게 남긴다

4-1. 콜백 미수신은 끝내 재현하지 못했다

실기기(Galaxy S20+, 프로덕션 1.3.0+130007)로 시도했으나 config.admob_disabled_os = 'ios,android' 때문에 checkAdsLimit 이 disabled:true 를 반환해 RewardedAd.load() 에 도달조차 못 했다. "이 광고는 일시적으로 사용할 수 없습니다" 다이얼로그로 깨끗이 종료됐다(멈춤 아님).

워치독은 "콜백이 안 와도 사용자가 갇히지 않게" 하는 방어이지, 미수신의 근본 원인을 제거했다는 주장이 아니다.

4-2. Dart 워치독은 네이티브 ANR 을 막지 못한다

커밋 4729cc5d7(2026-05-13)이 Sentry App Hanging/ANR 14건·200명+ 에서 GAD_*(AdMob) culprit 을 기록한다. 이는 광고 SDK 의 네이티브 메인스레드 블로킹이라, Dart 이벤트 루프에서 도는 타이머로는 UI 복구가 지연될 수 있다. AdMob 을 다시 켜면 이 ANR 노출면도 함께 돌아온다. 켜기 전 Play Console ANR 기준선을 기록하고 OS 별로 점진 해제할 것.

4-3. 테스트 사각지대 — 헬퍼는 지키지만 배선은 못 지킨다

Sol 최종 판정은 "현 상태는 머지 불가" 였다. 코디네이터가 실측으로 확인한 내용:

# 분류 근거를 하드코딩 라벨로 퇴행 → 테스트 2건 실패 ✅ (가짜 green 제거됨)
# 그러나 호출부가 헬퍼를 우회하도록 인라인 교체 → 320건 전부 통과 ❌

즉 handleLoadFailedForFlow 같은 추출 헬퍼는 테스트되지만, 프로덕션 호출부가 그 헬퍼를 쓰는지는 검증되지 않는다. 같은 구조가 GA4 스냅샷과 FreeChargeStation dispose 에도 있다.

근본 원인은 AdmobPlatform 이 위젯·AnimationController·Riverpod 에 묶여 있어 호출부 자체를 테스트로 실행하기 어렵다는 구조다. 그래서 워커가 반복적으로 헬퍼 추출이라는 우회로를 택했다. 진짜로 막으려면 AdmobPlatform 을 인스턴스화해 showAd() 를 돌리는 통합 테스트가 필요하고, 광고 SDK 목킹이 선행돼야 한다.

4-4. PangleMediationAdapter 는 notReady

실기기 캡처: AdMob 코어·Vungle·Meta 어댑터는 ready 인데 PangleMediationAdapter 만 notReady — 'does not implement the initialize() method'. 우리는 Pangle 을 직접 SDK 로도 쓰고 있어(아시아 픽 #1) 중복이다.

계획서 §C 는 제거를 권고한다(현재 기여 0 + 중복). ⚠️ 단 iOS 는 pod 'Ads-Global' 재추가가 필수 — 현재 iOS 의 Pangle SDK 를 이 어댑터가 끌어오고 있어 그냥 빼면 빌드가 깨진다. 네이티브 변경이라 OTA 불가, 별도 바이너리 릴리스 필요.

6. 권장 진행 순서

  1. 워치독 PR 먼저 분리해 올린다. 3커밋은 그 자체로 완결된 결함 수정이고, AdMob 을 켜든 안 켜든 가치가 있다(현재 죽은 코드에 남은 실제 결함). Dart 전용이라 OTA 경로다. §4-3 테스트 사각지대는 PR 본문에 후속으로 명시한다.
  2. 계획서를 다시 쓴다. §2 어뷰징 사실과 §3 코튼 정산 경로 부재를 반영해 §A 전제조건·§E 롤아웃을 재설계한다. PICNIC-2377 에서 배운 것을 반드시 넣을 것 — 두 저장소를 잇는 계약에 테스트가 없으면 같은 실패가 반복된다(Pangle 에서 결함 3건이 전부 이 공백에서 나왔다).
  3. 서버 작업(403 해제 + 코튼 정산 경로)을 별도 설계·구현한다. 배포 경로가 앱과 다르다.
  4. 스테이징 실검증 → OTA → 프로덕션 admob_disabled_os android 먼저 해제 → 48시간 ANR 모니터링 → ios.

되살리기 자체를 재검토할 여지도 있다. 686계정 어뷰징을 겪은 채널이고, 현재 Pangle·자체 숏폼 2개 구좌가 정상 작동 중이다(2026-08-13 기준 Pangle 코튼 지급 복구 완료). AdMob 수익이 §3 의 서버 작업량과 §4-2 의 ANR 노출 재개를 정당화하는지는 제품 판단이다.
