조사일 2026-09-30 · 문의 admin.picnic.fan/qnas/show/395 · 사용자 971e4a24(닉네임 하미니에요, KR, 카카오 가입) · 기기 갤럭시 S24 울트라(SM-S928N), One UI 8.5(사용자 진술) · 앱 1.3.5+130504, 패치 없음

1. 결론 요약

  • 증상은 "광고 로드 실패"다. 첫 스크린샷은 자체숏폼 전체화면(검은 배경)에 뜬 label_ads_load_fail("광고 로드에 실패했습니다. 다시 시도해주세요.") 다이얼로그다. 촬영 시각은 9/28 16:01 KST 발급 건 직후로 맞아떨어진다.
  • 서버는 정상이다. 이 사용자에게 9/26~9/29 사이 자체숏폼 토큰이 27번 발급됐고(ad_impressions 27행) 서버 오류·안티어뷰징 차단·한도 초과는 없었다. 실패는 발급 뒤 단말에서 HLS 영상을 15초 안에 초기화하지 못해 생긴 것이다. 27건 중 2건(9/27 12:33·12:35)만 끝까지 재생돼 적립됐다.
  • 전체 장애가 아니다. 최근 16일 전체 완료율은 93.7~96.7%로 평탄하고 1.3.5 출시(9/25) 전후로 변화가 없다. 같은 기간 이 사용자는 AdMob(글로벌픽#1)·Pangle(아시아픽#1)을 하루 50회씩 정상 시청했다.
  • 이 사용자는 예전엔 잘 됐다. 4월~8/20까지 자체숏폼 92건 중 91건 완료. 9/26부터 갑자기 2/27. 그 사이에 앱 1.3.5 업데이트와 (사용자 진술상) One UI 8.5 업데이트가 있었다. 어느 쪽인지 서버 데이터로는 못 가른다.
  • 관리자 1차 답변의 "1시간 10회"는 맞다. 서버 한도는 공급자별 시간당 10회·KST 일 120회(get_cotton_ad_limit_status)다. 다만 이 건은 한도와 무관하다. 한도 초과면 발급 자체가 막히고, 이 사용자는 매번 발급이 됐다.
  • 원인을 확정할 로그가 없다. 영상 로드 실패 경로는 다이얼로그만 띄우고 Sentry·서버 어디에도 오류 종류를 남기지 않는다. 이 사용자·이 기기 모델의 Sentry 이벤트는 최근 7일 0건이다. 그래서 아래 회신은 원인 후보를 좁히는 질문을 포함한다.

  • 활성 캠페인 6개(이프아이 1~5, 이스트샤인) 모두 완료율 94.4~96.3%. 특정 영상 문제 아님.

4. 원인 후보(가능성 순)

  1. 단말 네트워크 속도 부족 + 15초 초기화 타임아웃. 이동통신 IP, 같은 IP에서 성공·실패 혼재, 재시도 간격 ~15초, AdMob·Pangle 정상, 구형·저가 기기에서 완료율 하락 — 전부 이 가설과 맞는다. 사용자에게 Wi-Fi 재현 여부와 요금제 속도제한 여부를 물어 확인한다.
  2. One UI 8.5(베타/최신 펌웨어)와 media3 디코더 조합 문제. 9/26 갑작스런 전환과 사용자가 UI 8.5를 직접 언급한 점이 근거. 같은 모델 다른 사용자 3명은 대체로 되지만 한 명이 절반 실패라 배제는 못 한다. Wi-Fi에서도 실패하면 이쪽으로 본다. 그 경우 실기기 재현 없이는 확정 불가.
  3. 앱 1.3.5 회귀. 코드·의존성 diff에 플레이어 변경이 없고 전체·Android 16 코호트 완료율에 변화가 없어 가능성 낮음.

5. 회신 초안(관리자 → 사용자)

1차 답변에서 "정상 작동 중"이라고 한 뒤 사용자가 버전을 보내왔으니, 확인했다는 사실과 로드 실패 원인이 단말 쪽 영상 로딩임을 말하고, 원인을 가르는 두 가지 확인을 요청한다. 한도 안내는 이미 했으므로 반복하지 않는다.
안녕하세요, 버전 정보 보내주셔서 감사합니다. 보내주신 화면(“광고 로드에 실패했습니다”)은 광고 발급은 정상적으로 됐는데 기기에서 광고 영상을 제한 시간(15초) 안에 불러오지 못했을 때 표시됩니다. 확인해 보니 9/26~9/29 사이 글로벌픽#2 광고가 여러 차례 정상 발급됐고 그중 두 번은 끝까지 재생돼 적립까지 됐습니다. 즉 회원님 계정이나 서버 문제는 아니고, 광고 영상(고화질 스트리밍)이 기기에서 시간 내에 로딩되지 못한 경우로 보입니다. 원인을 좁히기 위해 두 가지만 확인 부탁드립니다. 1. Wi-Fi에 연결한 상태에서 글로벌픽#2를 다시 시도해 주시고, 그래도 같은 화면이 뜨는지 알려주세요. 2. 평소 모바일 데이터로 이용하신다면, 데이터 소진 후 속도 제한이 걸리는 요금제인지도 알려주시면 도움이 됩니다. Wi-Fi에서는 정상 재생된다면 이동통신 속도 문제이고, Wi-Fi에서도 같은 화면이 뜬다면 One UI 8.5 업데이트와의 호환 문제로 보고 개발팀에서 해당 기기 기준으로 재현·수정을 진행하겠습니다. 불편을 드려 죄송합니다.

6. 개발 후속 과제

  1. 로드 실패 텔레메트리 추가(우선). _showVideoLoadErrorDialog에서 오류 종류(TimeoutException / PlatformException 코드·메시지), 경과 시간, 선택된 video_url, 네트워크 종류(Wi-Fi/셀룰러)를 Sentry 이벤트로 남기고, 가능하면 ad_impressions에 load_failed_at·load_fail_reason을 기록하는 콜백을 추가한다. 지금은 CS가 들어와도 원인을 볼 방법이 없다. 이 문서의 원인 후보 1·2도 이 데이터가 있어야 확정된다.
  2. 저속망 완화. 19초짜리 세로형 광고에 1080p 5 Mbps 변형은 과하다. 마스터 플레이리스트에서 1080p를 빼거나 720p 이하로 캡하고(서버/인코딩 파이프라인 쪽), 앱에서는 초기화 타임아웃을 15초에서 30초로 늘리되 로딩 표시를 유지한다. 완료율 4~5%p 손실의 상당 부분이 구형·저속 코호트에서 나오므로 전체 적립 손실도 줄어든다.
  3. One UI 8.5 실기기 재현. 사용자가 Wi-Fi에서도 실패한다고 답하면 S24 울트라(One UI 8.5) 실기기로 자체숏폼을 열어 logcat의 ExoPlayer 오류를 확인한다. 회사 보유 기기가 없으면 Samsung Remote Test Lab을 쓴다.
  4. 별건 관찰. 광고 활성 사용자의 40%가 최근 7일 devices 갱신이 없다(이 사용자는 5/27 이후 정지). 배포율·강업 판단이 이 테이블에 기대므로 별도 조사 대상으로 남긴다. 이번 건과는 무관하다.

7. 확인에 쓴 쿼리

-- 사용자 발급/완료 일별
select (issued_at at time zone 'Asia/Seoul')::date, count(*), count(completed_at)
from public.ad_impressions where user_id='971e4a24-97cf-46b4-9aa3-b49bf69fdddf'
group by 1 order by 1;

-- 실패 뒤 재시도 간격
select issued_at, completed_at is not null as ok,
  extract(epoch from lead(issued_at) over (order by issued_at) - issued_at) as secs
from public.ad_impressions where user_id='971e4a24-...' and issued_at >= '2026-09-26';

-- 기기 코호트 완료율(최근 7일, devices.last_seen 7일 이내 사용자만)
with dev as (select distinct on (user_id) user_id, app_version,
  device_info->>'model' model, device_info->'version'->>'release' os
  from public.devices where last_seen >= now()-interval '7 days' order by user_id, last_seen desc)
select d.os, d.app_version, count(*), count(i.completed_at)
from public.ad_impressions i join dev d using (user_id)
where i.issued_at >= now()-interval '7 days' group by 1,2;
