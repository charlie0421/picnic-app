1. 무엇이 바뀌었나

1-1. 목록 자동 복구 제거

AdRewardRecovery.recover() 와 그 뒤의 _recoverForOwner · _pollRecoveredReferences · _resumeAcknowledgement 를 전부 삭제했다. 시작·복귀·같은 사용자 인증 이벤트에서 발생하던 list_unacknowledged_ad_rewards 페이지 순회와, 로컬 pendingDisplay 레코드 전체에 대한 6단 get_ad_reward_status 사다리가 함께 사라졌다.

함께 없어진 것: adRewardRecoveryPollDelays, adRewardRecoverySuccessCooldown, _adRewardRecoveryMaxConcurrentReads, adRewardRecoveryClockProvider, 단일 비행/쿨다운 상태(_recovering, _lastSuccessfulRecovery, _suppressedRecoveryCooldowns).

1-2. 현재 광고의 개별 확인은 유지

poll() 과 포그라운드 사다리(1·2·4·8·15초, 총 6회 읽기)는 그대로다. 배너 (checkingReferences), 소유자·세대 가드, _queued 클레임, ACK 경로도 그대로다. 사다리가 하나로 줄면서 진행 중인 확인에 겹쳐 든 중복 콜백은 두 번째 조회를 만들지 않는다 (이전에는 bg:/fg: 토큰이 갈려 두 사다리가 동시에 돌았다).

1-3. 확정된 적립의 통계 저장을 팝업 수명과 분리

새 파일 picnic_lib/lib/core/analytics/ad_reward_earn_recorder.dart 가 AdRewardStatusModel → GA4 payload 매핑과 durable outbox 저장을 소유한다. AdRewardDialogHost 의 _logEarnVirtualCurrency 와 earnAnalyticsStore 생성자 인자는 제거했다.

기록 시점은 앱이 grant 를 확인한 순간이며 세 경로 모두를 덮는다.

1-4. 계정별 안전한 복귀 시 잔액 갱신

새 파일 picnic_lib/lib/core/services/wallet_resume_refresher.dart. wallet_provider.dart 는 수정하지 않았고 공개 인터페이스 (walletAuthGatewayProvider · walletRepositoryProvider · walletSummaryProvider.setSummary · kWalletSummaryReadTimeout)만 소비한다.

1-5. 로컬 기록 무한 증가 차단

복구 스윕이 pending_ad_rewards_v1 을 훑으며 정리해 주던 경로가 사라졌으므로, ACK 이 끝내 실패한 기록을 치울 주체가 없어진다. PendingAdRewardStore 에 사용자당 상한 kPendingAdRewardMaxRecords = 100 을 넣고 넘치면 가장 오래된 것부터 버린다. markAckPending 은 해당 항목을 목록 맨 뒤로 옮겨, 지금 확인 중인 건은 잘려 나가지 않는다.

버리는 것은 앱 로컬 표시 상태뿐이다. 서버 보상·원장·이미 저장된 적립 통계는 건드리지 않는다.

5. 루트 배선 계약 (app.dart / ad_reward_lifecycle.dart)

루트가 이미 AdRewardLifecycle 로 소비 중인 것을 확인했다. 계약 요약:

  · refreshOnResume()  // resumed 에서 호출. 60초 쿨다운·6초 timeout·계정/세대 검증·

루트 파일에 대한 관찰 1건(수정하지 않음): ad_reward_lifecycle.dart 62행이 _wallet.refreshOnResume().catchError(...) 형태다. refreshOnResume() 은 내부에서 오류를 잡아 failed 를 돌려주므로 정상 경로에서는 문제없지만, 주입된 isWalletLoaded(=ref.exists/ref.read)가 dispose 된 컨테이너에서 동기로 던지면 그 예외는 Future 가 아니라 호출부로 새어 catchError 가 잡지 못한다. Future.sync(() => _wallet.refreshOnResume()) 로 감싸면 닫힌다. (레포가 poll 호출부에서 같은 이유로 이미 쓰는 방어 패턴이다.)

6. 한계와 후속

  • 지난 세션의 미확인 보상은 더 이상 재표시되지 않는다. 승인된 설계 그대로다. 서버 보상·원장은 그대로 남고 사용자는 이미 재화를 받은 상태이며, 통계는 확정 시점에 별도로 저장된다. 잃는 것은 그 건의 영수증 팝업과 서버측 acknowledged 표시뿐이다.
  • listUnacknowledged RPC 는 코드에 남겨 두었다. AdRewardApi 인터페이스와 AdRewardRepository 구현 모두 유지했고 앱에서 호출하는 곳은 0곳이다. 저장소 인터페이스 정리는 작업 1의 범위가 아니라고 판단해 넘겼다.
  • 로컬 기록 상한은 100건이다. 기존 'serializes 100 concurrent adds across owners without loss' 테스트(소유자당 50건)를 깨지 않으면서 무한 증가를 막는 값으로 골랐다. 사용자당 약 11KB 상한.
  • 앱 lifecycle 실제 호출 경로 검증은 루트 소유로 이관됐다. 라이브러리 쪽 보증은 내 테스트가 덮는다: 광고 1건 시청에서 listCallCount == 0, 지난 세션 로컬 레코드가 있어도 reads == [방금 본 광고], 앱 실행 시 statusReads == 0 && listCalls == 0.
  • 운영 호출량 감소는 배포 전이라 주장하지 않는다. 계획의 완료 기준대로, 실제 감소는 앱 배포 후 측정으로 확인해야 한다.
  • build_runner 는 실행하지 않았다(조정자 지시). 생성 파일 변경 0건.
