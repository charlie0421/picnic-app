PICNIC-2743 · iOS 미완료 결제 복구

2026-09-21 · picnic-app · fix/ios-purchase-recovery · 실기기 검증 및 배포 전

승인 범위는 SK2/JWS 기반 미완료 거래 회수, 백그라운드 캐시 정리 중 구매 스트림 구독 유지, 결제 실패 Sentry 관측과 로그인 사용자 식별 연동이다.

확인한 원인과 수정 범위

문제수정 목표보호 조건
SK1 앱 영수증을 JWS 전용 검증 경로에 전송고정된 StoreKit 플러그인의 SK2Transaction.unfinishedTransactions()와 거래별 JWS 사용서버 지급 확인 후 finish. 구매 진행·승인 대기·검증 불가 거래 보존.
백그라운드 캐시 정리 중 구매 스트림 cancel/재구독캐시 정리 중에도 구매 이벤트를 연속 수신구독 중복과 정리 도중 이벤트 유실 방지.
결제 실패 및 계정별 관측 부족제한된 오류 분류와 인증 사용자 ID 기록로그아웃·계정 전환 반영. 영수증·토큰·이메일·원본 오류 본문 제외.

기존 핸드오프의 타이밍 설명 정정

고정 버전 in_app_purchase_storekit 0.4.8+1의 SK2 구매 호출은 네이티브 product.purchase() 결과를 기다리고 이벤트를 보낸 후 반환한다. 앱은 그 반환 뒤 백그라운드 정리를 예약한다. 따라서 “결제 시작 5초 뒤 구독이 끊겨 오래 걸리는 일반 결제를 놓친다”는 설명은 확정 근거로 사용할 수 없다. 정리 중 구독 공백은 실제 코드 결함이며, 비동기·지연 구매 이벤트에 대한 위험을 제거하는 것이 이번 수정의 근거다.

수정 전 코드와 같은 Flutter·고정 lockfile로 재현했다. 원인을 환경 차이로 확정하지 않았으며, 기대 이미지는 갱신하지 않았다.

독립 리뷰에서 보완한 사항

  • SK2 finish 무응답: 고정 플러그인은 거래를 찾지 못하면 완료 응답을 보내지 않는다. 정상 경로와 스윕의 동시 완료를 고려해 10초 제한 후 preserved로 반환한다. 응답이 끝내 오지 않아도 다음 스윕이 실행되는 것을 실제 앱 finalizer와 가짜 플랫폼으로 검증했다. 네이티브 호출 자체를 취소하는 변경은 아니다.
  • 네이티브 Sentry 병합: 네이티브 데이터 병합이 로그와 미로그인 사용자 식별자를 다시 붙일 수 있어, 최초 사용자 ID를 이벤트별 Hint에 고정하고 최종 beforeSend에서 사용자·breadcrumbs를 재설정한다. 실제 LoadContextsIntegration과 가짜 네이티브 응답, 직렬화된 전송 envelope로 검증했다. 일반 이벤트는 유지한다.
  • 미확정 중복 기록: 스윕의 grantConfirmed=false 중복도 오류 기록을 남기며, 거래는 종료하지 않는다.
  • 인증 이벤트에서 접근 토큰을 출력하던 기존 로그 한 줄을 제거했다.

Claude Opus/high 구현 및 독립 리뷰, 현재 Codex 세션의 추가 소스 검토. 신규 Codex 작업자는 조회된 쿼터 소진으로 사용하지 않았다. 원 리뷰어가 보완 결과를 재검증했고 차단 사항 없음으로 마무리했다(리뷰어 실행 6개 파일·92개 테스트 통과). 과거 handlePurchase/restored 경로의 직접 완료 호출에는 기존 무제한 대기가 남아 있으며 이번 SK2 정산 경합 수정의 대상이 아니다.

실기기 및 배포 후 확인

  1. 지급 전 앱을 종료한 Sandbox 거래가 다음 실행·재개에서 JWS로 재검증되고, 서버 지급 확인 후에만 finish 되는지 확인한다.
  2. 백그라운드 정리 시점의 구매 완료·Ask to Buy 승인 이벤트가 끊기거나 중복 처리되지 않는지 확인한다.
  3. 다른 앱 계정으로 전환한 기기에서 서버 소유자 검사가 지급을 차단하며, 미확정 거래를 앱이 임의로 종료하지 않는지 확인한다.
  4. 실제 Sentry 전송에서 오류 분류와 앱 사용자 ID가 조회되고 로그아웃 후 식별이 해제되는지, 영수증·토큰·이메일이 포함되지 않는지 확인한다.
  5. 배포 버전별 APPLE_JWS_INVALID 발생과 실제 지급 내역을 대조한다. 후보 사용자의 실제 미지급 여부와 보상 판단은 별도 운영 확인 대상이다.
단위 테스트는 실제 Apple 결제 재전달 및 운영 지급 복구를 증명하지 않는다. 다른 계정의 미완료 거래 등 영구 거부가 구매 게이트를 막는 기존 동작은 유지했다. 서버 타임아웃·멱등 충돌, 세션 복원 전 구매 이벤트 보류, 보상 지급, 앱/OTA 배포는 이번 변경 범위 밖이다.

결제 보고에서 신규 수집하는 값은 앱 사용자 ID와 오류 분류·상품·플랫폼이다. 영수증·JWS·토큰·원본 오류 객체는 전달하지 않는다. 기존 SDK의 장치·OS·일반 tags/contexts 수집 전체를 제거하는 변경은 아니다. 과거 경로 handlePurchase 전체에 대한 관측 확대는 포함하지 않았다.

자료와 기록 범위

  • Flutter StoreKit 플러그인 변경 이력 및 설치된 고정 버전의 Dart/Swift 소스를 대조했다. 의존성 갱신 없이 기존 API를 사용한다.
  • Apple JWS 문서: 서버 검증용 거래 증빙.
  • Supabase 인증 이벤트 문서: 초기 세션·로그인·로그아웃·계정 변경 및 스트림 오류 처리.

사용자 식별자가 포함된 원본 핸드오프는 로컬 문서와 별도 로컬 Git 이력에 보존한다. 공개 PR에는 식별자를 제외한 이 검증 문서와 이번 코드·테스트만 포함한다. Jira 상태는 변경하지 않는다.
