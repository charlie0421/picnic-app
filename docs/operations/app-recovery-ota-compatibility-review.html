결론 — iOS / Android 양쪽 모두 이 Dart-only OTA에 대해 호환 가능하다고 판정한다.
탐지된 모든 아티팩트 차이는 로컬 빌드 환경(Xcode 26.6 vs 26.3, CocoaPods 재해결, R8 fullMode, 그 외 툴체인 산물)에서 비롯된 것이며, 소스 차분에는 네이티브·플러그인·에셋 변경이 한 건도 없다(66개 파일 전부 .dart). 차이가 발생한 산출물은 모두 패치에 실리지 않는 영역(Assets.car, classes*.dex, Pods, Podfile.lock)이며, 변경된 Dart 코드가 새로운 네이티브 API나 새로운 에셋을 요구하지 않음을 개별 확인했다.
단, 가드를 통과하려면 플래그가 필요하다 → iOS: --allow-asset-diffs --allow-native-diffs / Android: --allow-native-diffs (+ --android-project-arg=android.enableR8.fullMode=true). 각 플래그의 근거는 §6에 있다. 해당 플래그를 붙인 dry-run 이 iOS·Android 양쪽 모두 패치 생성 경로 전 구간을 No issues detected. 로 통과했고(§6.2), preflight 는 완료 상태다. 남은 것은 프로덕션 실행에 대한 사용자 승인뿐이다.

따라서 릴리스 바이너리의 락은 저장소의 커밋된 락이 아니라 빌드 시각의 CDN 최신 해상도다. 저장소 락은 태그↔HEAD 간 바이트 동일하고 로컬 pod install 로도 변경되지 않았으므로(§2), 이 불일치는 이번 변경이 만든 것이 아니라 파이프라인 구조상 상시 발생한다.

4.3 이 차이가 이번 OTA를 깨뜨리는가 — 아니오

  1. 패치 페이로드에 Pods 가 없다. iOS 패치는 Dart AOT 스냅샷(App.framework) 차분만 싣는다. 로컬에 설치된 구버전 Pod 는 기기에 도달하지 않으며, 기기는 이미 가진 최신 Pod 를 계속 쓴다. 즉 이 차이는 "패치가 구버전 SDK 를 끼얹는다"는 뜻이 아니다.
  2. Dart↔네이티브 계약이 불변이다. pubspec.lock 이 동일하므로 플러그인(google_sign_in_ios 6.3.0, firebase_* 등)의 Dart 코드와 ObjC 브리지 코드가 릴리스와 같다. 위 5건은 그 플러그인들이 끌어오는 전이 네이티브 SDK일 뿐, 채널 이름·페이로드 스키마를 바꾸지 않는다.
  3. 이미 프로덕션에서 검증된 조합이다. 배포본의 최신 Pod + 동일 플러그인 Dart 코드 조합은 지금 사용자 기기에서 1.3.3+130305 로 정상 동작 중이다. OTA 는 여기에 우리 앱 Dart 코드만 교체한다.
  4. 변경된 Dart 가 해당 SDK 의 새 기능을 요구하지 않는다. §2.1 확인 결과 Firebase.initializeApp(options:) 호출 시점 변경이 전부이며, GoogleSignIn/AppAuth 관련 신규 호출은 0건이다. 방향도 안전한 쪽이다 — 기기 쪽이 더 신 버전이고 로컬이 구버전이므로, "로컬에만 있는 신규 심볼을 기기가 못 찾는" 시나리오 자체가 성립하지 않는다.
  5. 실제 호환성 게이트는 따로 통과했다. Starting Verifying patch can be applied to release... Done 이 3회 실행 전부에서 성공했다. 이것이 AOT 스냅샷 적용 가능성의 실질 검증이며, Podfile.lock 검사는 해시 기반 휴리스틱 경고다(차분 내용조차 출력하지 않는다).

선례: 2026-08-28 프로덕션 1.3.1+130103 iOS Patch 1 도 동일한 Podfile.lock 경고를 받은 채 --allow-native-diffs --allow-asset-diffs 로 발행되어 정상 배포됐다(shorebird 로그 1787897112765). 이번이 새로 생긴 이상 징후가 아님을 확인했다.

5. Android — DEX 차이의 정체

5.1 1차 dry-run: 79,510 breaking differences (오탐)

초기 dry-run 은 classes.dex / classes3.dex / classes4.dex 에서 Safe 20,249 + Breaking 79,510 라인을 보고했다. 이는 R8 난독화 매핑이 통째로 달라진 결과이며, 다음 증거로 확정했다.

  • 같은 짧은 이름이 서로 다른 클래스를 가리킨다. 예: Lcom/android/billingclient/api/a; 가 릴리스에서는 필드 a~G 를 가진 BillingClientImpl 급 구현체인데, 로컬에서는 access flags 0x401(public abstract interface) 에 io.flutter.plugins.inapppurchase.* 를 인자로 받는 소형 인터페이스다. 라이브러리 버전 변경이 아니라 이름 재배정이다.
  • pincrux 는 저장소에 커밋된 로컬 AAR 이다. implementation files('libs/pincrux_offerwall.aar') — 바이트가 동일한 입력인데도 수백 건의 "method added/removed"가 났다. 입력이 같으므로 차이는 재난독화 산물일 수밖에 없다. Android 의존성은 전부 고정 버전이며 dynamic version(+)이 없다.

5.3 남은 2개 클래스 — 컴파일러 synthetic, 무해

검증됨 두 클래스의 원본 소스를 직접 확인했다. 둘 다 enum 에 대한 switch 를 포함하며, 이 형태에서 컴파일러가 $SwitchMap$ 를 담은 synthetic $1 클래스를 만든다. 즉 "이 두 클래스가 사용자 코드가 아니라 switch-map synthetic 이다"라는 분류는 소스로 확정된 사실이다.

// google_mobile_ads-6.0.0/.../FlutterNativeTemplateFontStyle.java
public enum FlutterNativeTemplateFontStyle { NORMAL, BOLD, ITALIC, MONOSPACE;
  Typeface getTypeface() { switch (this) { case NORMAL: ... } }   // -> $1 (switch map)

// image_picker_android-0.8.13+14/.../ImagePickerCache.java
void saveType(CacheType type) { switch (type) { case IMAGE: ... } }  // -> $1
  • 두 플러그인은 pubspec.lock 고정 버전이며 소스가 릴리스와 동일하다. 동일 소스에서 한쪽에만 synthetic 클래스가 남았다는 사실 자체는 확인됐다.
  • 추정 정확한 codegen 분기 원인은 규명되지 않았다. 로컬은 Temurin 17.0.15, CI 도 java 17 로 메이저 버전이 같으므로 "JDK 메이저 차이" 가설은 성립하지 않는다. 남은 후보는 마이너/패치 단위 javac 빌드 차이, R8 의 switch-map 인라이닝 판단 차이, desugaring 입력 순서 등이며 어느 것도 증거로 확정하지 못했다. 이 항목은 추정으로 표기하며, 아래 무해성 판단은 이 원인 규명에 의존하지 않는다.
  • 이 클래스들은 패치에 실리지 않는다(dex 는 패치 페이로드가 아님). 기기는 릴리스 dex 를 그대로 쓰며, 그 dex 안에는 동등한 로직이 이미 인라인되어 있다.
  • 변경된 Dart 는 image_picker 도 네이티브 광고 템플릿도 건드리지 않는다(§2.1). 즉 이 두 클래스에 대한 의존이 새로 생기지 않는다.

판정: "breaking"은 shorebird 의 분류 라벨일 뿐이며, 실제 파괴적 변경이 아니다. 무해성의 근거는 (a) 두 클래스가 switch-map synthetic 이라는 확정된 분류, (b) dex 가 패치 페이로드가 아니라는 구조적 사실, (c) 변경 Dart 가 두 플러그인을 건드리지 않는다는 확인 세 가지이며, 원인 미규명은 이 결론을 흔들지 않는다. Android 도 차단 사유 없음.

--allow-native-diffsAndroid synthetic class 2건이 남아 가드가 여전히 발동 §5.3. dex 는 패치에 실리지 않고, 두 클래스는 javac switch-map 산물이며 변경 Dart 와 무관
--android-project-arg=
android.enableR8.fullMode=true		Android 로컬 전역 gradle 설정(false)과 CI 기본값(true)의 불일치 보정 dex 생성에만 영향하고 libapp.so(=실제 패치 페이로드)에는 영향 없음. 검증에 쓴 빌드와 실제 패치 빌드를 동일 조건으로 맞추기 위해 실배포 실행에도 그대로 붙일 것을 권장. 전역 ~/.gradle/gradle.properties 는 건드리지 않는 현재 방식이 옳다
--allow-asset-diffsAndroid 불필요 — Android dry-run 은 asset 경고를 내지 않았다 붙이지 말 것. 가드를 살려두면 실제 에셋 변경이 섞일 경우 여전히 잡힌다(안전 마진 유지)

6.1 검증된 실행 형태

dry-run 에서 사용된 dart-define 3종이 codemagic.yaml 의 프로덕션 릴리스 정의와 정확히 일치함을 확인했다(ENVIRONMENT=prod, PANGLE_ENVIRONMENT=prod, PAYMENT_ENVIRONMENT=prod). Android 는 릴리스가 -- --split-debug-info=build/symbols 로 빌드되었고 codemagic.yaml 주석이 패치에도 동일 전달을 요구하는데, dry-run 이 이를 충족했다.

cd /Users/charlie.hyun/orca/workspaces/picnic-app/chore-startup-ota-preflight/picnic_app
APP_VERSION=$(sed -n 's/^version:[[:space:]]*//p' pubspec.yaml)   # 1.3.3+130305

shorebird patch ios \
  --release-version="$APP_VERSION" --no-confirm --no-codesign \
  --allow-asset-diffs --allow-native-diffs \
  --dart-define=ENVIRONMENT=prod \
  --dart-define=PANGLE_ENVIRONMENT=prod \
  --dart-define=PAYMENT_ENVIRONMENT=prod

shorebird patch android \
  --release-version="$APP_VERSION" --no-confirm \
  --allow-native-diffs \
  --dart-define=ENVIRONMENT=prod \
  --dart-define=PANGLE_ENVIRONMENT=prod \
  --dart-define=PAYMENT_ENVIRONMENT=prod \
  -- --split-debug-info=build/symbols --android-project-arg=android.enableR8.fullMode=true

shorebird 는 pubspec.yaml·shorebird.yaml 이 있는 디렉터리에서 실행해야 하므로 cd 를 명시했고, 버전도 같은 디렉터리의 pubspec.yaml 에서 읽는다(하드코딩 금지). 위 두 명령은 사용자 명시 승인 전에는 실행하지 않는다. 릴리스 1.3.3+130305 는 존재하며 현재 패치 0건({"patches":[]}, release id 826507)이므로 이번이 Patch 1 이다. 프로덕션 OTA 실행 전 사용자 명시 승인은 코디네이터 소관이다.

6.2 최종 preflight 결과 — iOS · Android 양쪽 전 구간 통과

권고한 플래그 조합을 그대로 적용한 --dry-run 이 두 플랫폼 모두 가드 이후 실제 패치 생성 경로 끝까지 통과했다. 이것이 "변경된 Dart 스냅샷이 배포된 릴리스 아티팩트에 실제로 링크·패치화된다"는 최종 실증이며, 추가로 확인할 preflight 는 남아 있지 않다(재실행 불필요).

#심각도위치실패 조건최소 수정 방향
1Minor codemagic.yaml 146–150 rm -rf Podfile.lock Pods; pod install --repo-update 때문에 릴리스마다 네이티브 Pod 가 무통제로 올라간다. 어느 날 전이 SDK 가 동작 변경 버전을 물면 아무도 모른 채 스토어에 나간다(이번에도 5건이 올라가 있었고 락과 불일치). 락 삭제를 중단하고 커밋된 Podfile.lock 을 신뢰(pod install 만 실행). 갱신이 필요하면 별도 PR 로 락을 커밋. 부수 효과로 Shorebird 의 Podfile.lock 가드가 진짜 신호로 되살아난다.
2Minor ~/.gradle/gradle.properties android.enableR8.fullMode=false 가 CI 와 상시 불일치 → 모든 Android preflight 가 79k 라인 오탐을 내고, 진짜 네이티브 변경이 그 잡음에 묻힌다. preflight 호출마다 --android-project-arg=android.enableR8.fullMode=true 를 붙이는 현재 방식을 표준 절차로 문서화한다. 저장소 gradle.properties 에 값을 넣는 방법은 쓰지 말 것 — Gradle 우선순위상 사용자 홈 ~/.gradle/gradle.properties 가 프로젝트 파일을 덮어쓰므로 무력화된다. 항구 해결은 사용자 홈 설정에서 해당 줄을 제거/정렬하는 것뿐이며, 전역 설정 변경은 본 작업 범위 밖이다.
3Minor 로컬 Xcode 26.6 vs CI 26.3 툴체인 격차가 벌어질수록 Assets.car·Runner 차이가 커져 preflight 신호 대 잡음비가 나빠진다. (이번 판정에는 영향 없음 — 패치 페이로드는 Dart AOT 뿐) 패치 실행 머신의 Xcode 를 릴리스 빌드와 맞추거나, 최소한 릴리스 시 Codemagic 이미지의 Xcode 버전을 릴리스 노트에 기록.

8. 배포 후 필수 검증 (정책 §3)

CLI 성공 메시지만으로 완료 처리하지 않는다. iOS·Android 각각 패치 생성 후:

  • 요청한 플랫폼(ios/android) artifact 가 각각 존재하는가
  • 채널이 stable 인가
  • is_rolled_back == false 인가
  • Android 는 필요한 ABI(arm64-v8a / armeabi-v7a / x86_64) artifact 가 모두 있는가 — libdartjni.so 3종 ABI 동일성은 이미 확인됨
