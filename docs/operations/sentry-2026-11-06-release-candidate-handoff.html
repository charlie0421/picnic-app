다른 워크트리의 실행 순서

  1. 최신 대상 브랜치·main·업로드 상태와 적용할 다른 이슈 목록을 확인한다.
  2. 고정 소스의 5개 커밋을 중복 없이 통합한다. 충돌 해결에서 최종 소유권·개인정보 경계를 보존한다.
  3. 통합된 실제 커밋에서 관련 호스트 테스트와 분석을 실행한다. 개별 원본 커밋의 통과 기록만으로 충돌 해결 결과를 승인하지 않는다.
  4. 현재 업로드·릴리스 상태를 근거로 새 버전과 Build number를 정한다. 이 문서의 130606을 그대로 채택하지 않는다.
  5. 정확한 QA 산출물·서명·버전·환경을 기록하고 TestFlight와 Android QA를 수행한다. 실패한 필수 확인은 미확인/차단으로 남긴다.
  6. 통합 코드·QA 결과가 준비되면 대상 버전·커밋·플랫폼·배포 경로·롤백/중단 절차를 제시한다.
  7. 정확한 배포 대상을 사용자에게 보여주고 별도 배포 승인을 받는다. 승인 전 태그 push·Codemagic 실행·스토어 배포·OTA를 시작하지 않는다.
  8. 배포 후 T9에서 실제 적용 릴리스·세션 노출·기능 결과와 Sentry 재발을 비교한다. 이슈 상태는 별도 지시 없이 바꾸지 않는다.
