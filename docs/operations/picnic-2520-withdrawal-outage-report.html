2. 증상과 조사 경로

  1. QnA #383: "버튼이 활성화가 안 돼서 클릭이 안 먹혀요". 사용자 ed8b9618-…, 8/29 15:39 UTC.
  2. 앱 코드: 확인 버튼은 onPressed 가 항상 설정돼 있어 비활성이 아님. 배경색 grey300 이 비활성처럼 보임. 실패 시 예외를 rethrow 만 하고 UI 피드백 없음.
  3. Edge Function 로그: 8/29 15:37 에 delete-user 500 이 16초 동안 50회 이상(사용자가 연타). 8/28·8/30·8/31·9/1 에도 같은 패턴.
  4. Auth 로그: GoTrue DELETE /admin/users/:id 가 context deadline exceeded(10초, 504). 같은 request_id 로 504 여러 번 뒤 200 이 찍히지만 DB 상태는 미변경 — 그 200 은 성공이 아님.
  5. DB: auth.audit_log_entries 6,117,340행 · 3.5GB, 인덱스는 pkey·instance_id 뿐. 트리거의 마스킹 UPDATE 는 Seq Scan + 행마다 28갈래 jsonb 경로 함수 평가. 동일 술어의 SELECT count 가 68초를 넘겨 취소.
  6. wallet_audit_events.ANONYMIZE_ACCOUNT 는 8/12 백필 1,629건이 전부 → 8/12 이후 성공 0건 확정.

3. 근본 원인

탈퇴 → auth.users BEFORE DELETE 트리거
     → update auth.audit_log_entries … where auth_audit_targets_user(payload::jsonb, …)  (6.1M 행 Seq Scan, 68초+)
     → GoTrue request timeout 10초 → 504 → 트랜잭션 롤백
     → Edge Function delete-user 500 "Account deletion failed"
     → 앱: 예외 삼킴, 화면 무반응

컷오버 리허설은 소규모 데이터에서만 검증됐고, 감사 로그 마스킹이 삭제 트랜잭션과 동기 결합돼 있었다.
