결제 인테이크 무흔적 CS 런북

작성 2026-07-31 · 대상: "결제했는데 캔디가 안 들어왔어요" 문의 중 서버에 아무 흔적이 없는 케이스 · 근거 코드는 앱 picnic-app@d6ff164d7, 엔진 picnic-supabase-cotton-candy-engine 기준

한 줄 요약 — Ask to Buy·타기기 결제·결제시트 중 앱 종료는 클라이언트가 영수증을 서버에 전달하지 못해 알림·인박스 어디에도 잡히지 않는다. 1차 대응은 언제나 "원 구매 계정으로 로그인 → 스토어 탭 진입" — 이것이 앱이 스토어 리스너를 켜고 미전송 트랜잭션을 재전송하는 유일한 트리거다. 그래도 안 되면 흔적 유무를 판정(§3)하고, 무흔적 확정 시 수동 지급(§5)으로 넘어간다.

1. 왜 흔적이 없는가 (케이스 분류)

케이스메커니즘자가복구 가능?
Ask to Buy (자녀 계정 승인 대기)결제가 deferred 상태로 보류. 앱에 deferred 처리 코드가 없어 승인 전엔 아무 일도 없고, 승인 후에도 스토어 탭을 연 적이 없으면 이벤트가 소실된다✅ 승인 완료 후 스토어 탭 진입
타기기 결제 (같은 Apple ID 의 다른 기기)트랜잭션에 원 구매자의 계정 토큰(appAccountToken)이 각인돼 동기화되지만, 그 기기에서 스토어 탭을 열기 전까지 앱이 수신하지 않음✅ 원 picnic 계정 로그인 + 스토어 탭 진입
결제시트 중 앱 종료/크래시스토어 결제는 완료됐지만 앱이 영수증을 서버에 못 보냄. iOS 는 StoreKit 이 미완료 트랜잭션을 보존하므로 재실행+스토어 진입 시 재전달됨. iOS 는 영수증 로컬 큐가 없다(Android 만 있음)✅ 재실행 + 스토어 탭 진입
다른 picnic 계정으로 로그인 상태트랜잭션이 도착해도 서버가 소유자 불일치(APPLE_OWNER_MISMATCH/GOOGLE_OWNER_MISMATCH)로 422 영구 거부 — 이 경우는 흔적이 남는다(인박스 DEAD/422)✅ 원 구매 당시 로그인했던 picnic 계정으로 로그인 후 스토어 진입

참고: 구매 파이프라인 전체(리스너·큐 재전송·Android reconcile)가 스토어 화면 initState 에서 시작된다(purchase_star_candy_state.dart:97). "앱을 껐다 켜세요"만으로는 아무 것도 재전송되지 않는다 — 반드시 스토어 탭 진입까지 안내할 것.

2. 접수 시 확보할 정보

  1. picnic 계정 (이메일 / user id) — 결제 당시 로그인했던 계정인지 별도 확인
  2. 플랫폼(iOS/Android)과 스토어 주문번호: Apple 은 영수증 메일·reportaproblem.apple.com 의 주문 ID, Google 은 GPA.로 시작하는 주문번호
  3. 구매 상품(캔디 수량)·결제 일시·금액
  4. Ask to Buy 여부(자녀 계정?), 결제한 기기와 현재 기기가 같은지
  5. 앱 버전과 패치 번호(설정 화면) — 1.3.0 미만 구세대는 레거시 경로라 별도 판단

3. 서버 판정 절차 (읽기 전용)

"무흔적" 은 아래 3개 모두 0건일 때만 확정한다. 신·구 세대 공통으로 ①이 먼저다.

-- ① 영수증 테이블 (양 세대 공통 기록) — 주문번호/txid 로
select id, user_id, platform, environment, status, created_at
from public.receipts
where receipt_hash = '<주문번호 또는 transactionId>';

-- ② 신세대 인박스 — 트랜잭션 흔적
select idempotency_key, status, attempt_count, last_error_code, result_type, created_at
from public.wallet_provider_event_inbox
where purchase_provider_transaction_id = '<txid>';

-- ③ 사용자 기준 최근 지급 원장 (이미 지급됐는데 못 봤을 가능성)
select transaction_id, amount, type, created_at
from public.star_candy_history
where user_id = '<uid>' and created_at > now() - interval '14 days'
order by created_at desc;
판정다음 행동
③에 지급 이력 있음이미 적립됨 — 잔액 화면 새로고침(파우치 당겨서 갱신) 안내로 종결
②에 행 있음 (PENDING/RETRY)정산 재시도 중 — 대기 안내(§6-D). attempt 가 계속 늘면 서버팀 에스컬레이션
②에 행 있음 (DEAD / 422)무흔적 아님 — last_error_code 로 원인 판단. OWNER_MISMATCH 면 §6-C 안내. 그 외 DEAD 는 서버팀이 admin_request_wallet_operation_retry(DEAD 부활 지원)로 복구
전부 0건무흔적 확정 → §4 자가복구 안내 → 실패 시 §5 수동 지급

4. 1차 대응 — 자가복구 안내 (항상 먼저)

  1. 원 구매 계정 확인: 결제 당시 로그인했던 picnic 계정 + 결제한 스토어 계정(Apple ID/Google 계정)이 지금 기기에 로그인돼 있는지.
  2. 앱 완전 종료 후 재실행 → 스토어 탭(캔디 구매 화면) 진입 → 30초 대기. iOS 는 StoreKit 이 미완료 결제를 재전달하고, Android 는 과거 구매 대조가 돌아 자동 적립된다.
  3. Ask to Buy 는 보호자 승인 완료 후 위 절차. 승인 전에는 결제 자체가 성립 전이므로 지급 대상이 아니다.
  4. 타기기 결제는 결제한 기기에서 위 절차를 수행하는 것이 가장 확실.

안내 후 ③ 원장 쿼리로 적립을 확인하고 종결. 24시간 내 미적립이면 §5.

5. 수동 지급 절차 (무흔적 확정 시)

먼저 알아야 할 현실 — 신세대 정식 수단(admin_adjust_star_bonus RPC + wallet-ops 어드민 UI)은 아직 쓸 수 없다: UI 가 feat/wallet-ops 브랜치에만 있고, admin_financial_commands_enabled=false 이며, 켜려면 evidence 3종 + Super Admin 2명 배치가 선행돼야 한다. 따라서 1b 전 현재 시점의 실무 수단은 레거시 picnic-admin 지급(A안)뿐이다.

A안 — 레거시 picnic-admin 수동 지급 (현행 유일 실무 수단, 1b 전까지만)

  1. 증빙 확보 필수: 스토어 주문번호 + 영수증 스크린샷. 지급 전 §3 쿼리 재실행으로 이중 지급 방지(자가복구가 그 사이 성공했을 수 있음 — 실제로 가장 흔한 사고 경로).
  2. picnic-admin → 사용자 상세 → 스타캔디/보너스 수동 지급. 지급량은 상품 정의(유상 스타캔디 + 보너스)를 정확히 분리해서 각각 지급. 타입은 ADMIN_ADJUST, 사유에 CS 티켓 번호 + 스토어 주문번호를 반드시 기입(이 경로는 자동 감사 기록이 없어 이것이 유일한 추적 앵커다).
  3. 지급 후 ③ 쿼리로 원장 반영 확인 + 사용자에게 §6-E 안내.
A안 주의: 이 경로는 user_profiles 직접 UPDATE + 히스토리 INSERT 라 1b(컷오버) 적용과 동시에 죽는다. 1b 전에 wallet-ops(B안) 선행조건 4가지 — ① feat/wallet-ops 배포 ② evidence 3종 기록 ③ Super Admin ≥2·Finance ≥1·Operator ≥1 배치 ④ 플래그 ON — 를 채워 공백 없이 전환해야 한다. 이것이 1b 체크리스트에 들어가야 할 신규 항목이다.

B안 — 신세대 정식 수단 (1b 전후 전환 목표)

  1. admin_adjust_star_bonus RPC: request_id(멱등)·reason·cs_ticket 필수, wallet_audit_events 자동 감사 기록. 1,000 초과 지급은 요청자≠승인자 2인 승인 강제.
  2. 코튼캔디는 조정 자체가 금지(ADMIN_COTTON_ADJUSTMENT_FORBIDDEN) — 코튼 관련 CS 는 별도 정책 필요.
  3. 이 RPC 는 영수증을 검증하지 않는다 — 실결제 확인은 사람 절차(주문번호 대조)이고 cs_ticket 이 증빙 앵커다.

비상 경로 (권장하지 않음, 기록용)

wallet-provider-event 엣지 함수는 service_role 키로 직접 호출 가능하고, 사용자가 제출한 영수증(iOS JWS / Android purchaseToken)을 봉투로 만들어 넣으면 서버가 서명·소유자를 재검증하므로 조작 지급은 불가능하다. 단 사람 손의 service_role 사용 + 감사 기록 부재라, 운영 절차로 쓰려면 래핑(호출 스크립트 + 로그)이 선행돼야 한다.

절대 금지

  • 인박스(wallet_provider_event_inbox) 수동 INSERT/UPDATE — DEAD 가 된 멱등 키는 그 트랜잭션을 영구 결제 불가로 만든다 (실제 사고 사례 있음)
  • 신세대 사용자의 user_profiles 잔액 직접 UPDATE — 원장 없는 잔액은 투영 드리프트로 잡힌다 (A안은 히스토리 INSERT 를 동반하는 레거시 관행이라 예외)
  • 사용자에게 "다시 결제해 보세요" 안내 — 소모품 재결제는 이중 청구다. 재결제 유도 문구 금지

6. 응대 문구 템플릿

A. 공통 1차 안내 (자가복구)

안녕하세요, Picnic! 입니다. 결제가 완료됐는데 캔디가 보이지 않는 경우, 대부분 앱이 스토어의 결제 완료 신호를 아직 받지 못한 상태입니다. 아래 순서로 진행해 주세요.

1. 결제하실 때 사용했던 Picnic! 계정으로 로그인돼 있는지 확인해 주세요.
2. 앱을 완전히 종료한 뒤 다시 실행해 주세요.
3. 스타캔디 구매 화면(스토어 탭)에 들어가 30초 정도 기다려 주세요. 이 화면에 들어와야 결제 확인이 다시 시작됩니다.

※ 처리되는 동안 절대 다시 결제하지 마세요. 완료되는 대로 자동으로 적립됩니다.
(EN) Hi, this is Picnic! If your payment went through but the candy hasn't appeared, the app usually hasn't received the store's completion signal yet. Please: 1) make sure you're logged in with the Picnic! account you used when purchasing, 2) fully close and reopen the app, 3) open the Star Candy purchase screen (store tab) and wait about 30 seconds — the purchase check only restarts on that screen. Please do not pay again; your candy will be credited automatically.

B. Ask to Buy (승인 대기)

확인 결과, 해당 결제는 가족 구성원(보호자)의 승인을 기다리는 상태로 보입니다. 보호자께서 승인을 완료하신 뒤, 결제하신 기기에서 앱을 실행해 스타캔디 구매 화면에 들어가 주시면 자동으로 적립됩니다. 승인 전에는 결제가 아직 완료되지 않은 상태라 적립이 진행되지 않는 점 양해 부탁드립니다.

C. 다른 계정으로 결제된 경우 (OWNER_MISMATCH)

확인 결과, 해당 결제는 지금 로그인하신 계정이 아닌 다른 Picnic! 계정으로 로그인한 상태에서 진행된 것으로 확인됩니다. 캔디는 결제 당시 로그인했던 계정으로만 적립할 수 있습니다. 결제하실 때 사용하셨던 계정으로 로그인하신 뒤, 스타캔디 구매 화면에 들어가 주세요. 어떤 계정인지 기억나지 않으시면 결제 영수증의 주문번호와 함께 회신해 주시면 확인을 도와드리겠습니다.

D. 흔적 있음 — 정산 재시도 중

결제는 정상 접수됐고, 현재 서버에서 적립 처리가 진행 중입니다. 처리가 끝나는 대로 자동으로 적립되며, 다시 결제하실 필요가 없습니다. 1시간 이후에도 적립되지 않으면 다시 문의해 주세요. 저희가 직접 처리해 드리겠습니다.

E. 수동 지급 완료 안내

불편을 드려 죄송합니다. 보내주신 주문번호로 결제 내역을 확인해 캔디 {수량}개를 계정에 직접 적립해 드렸습니다. 앱에서 스타캔디 잔액을 아래로 당겨 새로고침하면 확인하실 수 있습니다. 같은 결제로 중복 적립이 시도될 경우 시스템이 자동으로 걸러내니 안심하셔도 됩니다.

F. (별건) 구버전 앱에서 출석 체크 오류 문의 — 1b 이후

출석 보상 이벤트는 종료되었습니다. 사용 중이신 앱이 이전 버전이라 출석 화면이 아직 보이는 것으로 확인됩니다. 스토어에서 최신 버전으로 업데이트해 주시면 됩니다. 이용에 불편을 드려 죄송합니다.

배경: 출석 보상은 폐지됐고 1.3.0 에는 출석 UI 가 없다. 강업이 닿지 않는 구 릴리스 코호트만 1b 이후 출석 체크 시 오류를 본다 — 정상이며 수동 지급 대상 아님.
