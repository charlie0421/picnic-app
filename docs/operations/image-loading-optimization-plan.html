추천 변경안

공통 이미지 요청 규격을 정리하고, 사용자가 곧 보게 될 항목만 미리 준비한다. 화면별 플래그 수정만 하는 방안은 작고 빠르지만 원본 요청·캐시 키 차이·다음 페이지 대기를 함께 해결하지 못한다. CDN 포맷 전환과 서버 캐시 재설계는 실제 운영 경로 확인과 별도 배포가 필요하므로 이번 앱 변경안에는 포함하지 않는다.

1. 공통 요청과 캐시 재사용

  • 최종 CDN URL, 다운로드 크기, 디코딩 크기, ImageProvider 키를 한 경로에서 계산해 표시와 사전 로딩에 함께 사용한다.
  • 화면 크기가 직접 주어지지 않은 이미지도 유한한 레이아웃 제약에서 요청 크기를 구한다. 너비·높이·DPR 변경 시 갱신하고 동일 조건의 재빌드는 같은 키를 유지한다.
  • imageBuilder에서 원래 provider를 다시 디코딩하는 경로를 없앤다. 논리 픽셀/물리 픽셀을 구분하고 디코딩 크기에 상한을 둔다. 기존 명시적 memCache 크기는 물리 픽셀 계약을 보존한다.
  • 캐시에 있는 이미지는 즉시 유지하고, 빠른 스크롤에서는 새 작업만 지연한다. 화면 진입 시 임의 캐시 축소를 제거하거나 공통 상한 정책으로 통합한다.
  • 외부 HTTP(S)의 서명 쿼리와 기존 CDN w/h/q 계약을 유지한다. 글로벌 캐시 용량을 늘리는 방식은 사용하지 않는다.

2. 네 화면에 연결

  • 배너: 캠페인 응답 중에도 이미 조회된 일반 배너를 표시. 캠페인 데이터 도착 시 기존 필터·순서 규칙으로 합성한다. 캠페인 전용 행이 일반 배너에 재등장하지 않도록 기존 Supabase 필터를 보존한다. 배너 키는 항목 기준으로 고정하고 다음 슬라이드를 미리 준비한다.
  • 메인 투표 슬라이드: 실제 히어로 영역 크기로 요청하고 현재 이미지 우선, 다음 1–2개만 미리 준비한다. 화면 크기·데이터 순서 변경과 위젯 해제를 처리한다.
  • 팝업: 아티스트 이미지는 가시성 알림을 기다리지 않고 생성 즉시 로딩. 가능한 경우 팝업을 여는 동작에서 동일 규격 이미지를 미리 요청하되, 팝업 표시를 네트워크 완료까지 기다리지 않는다.
  • 투표 리스트: 다음 카드의 대표/상위 아티스트 이미지만 제한적으로 사전 로딩하고, 마지막 페이지에 도달하기 전에 다음 데이터 조회를 시작한다. 이미지의 고정 0.5초 숨김을 없애거나 짧게 줄인다. 상세 후보 리스트에서도 캐시 적중 이미지는 스크롤 중 유지한다.
  • 기타: 아바타·리워드·미디어 썸네일 등 공통 로더 이용 화면의 크기 누락과 지연 설정을 점검해 같은 원인의 누락만 수정한다.

3. 사전 로딩의 한계

사전 로딩은 화면별 인접 항목에 한정하며 백그라운드 동시 요청은 최대 2개를 시작 기준으로 검토한다. 중복 진행 요청을 합치고, 화면 이탈·빠른 페이지 전환 후 오래된 대기 작업을 버린다. 표시 이미지의 요청을 막는 전역 슬롯 제한이나 전체 목록 선다운로드를 추가하지 않는다. 메모리 캐시에는 실제 사용 크기만 유지한다.

조사에서 제외한 추정

Luna가 제안한 CDN 쿼리 보존 변경은 현재 resolver 테스트와 CDN 계약에 반하므로 이번 변경에 자동 반영하지 않는다. 로컬 Lambda의 버킷 설정은 실제 운영 배포본인지 확인되지 않아 현재 앱 지연 원인으로 단정하지 않는다. 기존 memCache/DPR 불일치 주석만으로 최종 이미지가 작게 디코딩된다고 단정할 수 없으며, 실제 imageBuilder가 원래 provider를 다시 사용한다는 패키지 경로를 기준으로 수정·검증한다.

오케스트레이션 상태와 승인 지점

요청은 풀부스트·Astra 적극 활용이다. Orca 1.4.200은 연결되지만 account list의 모든 rateLimits가 null이어서 실제 사용률·리셋·배분 압력은 계산할 수 없었다. 라우터는 fallback=true, Luna/low, 동시 워커 1, Fast OFF를 반환했다. 조사 단계에서는 Luna만 실행했으며, 사용자 예외 승인 후 Astra/ultra 계획 워커를 시작했다.

사용자가 “사용량 조회 없이 풀부스트 진행”으로 예외를 승인했다. 예외 승인 후에는 Astra 계획, Sol 구현, Opus 교차 리뷰에 배분하며 가상의 사용량 비율을 제시하지 않는다. Fable 상태도 조회 실패다. 전체 모드 안내.

여러 화면과 공통 로더 구조 변경이므로 사용자 공통 AGENTS.md의 “대규모 변경 … 전에는 계획을 짧게 제시하고 확인받는다”에 따라 변경안을 제시했고 사용자 진행 응답을 받아 실행한다. Superpowers brainstorming/SKILL.md도 “Do NOT … write any code … until … they have approved it”을 요구한다.
