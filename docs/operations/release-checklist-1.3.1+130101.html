05릴리스 절차

  1. 1버전 범프 PR

    이 워크스페이스(브랜치 chore/release-1.3.1)에서 picnic_app/pubspec.yaml 을 1.3.1+130101 로 수정 → PR → main 머지. 이 체크리스트 문서도 같은 PR 에 실린다.

  2. 2태그 전 확인

git status --short          # 깨끗해야 함
git rev-parse HEAD origin/main   # 일치해야 함
git tag --list "picnic-v1.3.1+130101"                    # 없어야 함
git ls-remote --tags origin "refs/tags/picnic-v1.3.1+130101"  # 없어야 함
  3. 3사용자 명시 승인

    태그명·버전·대상 커밋 SHA 를 보여주고 승인받은 뒤에만 다음 단계. 태그 푸시가 곧 외부 빌드 시작이다.

  4. 4annotated 태그 푸시

  5. 5Codemagic 확인

    iOS·Android 프로덕션 워크플로 2개가 올바른 태그·커밋으로 시작됐는지, Android 로그에 --split-debug-info=build/symbols 가 실제로 찍혔는지, IPA/AAB 생성까지.

  6. 6스토어 + Shorebird 확인

    App Store Connect / Play Console 업로드 결과 확인. shorebird releases list 로 새 release 1.3.1+130101(iOS·Android) 생성 확인. 태그 푸시 사실만으로 완료 보고하지 않는다.

빌드 실패 시 — 태그를 건드리지 말 것

태그 푸시 후 실패하면 원격 태그를 삭제·이동·재사용하지 않는다. 수정을 main 에 반영하고 130102 로 새 태그를 만든다. 스토어 업로드 실패 시에도 빌드번호 재사용 불가로 가정한다.

07이후 OTA — 이 워크스페이스의 두 번째 역할

  • 새 릴리스가 나가면 OTA 기준은 1.3.1+130101 이다. 이후 Dart 수정은 이 release 대상 패치로 나간다.
  • 로컬 shorebird patch 는 이 프로젝트에서 금지(스크립트 NO-GO 가드). 패치는 Codemagic picnic-app-patch-ios·picnic-app-patch-android 워크플로 전용, 정확한 대상 SHA 승인 증빙 필요.
  • 패치 워크플로는 빌드번호 ≥130008 에 --split-debug-info 를 자동 전달한다 — 130101 은 해당. 플래그 정합이 어긋나면 패치가 깨진다.
  • 알려진 구멍: 패치 워크플로가 release provenance 를 검증하지 않아 스테이징 릴리스에 프로덕션 패치가 가능하다. 실행 때마다 대상 릴리스를 수동으로 재확인할 것.
  • 패치 후 shorebird patches list --release-version="1.3.1+130101" --json 으로 stable 채널·롤백 아님·플랫폼별 artifact 확인.
