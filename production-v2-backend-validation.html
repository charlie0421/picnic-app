2. 주요 발견

BLOCKER 로컬 DB 검증 증거가 없음

원격 관련 환경변수를 제거하면 로컬 target guard는 통과했다. 그러나 outbound-webhook guard가 127.0.0.1:54322에 연결할 때 샌드박스가 Operation not permitted로 차단했다. 두 가드 통과가 SQL 실행의 선행조건이므로 6개 V2 SQL 테스트와 V1/refund SQL 테스트를 실행하지 않았다.

따라서 로컬 DB가 V2 스키마와 일치하는지, 또는 어떤 migration이 누락됐는지는 관찰할 수 없었다. 이는 확인된 schema mismatch가 아니라 환경 제한이며, 기존 picnic-local DB는 reset하지 않았다.

HIGH 지정 브랜치는 현재 main 배포 기준선으로 부적합

지정 HEAD는 로컬 origin/main보다 109개 main-side commit 뒤에 있으며 양방향 diff는 155개 파일에 걸친다. 전체 checkout을 프로덕션 배포 입력으로 쓰면 이후 main 변경이 대량 누락된다.

반면 검토 대상 6개 V2 migration과 V2 테스트/fixture 산출물은 로컬 origin/main과 byte-identical하다. 즉 migration 내용 자체의 main 병합 드리프트는 없지만, 실행은 최신 원격 main의 검증된 SHA에서 다시 수행해야 한다.

MEDIUM 전체 safety suite의 비이식적 절대경로 4건

npm run test:wallet:safety는 57개 중 52개 통과, 5개 실패했다. 그중 4개는 scripts/safety/wallet-release-artifacts.test.mjs가 삭제된 별도 checkout /Users/charlie.hyun/Repositories/picnic-app-cotton-candy-policy/...를 하드코딩해 ENOENT가 난 genuine test-harness failure다. 동일 fixture는 현재 /Users/charlie.hyun/Repositories/picnic-app/picnic_app/integration_test/fixtures/wallet_contract_fixtures.g.dart에 존재한다.

백엔드 V2 동작 실패 증거는 아니지만, 프로덕션 전 safety gate를 환경 독립적으로 재현할 수 없으므로 수정 후 녹색 결과가 필요하다.

wallet-contract-verifier.test.mjs의 Dart format 검사는 처음에는 Flutter SDK engine.stamp, SDK 내부 Dart를 직접 선택한 재시도에서는 ~/.dart-tool/dart-flutter-telemetry-session.json 쓰기가 샌드박스에서 차단되어 실패했다. 나머지 4개 verifier test는 통과했고, 이는 코드 assertion failure가 아닌 실행 환경 제한이다.

7. 최소 다음 단계

  1. localhost loopback만 허용되고 원격 자격증명이 제거된 환경에서 local target guard와 webhook guard를 다시 통과시킨다. webhook trigger가 발견되거나 schema가 다르면 중지하고 mismatch를 보고하며 DB reset은 하지 않는다.
  2. 가드 통과 후 위 6개 rollback형 V2 SQL과 안전한 V1/refund 5개만 개별 psql -v ON_ERROR_STOP=1 -f로 실행한다. dblink commit/fixture-retaining 테스트와 전체 test:wallet:sql은 이 비영속 검증에서 제외한다.
  3. 절대경로를 제거한 뒤 정상 개발 환경에서 npm run test:wallet:safety 57/57을 확보한다. Dart telemetry 쓰기 허용 또는 조직 표준 비활성화 설정도 필요하다.
  4. 독립 리뷰 결과와 위 실행 증거를 최신 원격 main SHA에 다시 묶는다. 지정 feature branch 전체는 배포 입력으로 사용하지 않는다.
  5. 그 전까지 promotion_schedule_v2_enabled=false를 유지한다. 어떤 production deploy/write/flag activation도 이 보고서로 승인되지 않는다.
