5. 보안 Advisor 전후 비교

기존 Auth 사용자 노출 경고 1건(public.cs_4_11_classification)은 설치 전·후 동일하게 존재한다. 이번 설치에서 만들거나 수정한 뷰가 아니며, 별도 보안 검토·조치가 필요하다. Supabase 공식 조치 안내.

새 ERROR 증가는 없었다. RLS 활성·정책 없음 INFO는 20→22(grants/audiences, 직접 접근 차단), authenticated SECURITY DEFINER 호출 가능 WARN는 91→95(신규 RPC 4개)로 증가했다. 이 네 RPC의 정의·소유자·빈 search_path·정확한 실행 권한은 postflight가 고정값으로 검증했다. 기존 나머지 보안 경고를 해결하거나 보안 점검 전체가 깨끗하다고 주장하지 않는다. RLS 정책 안내, SECURITY DEFINER 호출 권한 안내.

6. 소유권과 다음 단계

사용자 지시에 따라 앱 버전 적용·태그·TestFlight 빌드는 배포용 워크트리가 담당한다. 이 세션은 앱 파일·커밋·태그·빌드를 변경하지 않았다. 앱 #204 main 병합은 이전에 다른 세션이 완료했으며, 이후 배포용 워크트리의 최신 버전/빌드 상태는 여기서 단정하지 않는다.

  1. 배포용 워크트리에서 새 앱의 TestFlight/내부베타 설치 가능 상태를 확인.
  2. 서버 ADMIN_ONLY 활성화 전 운영 전제와 비상 OFF 경로를 확인하고 별도 승인. 대상은 is_admin 또는 is_super_admin 사용자이며 일반 사용자는 제외.
  3. 승인된 관리자 활성화 후 관리자/슈퍼관리자/일반 사용자 분리와 결제·광고·지갑 실기기 QA 및 모니터링.

ADMIN_ONLY/ALL 활성화, Edge 배포, 실제 구매, 앱 배포, 원장 복구·삭제는 이번 실행에 포함하지 않았다. 기존 워크트리와 보고서는 보존한다. Supabase의 대상·권한·사후 확인 절차와 Superpowers의 검증·리뷰 절차가 이번 실행 순서와 완료 판정에 반영됐다.
